## 2 修正清单（按严重度；每项写清现状 → 根因 → 改法 → 落点 → 测试）

### P1-1 ★ NPUSCH 单音表 / 多音表与「子载波数」解耦：会配出标准里没有的组合，门限差 1.6~3.8 dB，I_MCS↔I_TBS 映射错位

- **现状**：`src/linkbudget/BasebandPanel.vue`（`src/ngso/BasebandPanel.vue` 是镜像，再生式与端到端也 import 它）模板里「子载波数」下拉对任何 NB-IoT 上行标准都给 `[1, 3, 6, 12]`；`applyModcod()` 用 `p.nTones === 1` 决定「表里的 idx 是 I_MCS 还是 I_TBS」；`src/shared/lbSla.js pickMirPhy()` 用同一判据。`modcodTables.PHY_OF` 只给了初值（ST 表 `nTones: 1`、MT 表 `nTones: 12`），之后随便改。
- **后果**：
  - 选「NPUSCH 单音」表后把子载波数改成 3/6/12：门限仍是单音列（比多音列高 1.6 dB@I_TBS 0 … 3.8 dB@I_TBS 10），且 I_MCS 0/1 的 π/2-BPSK 被套到多子载波上——TS 36.213 §16.5.1.2 规定 N_sc^RU > 1 时恒 QPSK；idx 又被当 I_TBS 直读，I_MCS 1（应为 I_TBS 2）变成 I_TBS 1。
  - 选「NPUSCH 多音」表后把子载波数改成 1：门限偏乐观 1.6~3.8 dB；I_TBS 1/2 被当 I_MCS 过单音映射（1↔2 互换），I_TBS 11/12 映射不到又悄悄退回原值。
- **改法**：子载波数由标准锁定，不由用户随手改。
  1. `PHY_OF` 的 NB-IoT 三条各加 `st` 字段：NPDSCH `st: null`，NPUSCH MT `st: false`，NPUSCH ST `st: true`；`normalizePhy` 透传 `st`（认不出记 null）。
  2. `normalizePhy`：`st === true` → 强制 `nTones = 1`；`st === false` 且 `nTones === 1` → **不归正，留给 `resolve()` 报错**「NPUSCH 多音表不含单子载波配置」；`st === false` 时 `scs` 强制 15（3.75 kHz 只有单音）。
  3. 面板：`st === true` 时「子载波数」下拉只剩 1（禁用），`st === false` 时选项 `[3, 6, 12]` 且子载波间隔下拉不出 3.75；`applyModcod()` 与 `pickMirPhy()` 改按 `p.st === true` 判映射，不再看 `nTones`。
  4. 自建标准（`custom[].phy = 'nbiot'`）没有 st：面板照旧给全选项，但 `applyModcod` 按「当前 nTones === 1」判映射的老逻辑只对 `st == null` 保留，并在 `title` 写明。
- **落点**：`packages/core/utils/modcodTables.js`（PHY_OF）、`packages/core/utils/ntnPhy.js` + 镜像（normalizePhy / resolve）、两份 `BasebandPanel.vue`、`src/shared/lbSla.js`。
- **测试**：ntnPhy.test 加「st:true 填 12 归 1」「st:false 填 1 → resolve 报错」「st:false 填 3.75 → scs 归 15」；lbSla.test 加 ST/MT 各一条 pickMir（ST 行的 idx 经映射、MT 行不经映射）。

### P1-2 ★ 变换预编码表允许选「下行」

### P2-5 NB-IoT 表的「FEC 码率」列是编出来的数：分母 264 对三张表都不对

- **现状**：三张 NB 表的 `fec` 写成 `TBS/264`（label 也印着 `QPSK 16/264`），注释说 264 = (14−3)×12×2。这个数只参与显示（NB-IoT 速率走 TBS 表、`k = infoRate/B_occ`，引擎与 SLA 都不拿它算），但它出现在 MODCOD 下拉、级联表「FEC 码率」行与报表里，读者会当成码率。
- **按 TS 36.211 结构算，正确的每传输块编码比特数**：
  - NPDSCH：每子帧 14 符号 × 12 子载波 = 168 RE，减 NRS（§10.2.6.2：l = N_symb−2, N_symb−1 每时隙两个符号、m = 0,1 每符号 2 RE、每端口每子帧 8 RE；2 个端口时另一端口的位置也不载数据 → 16 RE）= **152 RE → 304 bit**（独立/保护带部署，l_DataStart = 0，TS 36.213 §16.4.1.4）；带内部署 l_DataStart = 3（eutraControlRegionSize）再扣 CRS：11×12 − 16 − 12 = **104 RE → 208 bit**。264 谁也不是。
  - NPUSCH 多音：一个 RU 无论 3/6/12 子载波都是 144 RE（12 子载波 2 时隙、6 子载波 4 时隙、3 子载波 8 时隙，每时隙 7 符号扣 1 个 DMRS 符号，TS 36.211 Table 10.1.4.2-1：l = 3@15 kHz / l = 4@3.75 kHz）→ **288 bit**（QPSK）。
  - NPUSCH 单音：16 时隙 × 6 符号 × 1 子载波 = 96 RE → **96 bit（π/2-BPSK）/ 192 bit（π/4-QPSK）**——这一张现在就是对的。
  - 分子按 3GPP 的码率定义含 24 bit CRC：`(TBS + 24) / 编码比特数`（NR 的 R 就是这个口径：N_info = N_RE·R·Qm ≈ TBS + CRC）。
- **改法**：`fec` 改成 `(TBS(I_SF=0 或 I_RU=0) + 24) / N_coded`，N_coded = NPDSCH 304（2 NRS 端口、独立/保护带）/ NPUSCH MT 288 / ST 96·Qm；label 改成 `I_TBS 0 · QPSK · TBS 16`（不再印假分数）。`fec` 列 `title`（MODCOD 编辑页 `src/shared/modcodTable.js` 与面板）写明「有效码率 = (TBS + 24 bit CRC) / 每传输块编码比特数，按 I_SF/I_RU = 0、独立部署、2 个 NRS 端口；带内部署为 208 bit」。带内部署时（P2-4 的 `opMode`）级联表「FEC 码率」行改由引擎按当前 I_SF/I_RU 与部署模式现算 `(TBS+24)/(N_coded·N_SF)` 回显 `phyCodeRateResult`（这一行对 NB 行替换 `fecResult`；NR 行照旧回显表值 R）。
- **测试**：ntnParams.test 的 `BITS_PER_SF = 264` 断言改成三张表各自的分母与「分子 = TBS + 24」；单音断言分母不变、分子改；新增「NPDSCH inband 下 (I_TBS 10, I_SF 0) 码率 = (144+24)/208」。

### P2-6 3GPP 行的级联表印着「误码率 1×10⁻⁷」

### P3-8 ITU PFD 限值折算对窄于参考带宽的载波偏严（顺手发现，**非 NTN 行**，须用户拍板）

- `linkCalculator.js:1138`、`linkCalculatorNGSO.js:1313`、再生式同款：`ituPfdLimitPerM2 = limit_4kHz + 10lg(B/4)`。限值定义在参考带宽 B_ref（4 kHz 或 1 MHz）内；载波带宽 B < B_ref 时全部功率都落在一个参考带内，允许的总 PFD = limit_ref，不应再减。正确式：`limit_ref + 10lg(max(B, B_ref) / B_ref)`。对 NTN 行是恒等变换（下行占用带宽 ≥ 180 kHz，Ka 的 FR2-NTN ≥ 50 MHz），**只影响 DVB 的窄载波**（例：Ka 频段 100 kHz SCPC，现值偏严 10 dB）。碰到「DVB 一位不变」的红线，故本任务**不改**，列进版本说明请用户拍板。

### P3-9 重复次数值域不校验

### P3-10 NR 方向切换不复位分配
