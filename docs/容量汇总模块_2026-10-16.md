# 链路预算「容量汇总」模块（2026-10-16）

GSO / NGSO / 再生式三窗。原先是链路表表脚的一行（LbCapFoot 上行），2026-10-16 按用户要求改成与 SLA 同一形态的独立模块：
功能区「导出」组 SLA 右侧一颗「容量」按钮（Lucide `sigma`）→ 弹窗 `LbCapDialog`；表脚只留「本行读数」。

## 1 为什么重做

旧表脚把本批次所有已算链路的载波带宽、功率带宽、容量直接相加，并在「总功率带宽」的 title 里说「与总带宽相比即整批的功带平衡状况」。三处站不住：

1. **跨转发器相加**。功率带宽 = 功率占用 × 本转发器带宽，份额的分母是各自那只转发器。卫星「逐链路指定」用了多颗星时，合计不对应任何一只转发器的功带平衡（与高级计算 §13「一组＝一只转发器」同一前提）。示意：A 星 36 MHz（载波带宽 20、功率带宽 27）＋ B 星 54 MHz（载波带宽 34、功率带宽 27）→ 合计 54 = 54「平衡」，实际 A 受功率限、B 受带宽限。
2. **一行按一路载波计**。同一条前向载波按不同收端建了几行，带宽与容量被重复计入几次（高级计算文档 §2.4 第 1 条）。
3. **不对照可用资源**。只有合计，看不到每只转发器还剩多少带宽、多少功率。
4. NGSO 每行取各自的最差时刻，求和不对应任何同一时刻的状态；NGSO 也不按功率等效带宽售卖（高级计算文档 §2.5）。

## 3 计算口径（`src/shared/lbCapacity.js`）

账本单位＝一只转发器：GSO / NGSO 一份卫星配置一组；再生式「模块 × 卫星」一组（上行占上行频谱、下行占下行频谱），星间按「发射星 → 接收星」成对，手动几何整模块一组。体例照运营商传输计划（Eutelsat Transmission Plan 的 Tx Plan Resources：已分配 / 剩余的功率与带宽都以 MHz 计；Intelsat LST 租用汇总：Total BW allocated / PEB / available / margin）。

每组：

- **小计**：Σ载波数、Σ容量、Σ载波带宽、Σ功率带宽（逐行 × 载波数；容量取窗口的 `capacityKbpsOf` = η × B，与链路表「容量」列同源）
- **可用**：可用带宽缺省＝引擎回显的转发器带宽（整只转发器）；可用功率缺省＝可用带宽（功率份额与所租带宽成正比）。留空即缺省，输入框占位显示缺省值
- **剩余**＝可用 − 小计；**占用**＝小计 / 可用（> 100 %、< 0 标红，无文字判定）
- **结算带宽**＝max(Σ载波带宽, Σ功率带宽)（与 SLA「结算带宽」逐链路同式，这里按组取）；**年费**＝单价（万元/MHz/年）× 结算带宽；**单位容量成本**＝年费 / Σ容量（万元/Mbps/年）
- **表末合计**（≥ 2 组才出）只加能跨转发器相加的量：载波数、容量、载波带宽、结算带宽、年费（有一组列入了载波却没给单价就不报合计年费）。**功率带宽不跨组求和**。

三体制（`opts.pbw`）：

| 体制 | pbw | 功率带宽 | 可用带宽缺省 | 结算带宽 |
|---|---|---|---|---|
| GSO | `sum` | 组内求和，出可用功率 / 剩余功率 / 功率占用 | 转发器带宽 | max(ΣB, ΣPEB) |
| NGSO | `list` | 只逐行列（逐行占用按整只转发器折算），小计 / 剩余留空 | 转发器带宽 | ΣB |
| 再生式 | `none` | 不出（引擎回显的是占位转发器参数） | 无，填了才出剩余 / 占用 | ΣB |

## 4 自定义与存法

- **逐链路 `row.cap = { off?: true, n?: 整数 ≥ 2 }`**：缺省（列入、1 路）不落盘；`applyRowCap` 现造纯对象（行是响应式的，嵌套对象浅拷出去是 Proxy，过不了 IPC 结构化克隆——同 `applyRowSla`）。改列入 / 载波数走 `slaTouch`，不点亮「输入已变」。
  ★ 载波数只在本模块生效：链路表 09-07 随 CnC 回退删掉的「路数」列不恢复，高级计算组账仍是一行一路。
- **场景级 `capParams.tp[组键] = { bwKHz?, pwKHz?, price? }`**：组键 GSO / NGSO＝卫星配置 id；再生式 `'uplink:satId'` / `'downlink:satId'` / `'isl:发>收'`（手动几何 `'isl:>'`）。进 serialize / applyState / blankState / 指纹（规整后比，旧场景无此键不算改动）/ 自动保存监听；分享包导入经 `remapCapParams` 随卫星 id 换成对端的（对端没收的星那组丢掉，空位原样留）。
- 「重置」两件事一起做（同 SLA）：各行回列入、1 路，可用资源与单价清空；再生式只动当前模块。

## 5 界面（`src/components/LbCapDialog.vue`）

AppDialog `min(1120px, 94vw)`，界面字体 + `--lb-fs`，三线表。组头＝卫星配置名 · 转发器带宽；组内逐链路一行（列入 · # · 链路 · 载波 · 载波数 · 容量 · 载波带宽 · [功率带宽] · 带宽占用 · [功率占用]）；组末小计 / 可用（输入框就地在对应列）/ 剩余三行 + 一行读数（频谱效率 · 结算带宽 · 单价输入 · 年费 · 单位容量成本）；≥ 2 组表末合计。带宽类整表共选一档、容量一档（功能区「单位」锁定时恒 kHz / kbps，可用资源输入框按该档显示、按 kHz 回存）。打开前没算过或输入已变先补算（同 SLA）。弹窗关着时不喂 model（prop 在父组件渲染时求值，常驻绑定会让每改一格都重算整张账）。

## 6 报告

各窗经 `useLbReport` 的 `capFor(secKey, lang, noOf)` 交 `capReportBlock`（参数做行、转发器做列、≥ 2 组末列合计；首行「链路」用导出流程给的全篇 #N，区间压缩 `#1–#3, #5×20`）→ `lbReport.buildReportModel({ capacity })` → 主进程 `enrichReportModel` 挂到各节 `summary.cap` 并清空旧 `stats`；Excel / Word / PDF 三路渲染 cap 矩阵。端到端没有 `capFor`，照旧出它的统计行。
