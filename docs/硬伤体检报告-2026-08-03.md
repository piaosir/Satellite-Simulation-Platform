### 一处诚实说明

**P.676 低仰角（M3）修复后，5° 界面仍有约 0.02 dB 的残留跳变**，且方向仍是"仰角略低反而衰减略小"（实测 f=14 GHz：4.99°→0.8466 dB、5.01°→0.8666 dB）。这是球面几何式与平面 cosec 近似在切换点的固有不连续，平台原本就有、本次未引入；M3 真正解决的是 θ→0 时路径少一半的问题（幅度以 dB 计，远大于此）。两端现已完全一致。彻底消除需要全域统一用球面式，属模型选择变更，未在本次动。

### 结构性改进

64QAM 的修法不是"给五张表各补一行"，而是让平台两个引擎 `require('./constants.js')`、小程序两个引擎 `require('./constants.js')`、小程序 `index.js` 从既有 require 里多解构一个符号，并删掉它函数内的第二份内联表。**五处重复的调制表归一为两份 `constants.js`（平台一份、小程序一份），两份内容一致且都含 64QAM/256APSK。** 这条链以后不会再分叉。

## 高危（7 条）

### H1. 64QAM 缺调制因子，引擎静默按 QPSK 算，与面板两套数
- 位置：`packages/core/utils/linkCalculator.js:118-129, 490`；同病 `linkCalculatorNGSO.js:124/603`、小程序 `linkCalculator.js:83`、`linkCalculatorNGSO.js:90`、`pages/index/index.js:42`（这份连 256APSK 都缺）
- 根因：引擎本地 `MODULATION_FACTORS` 表缺 `'64QAM'` 键，`MODULATION_FACTORS[modulation] || 2` 静默回退 QPSK；而 UI 下拉与 3GPP NR-NTN MODCOD 预设（MCS17–28）全是 64QAM，渲染端 `src/shared/carrierRate.js:12` 的表含 `'64QAM': 6`——面板按 6 bit/symbol 显示、引擎按 2 计算。
- 影响：选 NR-NTN MCS17~28 或手选 64QAM 时，符号率/噪声带宽/分配带宽错 3 倍，Es/N0→Eb/N0 折算错 10·lg3≈4.77 dB，门限 C/T、所需功放功率、转发器占用整体偏差约 4.77 dB，无任何报错。已 node 实跑复现（MCS17：引擎 symbolRate=2660.01 ksps vs 正解 886.67 ksps）。
- 修法：两仓共 5 处表补 `'64QAM': 6`（更好：删本地表统一 require constants.js），补一条 64QAM 回归测试。

### H2. PFD 掩模 M.2101 相控阵旁瓣全 NaN，导出掩模主瓣外全部落成 −999 哨兵
- 位置：`packages/core/utils/pfdmask/esPatterns.js:81`
- 根因：`Number(p.floorDbi) === undefined ? -10 : Number(p.floorDbi)`——`Number(undefined)` 是 NaN，`NaN === undefined` 恒 false，floorDbi 未提供（UI 根本没有该输入）时底板取 NaN → 主瓣外增益全 NaN → 经 maskEngine 合并（NaN 比较恒 false → −Infinity）→ clampValue 钳到 −999，恰是"该角域永不发射"的哨兵。XML 通过全部 XSD 校验正常落盘。
- 影响：选 M.2101 生成的 eirp_mask_es 等于向 ITU 申报"主瓣外永不辐射"，epfd(up) 旁瓣干扰被彻底抹零，**掩模严重偏松且完全静默**——这是可能交付给监管方的文件。已 node 实跑复现（φ≥4° 全 −999，对照 S.580-6 正常滚降）。
- 修法：改为 `Number.isFinite(Number(p.floorDbi)) ? Number(p.floorDbi) : -10`，补"主瓣外增益有限且滚降"断言。

### H3. fpMiniExport 的 nz() 把 null 变 0，小程序端全部空值兜底失效
- 位置：`src/shared/fpMiniExport.js:42`
- 根因：`const nz = (v) => (Number.isFinite(Number(v)) ? Number(v) : null)`——`Number(null)`、`Number('')` 都是 0，留空字段（转发器 SFD/G/T/IBO/OBO/C/IM、LO 值、未定频载波起止、组头带宽等）全部从 null 变 0 发给小程序；小程序端全用 `== null` 判空显示"—"，被 0 击穿。同仓 `fpXlsxModel.js:50` 的同名 nz 已正确加前置守卫并注明"这个坑在本模块吃过一次"，恰恰漏了这一处。
- 影响：几乎每份计划必现——未填的 SFD 显示"0 dBW/m²"、G/T 显示"0 dB/K"（貌似真实、实则大错的工程值），未定频载波写"0 ~ 0"，LO 显示"0 MHz"；平台侧同一数据显示"—"，两端矛盾，"没录"与"录了 0"再也分不开。
- 修法：把 nz 换成 fpXlsxModel.js:50 那个实现（null/undefined/'' 先返 null）。

### H4. 小程序：云噪声未计入系统噪温，下行 C/N 系统性偏乐观（镜像漂移）
- 位置：小程序 `miniprogram/utils/linkCalculator.js:693`、`linkCalculatorNGSO.js:748-750`
- 根因：平台已修"云噪入 T_sys"（core `linkCalculator.js:726-734`，275·(1−10^(−AC/10)) 经馈线折算入 T_sys），小程序未同步：只在功率链扣云衰、不抬噪温（基尔霍夫不自洽）；另雨噪介质温度小程序用 273.15、平台统一 275。
- 影响：典型 Ku 配置两端 G/T 差约 0.9 dB，小程序下行 C/N 与余量偏乐观 ~0.9 dB；平台发过去的配置一经用户点"计算"，同屏两套数。
- 修法：移植平台 core:721-733 到小程序两份引擎。

### H5. 平台：圆极化选 L/R 时引擎不识别，雨致 XPD 按 τ=0° 线极化算
- 位置：`src/ngso/ngsoParams.js:68,70`、`src/regen/regenParams.js:51,54`、`src/linkbudget/params.js:65,67`（UI 存 'L'/'R'）；引擎 `linkCalculatorNGSO.js:414` 等处只认 'LHCP'/'RHCP'
- 根因：极化归一化 `(display==='LHCP'||display==='RHCP') ? 'C' : display`，'L'/'R' 原样落下 → τ 取 0°（水平线极化）。P.618 §4.1 的 Cτ 在 τ=0° 为 +14.95 dB、τ=45°（圆极化正解）为 0 dB。
- 影响：LEO/MEO 常用圆极化——凡有降雨，雨致 XPD 被抬高 ~13-15 dB，交叉极化干扰几乎被算没，雨天 C/N 与余量偏乐观（典型 0.3~2 dB），交付报告 XPD 行直接错 10 dB 以上。
- 修法：三引擎入口归一化补 `pol==='L'||pol==='R'` → 'C'（上下行共约 4 处），补 L/R 与 LHCP 逐位一致回归测试。

### H6. 小程序：P.836 水汽地图经度基准错 180°，查到的是地球对面的水汽密度（镜像漂移）
- 位置：小程序 `miniprogram/data/waterVaporGrid.js:15,46`
- 根因：两端加载同一份 p836_rho_v1.bin（md5 相同），平台 2026-07-25 已取证确认该 bin 为 0…360 经度排布并改 0 基准解读（core `data/waterVaporGrid.js:54`）；小程序仍按 `LON_LEFT=-180` 解读，整张图错位 180°。
- 影响：北京站实际读到南美/南大西洋的水汽密度，误差可达 ±10 g/m³；Ku 大气衰减偏差 0.1~0.3 dB，Ka 可近 1 dB，上/下行同错。数据下载成功后反而比走 P.835 兜底更错。
- 修法：镜像平台版解读（删 LON_LEFT，cf 改 `(((lon%360)+360)%360)/STEP`），抽查两三个站点核对。

### H7. 小程序：收藏历史记录到配置存成扁平 linkParams，加载后链路参数静默丢失错配
- 位置：小程序 `pages/index/index.js:4026`（doSaveHistoryToConfig）
- 根因：写入 `linkParams: record.linkParams`（扁平对象），而全软件约定槽位形 `{1:{...}}`（同文件 3586 行的导出路径就是对的）。configs 页加载后 index onShow 的槽位兜底取 `_lp[1]` 得 undefined，链路参数恢复整段被跳过。这是备忘录"槽位兜底两处不是一处"之外漏掉的第三处写入点。
- 影响：加载收藏配置后，卫星参数是收藏的、发/收信站与载波还是屏上旧的——混血参数参与计算，无任何报错；切链路号再切回直接落成默认参数。
- 修法：改为 `linkParams: { 1: record.linkParams }`；并在加载处对存量扁平配置做形状归一（否则已收藏的坏配置修完代码仍复现）。

## 中危（18 条）

### A. 小程序引擎镜像漂移（平台已修、小程序未同步）

**M1. 雨致 XPD 仍是旧版公式，注释却标 P.618-14**（小程序 `linkCalculator.js:2256`、`linkCalculatorNGSO.js:2382`）
平台已按 P.618-14 §4.1 分段 Cf/V(f)/σ 离散/低频保护；小程序仍是 Cf=30lgf 连续旧式且 f<4 GHz 硬算。C 频段 XPD 两端差 6 dB 以上。修法：移植 core:1976-2038。

**M2. 可用度>99.99% 时闪烁衰减静默归零**（小程序 `linkCalculator.js:1765`、`linkCalculatorNGSO.js:1898`）
`p<0.01 return 0`——可用度从 99.99 调到 99.995，总衰减不升反降。平台已改 `pEff=Math.max(p,0.01)` 钳位。修法：镜像钳位。

**M3. P.676 低仰角(<5°)旧路径式**（小程序 `linkCalculator.js:2046`、`linkCalculatorNGSO.js:2173`）
5° 界面衰减跳变、θ→0 时路径少一半，低仰角余量偏乐观。平台已改 `2h/(√(sin²θ+2h/Re)+sinθ)`。修法：镜像两处。

**M4. C 频段 S.524 离轴 PSD 门限抄错表**（小程序 `linkCalculator.js:1033-1046` 及 NGSO 同段）
5.85-6.725 GHz 段比 S.524-9 正文严 6 dB，且 φ=2.5° 两侧跳 11 dB 自相矛盾。展示性读数不进 C/N 链，但用户对照会得出错误合规结论。修法：改回 32/11/35/−7 或移植平台 patterns.js 单一出处。

### B. 平台算法

**M5. PFD：倾角 0° 时纬度轴退化 [0,0,0]**（`pfdmask/maskEngine.js:87`）
赤道星座 pfd 掩模必失败且报错误导向 XSD 格式；eirp 掩模则带重复纬度切片直接落盘交付。修法：latMax≈0 特判单切片并给 validateSlices2 补查重。

**M6. PFD：扫描角族降维是空转**（`pfdmask/maskEngine.js:298`）
esPatterns 从不读 scanAngleDeg，扫描族每条曲线相同，"降维损失 0.00 dB"是假象，掩模未覆盖扫描态旁瓣抬升。修法：真实消费 scanAngleDeg，或未实现前撤掉 UI/meta 声称。

**M7. 频率计划：autoPlace 首次适配只避让游标点**（`src/shared/freqPlanCapacity.js:282`）
已有定频载波时"自动排布"会把新载波压在已定频载波身上（事后 computeLoading 能报冲突，但一键动作产出即非法）。修法：改区间感知的空隙表放置。

**M8. 波束合成：repackGrdCommonGrid 按高斯 3.6θ 窗假设估 θ3，PAM 导出欠采样 2.2 倍**（`src/viz/grd/synth.js:422`）
PAM 窗全宽 8θ3，导出重打包步长只到 ~θ3/3.6，波束等值线呈多边形、sinc 旁瓣被抹掉。修法：按 SYNTHMETA.kind 选换算因子或把 θ3 写进 SYNTHMETA。

**M9. 波束合成：批量表格逐波束宽度/旋转只画进草图，生成 GRD 时被丢**（`src/viz/grd/useBeamSynth.js:765`）
generateGroup 强制用反射面 th3Design 且 rot=0，草图/信息表与真实方向图覆盖面积可差 3 倍。修法：生成沿用 b.thX/thY/rot，或表格列改只读收口。

**M10. 波束合成：仿真频率≠设计频率时宽度不随 λ 缩放但增益随 λ² 抬升**（`src/viz/grd/useBeamSynth.js:140`）
th3Sim 算了但全仓无消费（死代码），能量口径失衡，波束边缘增益偏高 1~3 dB，与悬停提示矛盾（赋形档是对的）。修法：simSame=false 时全链路改用 th3Sim。

### C. 平台数据安全 / 多窗一致性

**M11. 三链路窗关窗不冲刷 500ms 库存盘防抖**（`src/linkbudget/LinkBudgetApp.vue:194` 及 NGSO/再生式同构）

**M12. 文件管理删除/改名频率计划后，编辑窗自动整份覆盖**（`src/components/FileManager.vue:238`、`FreqPlanApp.vue:278`）

**M13. 无单实例锁，双开应用互相覆盖 library.json**（`electron/main.js`）
两实例各自整写命名空间，后写者冲掉前写者，configs.json 同理。修法：`app.requestSingleInstanceLock()` 三行。

**M14. custom.json 与 GXT index.json 非原子写且损坏时静默清空**（`electron/services/customSats.js:253`、`coverageGxt.js:26`）
断电截断 → 读侧静默空库 → 下次写盘用空库覆盖 → 永久丢。修法：换 storage.js 同款 tmp+rename+bak，读侧先试 .bak。

**M15. 活动配置有未保存编辑时发送到小程序，新参数的结果贴到旧参数上**（`src/linkbudget/LinkBudgetApp.vue:1372`、NGSO 同构）
useRes 只校验行数不校验内容一致，接收方按"平台计算值"采信一套物理上对不上的参数+结果。修法：加 fingerprint/isDirty 判定。

**M16. 草稿以恒定 srcId 投递，两次不同草稿在小程序端互相覆盖**（`LinkBudgetApp.vue:1388`、NGSO 同构）
'GEO:__draft__:0' 恒定身份，数月后另一条链路顶掉手机上原配置；行下标做身份后半段同病。修法：草稿按无 id 处理退化为内容哈希。

### D. 小程序数据安全

**M17. 清除缓存保留 satsimSeen，被清掉的频率计划/覆盖快照永不补拉**（小程序 `pages/settings/settings.js:7`）
数据清了、"已收"账没清，手动同步报"已是最新"，唯一恢复路径是平台重发。修法：satsimSeen 移出 KEEP_KEYS（导入按 id 幂等，重拉无副作用）。

**M18. 覆盖快照队列单键囤多份整包，超 1MB 后永远落不了地且每轮重拉**（小程序 `utils/satsimBox.js:254`）
单键 satsimGxtInbox 堆整包，超微信 1MB 上限后写入抛错 → 不记 seen → 每轮重新下载再失败，无限烧流量且快照永不出现。修法：照 fpPlan 模式分键存 + 失败单独记账。
