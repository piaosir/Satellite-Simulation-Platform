## 3. 阶段一查出来的事实（与线索不符 / 需要记录的）

### 3.1 国名锚点确系 NE 的 `LABEL_X/LABEL_Y`

任务书 §1.2-5 的猜测已证实。NE 10m `admin_0_map_units` DBF 实测：

| ISO3 | NE `LABEL_X` | NE `LABEL_Y` | `countryZh.js` 现值 |
|---|---|---|---|
| GNQ | 8.9902 | 2.333 | (8.9902, 2.333) |
| NZL | 172.787 | −39.759 | (172.787, −39.759) |
| TTO | −60.9184 | 10.9989 | (−60.9184, 10.9989) |

逐位相等。**结论：NE 的标注点本就允许落海**（多岛国取整体形心：赤道几内亚 = 比奥科岛 + 大陆，新西兰 = 南北两岛，特多 = 两岛）。这不是 NE 的错，是它与本平台的用途不同——NE 的 `LABEL_X/Y` 是给「可以压着海放标签」的制图用的。本平台的国名层要求锚点落陆（点选与避让都按落点算），故这是**本平台自己的口径**，在 `countryZh.js` 覆写这三条，其余 171 条保持「一字不改」。

### 3.2 Natural Earth 版本号逐图层不同，不是统一的「5.x」

`scripts/_ne/*.zip` 内 `VERSION.txt` 实测：

| 图层 | 版本 |
|---|---|
| `ne_{10m,50m,110m}_admin_0_map_units` | **5.1.1** |
| `ne_10m_admin_0_disputed_areas` | **5.1.1** |
| `ne_50m_admin_0_breakaway_disputed_areas` | **5.1.1** |
| `ne_10m_admin_1_states_provinces` | **5.1.1** |
| `ne_{10m,50m,110m}_admin_0_boundary_lines_land` | **5.1.0** |
| `ne_10m_populated_places` | **5.1.2** |

`build-basemap.mjs` 的 `meta.source` 原写「Natural Earth 5.x」，本次补成逐图层的具体版本号（脚本改了 meta 字段，**不重跑构建**——版本号是记录，不影响几何）。

### 3.3 geoBoundaries 的数据**一份都没有随包分发**

`build-adm.mjs` 文件头把 ADM2 写成「geoBoundaries gbOpen 逐国」，`scripts/_ne/` 里也确有 `gb-CHN-ADM1.zip` / `gb-CHN-ADM2.zip` / `gb-meta.csv` 三份缓存。但**实际产物只有 252 个文件：251 个 ADM1 + 1 个 `CHN-adm2.json`**，`index.json` 的 `adm2` 数组长度为 1，`ATTRIBUTION.json` 里 250 条 Public domain（NE）+ 2 条 DataV，**零条 geoBoundaries**。

即：gbOpen 是构建脚本**支持**的源，但没有从它生成过任何随包文件；中国的两级都走 DataV。台账按实际产物登记，不按脚本能力登记。要真出别国 ADM2 得跑 `node scripts/build-adm.mjs <ISO3>`，那时 ATTRIBUTION 才会出现 CC BY 4.0 / ODbL / PDDL 的逐国许可。

### 3.4 `povs/*.json` 是 NE 的派生产物，不是本平台自定

任务书 §1.2-6 把 `povs/*.json` 与 `frozen.js`、`povList.js` 一起归为「本平台自定，不是外部数据」。实测：`povs/*.json` 由 `build-basemap.mjs` 的 `writePovs()` **从 NE 自带的 32 套官方归属列生成**（`ADM0_A3_CN` / `ADM0_ISO` / `ADM0_A3_US` / `ADM0_A3_RU` 四列），`povList.js` 文件头也是这么写的。本平台自定的部分只有三处：取哪四套、台港澳剔除、CN 视角挂十段线与 `labels.hide`。

`frozen.js` 与 `povList.js` 确系本平台自定。台账按此分列（总表 #4 / #5）。

### 3.5 影像瓦片的两条源不是同一份文件

- 瓦片包（#9）用官方**八分幅** `3x21600x21600.{A1..D2}`，拼起来 86400×43200 = 500 m/px；
- 整幅档（#10）用官方**单张** `3x21600x10800`，1.86 km/px。

同一期（2004-07 topo+bathy）、同一署名，但不是同一个文件、也不是同一个分辨率。台账分两行登记。

### 3.6 `meta.iso3n3` 已弃用

`build-basemap.mjs:278` 与 `povResolver.js:24` 都写明：那张表是构建期从 map_unit 的 `ISO_N3` 列「先到先得」猜的，法国/挪威取错、AUS/CSI/ATC 与 ATA/ATG 撞码，已不再产出。数字码现由 `countryZh.js` 静态表反建（`ISO_NUM_TO_A3`），只供老存档迁移。

### 3.7 与任务书正文的三处数值出入

| 任务书 | 实测 |
|---|---|
| §2.1「L0 环绕带 −180° 到 −144°」 | 实为 **−180° 到 +36°（216° 宽）**。L0 网格 2 列 × 288° = 576°，横向越界 216°；列 1 的 west=108、east=396 → 环绕覆盖 −180..36。L1 的 −180..−108（72°）是对的 |
| §2.6「三档 \|lon\| ≥ 179.99 的最高点是 −84.35°」 | 10m / 50m = **−84.35°**，110m = **−84.71°**。三档都 ≤ −80，「无残段」的结论不变 |
| §1.2-1「meta 只写 5.x」 | 见 §3.2：不是一个版本号，是三个 |

其余附录 A–D 的实测数字与任务书逐项相符（110m 五点填充失败 / 174 条锚点 3 条落海 / USA 25 段·CAN 8 段·AUS 3 段沿纬线超 2° / CAN 60°N 那段沉 84.7 km·北凸 38.1 km）。

## 4. 评估与遗留

### 4.1 110m 档的现状

数据文件、`ensureDetail('110m')` 分支、`backfill-basemap.mjs` 的 110m 目标都在，但 `displayQuality.js` 的 `MAP_LEVELS` 只有 50m / 10m 两档，老存档里的 `'110m'` 在 `loadInit()` 里被迁到 `'50m'`。**用户当前碰不到这一档**。下线理由写在 `displayQuality.js:13-16`：NE 不出 110m 的争议面图层，藏南 / 阿克赛钦 / 克里米亚这类「宿主里的一块」在该档表达不出来——那不是「粗」，是错。

### 4.2 `countries-50m.json` 切到主权解算层的收益与代价（评估于 2026-09-05；**已于 2026-09-11 做完**）

**结果**：`lbBasemap.js` 改为动态 import `povResolver`，`ensureDetail('50m')` 后取 `landRings('50m')`（与视角无关的陆地环，只用来 evenodd 填色）+ `resolvedLines('50m')`（coast 单独一份描岸线；admin0 + indefinite + loc + claim 并成国界层，一律实线）。`onPovChange` → 整份重建 → `onBasemapChange` 通知 `LbSurfacePlot` 重画、`linkGlobe` 作废贴图重生成。`countries-50m.json` 已删。下面四条代价逐一对应：1 用 `landRings` + `prepareLines` 解决（不再并面，evenodd 直接吃逐单元的环；有宿主的争议叠加不进环集，否则被 evenodd 抠成洞）；2 五类并两类：coast 一类、其余四类一类；3 接上广播；4 本就是 Promise。直接动因是黄岩岛那次核查（见 #5）：链路预算的地理场图是最后一处不走主权口径的地图。

**收益（当时的评估）**：链路预算地理场图的国界与主地图**同一套主权口径**——目前它画的是 world-atlas（NE 4 时代）的一份**已经画好的**国界，台港澳、藏南、阿克赛钦的画法与主地图不一致，且不随「地图视角」设置走。换成 `resolvedFeatures('50m')` / `resolvedLines('50m')` 之后两处口径合一，视角切换也能带上。顺带甩掉一份 0.74 MB 的重复底图。

**代价**：

1. `lbBasemap.loadBasemap()` 现在用 `topojson.feature(topo, topo.objects.land)` 取整块陆地、`topojson.mesh(countries, a!==b)` 取国界。主权解算层没有 `land` 这个对象（它是「争议单元级的面 + 归属表」），陆地面得由逐单元的面自己并起来，而 `preparePaths` 的解缠 + 包围盒 + `Float64Array` 压平那套预处理要按新的数据形状重写。
2. `resolvedLines` 出的是**按类分组的线**（admin0 / coast / loc / indefinite / claim 五类），不是一条 mesh。`lbBasemap` 只画 COAST 与 BORDER 两种颜色，得先定「五类怎么并成两类」。
3. 主权解算层是响应式的（`onPovChange` 会广播重建），而 `lbBasemap` 是「懒加载一次、`_map` 缓存住」的静态模型——要么接上广播，要么明写「地理场图不跟视角」。
4. `resolvedFeatures('50m')` 走 `ensureDetail` 的动态 import，是异步的；`lbBasemap` 现在也是 Promise，这一条不难。

**结论**：技术上可行、口径上应该做，但它改的是链路预算那一侧的渲染管线，不属于地图核查的范围。单开任务，且按「大改动先单点原型」的教训，先只切国界那一层跑通再碰陆地面。

### 4.3 整幅影像贴图没有重生成脚本

`16k_earth_bmng.jpg` / `8k_earth_bmng.jpg` 是从官方 21600×10800 手工缩制的，`src/viz/imagery.js` 的文件头记了来源与两条约束（两档必须同源、16384 是 GPU 纹理上限），但**没有脚本能把它重跑出来**。瓦片包那一侧有 `build-imagery-tiles.mjs` + `check-imagery.mjs` 两道，整幅档这一侧是空的。要补的话是一个十几行的 `nativeImage` 缩制脚本，与瓦片脚本共用下载那一段。本次不补，记在这里。

### 4.4 `scripts/_ne/` 缓存不进仓库

`.gitignore` 排除 `scripts/_ne/`。所有构建脚本首次运行会重新下载（NE 走 `naciscdn.org`，DataV 走 `geo.datav.aliyun.com`，geoBoundaries 走 GitHub raw）。**版本号因此不是钉死的**——重跑一次可能拿到比 5.1.1 更新的 NE。`neFetch.cached()` 只按「文件存在且 >512 B」判命中，不校验版本。要复现某一版得自己保住缓存目录。
