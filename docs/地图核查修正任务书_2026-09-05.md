## 2. 阶段二：已核实的错误（按用户可见程度排序）

### 2.1 [3D · 影像底图] L0 / L1 补边瓦片横向环绕，压在正确的片上

**现象**：影像底图开着，相机距离 D 在 7.4–13.8 之间（选到 L1）或大于 13.8（选到 L0）时，经度 −180° 到 −108°（L1）或 −180° 到 −144°（L0）一带出现竖向条纹或闪烁。选级公式见 `scene.js` `updateImageryTilesInner`：`degPerPx = 2(D−1)·tan(fov/2)·57.3 / hPx`，`pickZoom` 取 `ceil(log2(0.5625/degPerPx))`。

**根因**：
- three.js 的 `SphereGeometry` 不钳制 `phiLength` / `thetaLength`：`node_modules/three/src/geometries/SphereGeometry.js:100-102` 顶点直接用 `thetaStart + v·thetaLength`，`thetaEnd` 只用于极点 uv 偏移和索引。
- `imageryTiles.js` 的网格在 L0–L2 比世界大：L0 是 2×1 片、每片跨 288°；L1 是 3×2、跨 144°；L2 是 5×3、跨 72°。切片脚本 `build-imagery-tiles.mjs` 的 `cutTile` 把越出世界的部分按边缘复制补齐。
- `scene.js` 的 `tileGeometry(z, r)` / `makeTileMesh` 按整片跨度建球面扇区：L1 第 2 列 west = 108°、跨 144°，覆盖经度 108° 到 252°，等价于 108° 到 180° 再加 −180° 到 −108°。右半是补边内容，与第 0 列同半径 0.998、同 polygonOffset（都是 −(z+1)）叠画，z-fighting。L0 第 1 列同理错 36°。
- 纵向越过南极的部分（L0 单行跨 288°，L1 第 1 行、L2 第 2 行）因绕序翻转被背面剔除，肉眼看不见，但顶点与纹理白算白传。
- 2D 不受影响：`imageryPlan` 画到世界矩形之外的部分被 `drawBelowContent` 的 clip 裁掉。

**修正**：
- `imageryTiles.js` 新增纯函数 `tileClip(z, row, col)`，返回 `{ west, north, spanX, spanY, fx, fy }`：`spanX = min(east, 180) − west`，`spanY = north − max(south, −90)`，`fx = spanX / span(z)`，`fy = spanY / span(z)`；`fx ≤ 0` 或 `fy ≤ 0` 返回 null。
- `scene.js`：
  - `tileGeometry` 的缓存键改成 `z/row/spanX`（L0 / L1 同一行会有两种宽度）；`SphereGeometry` 用 `phiLength = spanX`、`thetaLength = spanY`，段数按各自跨度取 `max(4, min(32, round(span/2)))`。
  - `tileTexture` 按 fx / fy 设纹理窗口（g = gutter，N = tileImgSize）：`offset.x = g/N`，`repeat.x = fx·TILE/N`，`offset.y = 1 − (g + fy·TILE)/N`，`repeat.y = fy·TILE/N`。fx = fy = 1 时与现值逐项相等，先用这条等式自证再上线。
  - `makeTileMesh` 对 `tileClip` 为 null 的片直接跳过；`rebuildBaseLayer`（L2 底层）同路。
- **验收**：单测 `tileClip` 全级全片满足 `west + spanX ≤ 180`、`north − spanY ≥ −90`，L3 起 fx = fy = 1；影像模式把相机拉到 D≈10 看太平洋无条纹；`imageryStats` 的 geo 计数正常（GEO_LIMIT 256 仍够）。

**证据**（附录 C / D 脚本输出）：

**修正**：
- 新增 `src/viz/geo/lineGeom.js`，导出 `densifyLonLat(pts, maxDeg = 1)`：就近解缠、线性插值到相邻间距 ≤ maxDeg、末尾折回 [−180, 180)。把 `islandChains.js` 的私有 `densify` 改为调用它（`mapAnnotations.test.mjs` 第 ⑪ 条守间距）。
- `scene.js` 的 `classPos()`、`setProvinces()`、`setCities()`：先 `densifyLonLat` 再 `llaToVec`；`classPos` 保留后面的 `densifyArc`（对 ≤1° 的段是 no-op）。不动 `admPacks.mergePacks`，2D 不需要。

### 2.3 [2D · 折线] `drawPolyline` 跨接缝的那一段整段丢掉

**位置**：`flatCoverage.js` `drawPolyline()`：`if (started && Math.abs(wx - pwx) > 180) { ctx.stroke(); ctx.beginPath(); started = false }`。跨缝的线段两端都不画到边，留一个缺口。

**影响**：聚焦星覆盖圈（72 点，5° 一段，缺口 5°）、航迹稀疏航点（可缺几十度）、用户改画面中心后跨缝的省界 / 岛链 / 等仰角线。3D 没有接缝，不受影响。

**修正**：在缝上插值断开。设前点 (pwx, pwy)、当前点 (wx, wy)，先取 wx′ = wx ± 360 使 |wx′ − pwx| ≤ 180；出边 xo = wx′ < 0 ? 0 : 360；t = (xo − pwx) / (wx′ − pwx)；ys = pwy + t·(wy − pwy)。绘制：`lineTo(xo, ys)`、`stroke`、`beginPath`、`moveTo(360 − xo, ys)`、`lineTo(wx, wy)`。这段算式抽成 `lineGeom.js` 的纯函数 `seamCrossing(pwx, pwy, wx, wy)` 返回 `{ xOut, xIn, y }`，`drawPolyline` 内联调用、不分配数组：它是静态层每次重建的热路径，CHN adm2 有 4.5 万段。

**验收**：单测 `seamCrossing` 覆盖左出 / 右出、y 插值；2D 画面中心改 0°E 后第三岛链在 180° 处连续。

## 附录 A：南极填充点判（三档 · 2D 现状 vs 改后 vs 3D）

存为 `scratch/ata.mjs`，在仓库根目录 `node scratch/ata.mjs` 运行。

```js
import fs from 'fs'
import { feature } from 'topojson-client'
import earcut from 'earcut'
import { antarcticaFillRings } from '../src/viz/globe3d/antarctica.js'

const LON0 = -30
const unwrap = (ring) => { const out = []; let prev = ring[0][0]; out.push([prev, ring[0][1]]); for (let i = 1; i < ring.length; i++) { let lo = ring[i][0]; while (lo - prev > 180) lo -= 360; while (lo - prev < -180) lo += 360; out.push([lo, ring[i][1]]); prev = lo } return out }
```

## 附录 E：2D 投影扩展分析（不在本任务范围，供用户拍板）

### E.1 现有架构对投影的约束

- 2D 的一切矢量层都烘成「世界度坐标」Path2D（x = lon − LON0，y = 90 − lat），逐帧只用 `setTransform` 做平移缩放。任何**固定中心**的投影都能沿用这套设计：换投影时按投影平面单位重烘一次（`setLon0` 已经是这条通路：换切口就整份重烘），之后平移缩放仍是仿射。
- 要新增的东西：正算 / 逆算函数（`screenToLonLat` 要逆算）；栅格层（影像瓦片、环境场位图、`bakeImagery`）的重投影；直线假设的处理（2D 现在把经纬点直连，非圆柱投影下长线段要先经纬面加密再投影，2.2 的 `densifyLonLat` 正好复用）；±360 环绕副本在非圆柱投影下不再是平移，要改成裁剪 / 切环（2.3 的接缝断开是第一步）；南极环在极方位投影下的收口。
- 地名避让在屏幕空间做，不受投影影响。
- 成熟参考：d3-geo（MIT，纯 JS，`geoPath(context)` 直接画 canvas，自带反子午线切割与球面裁剪）+ d3-geo-projection（Robinson / Winkel / Equal Earth 等）。按「先找成熟方案再动手」的约定，投影数学与裁剪应直接用它，不要手搓。

### E.2 候选投影与代价

| 档 | 投影 | 用途 | 代价 |
|---|---|---|---|
| 一（圆柱，只变 y）| Mercator（Web 口径，钳 ±85°）、Miller、等积圆柱（Lambert / Behrmann）| Mercator 是 GIS 与在线瓦片的通用口径，等积圆柱给覆盖面积统计一个不撒谎的底图 | 最低：x 不变，Path2D 重烘换 y；栅格按行拉伸（逐行 drawImage 或一次性行映射）；环绕副本仍是平移 |
| 二（伪圆柱全球图）| Robinson、Winkel Tripel、Equal Earth、Mollweide、Hammer | 出图美观，宣传与报告用；等积那几种配覆盖面积读数 | 中：x 随纬度变；栅格逐像素反算；边界变成曲线，环绕副本改裁剪 |
| 三（方位，本平台最贴切）| 正射（从无穷远看）、垂直透视 / 卫星视角（从卫星看，SATSOFT 的 Perspective uv / θφ / Az-El / El-Az 四种、STK 的 Perspective）、方位等距（以地球站或极点为心，真距离真方位）、极球面（极区共形）| 卫星视角是天线工程师的原生坐标，GRD 等值线在这里画成圆而不是被等距圆柱拉扁；方位等距以站为心时等仰角线成同心圆，极方位给极轨星座看北极覆盖 | 高：只画半球要做背面剔除；交互从平移变成转中心（与 3D 相同）；栅格逐像素反算 |
| 四（圆锥，区域图）| Lambert 共形圆锥、Albers 等积圆锥（中国全图惯用标准纬线 25°N / 47°N、中央经线 105°E）| 报告里的中国全图 | 中：区域投影要参数面板；只对区域图有意义 |

不建议：横轴墨卡托 / UTM 作为地图投影（坐标格式已提供 UTM / MGRS / 高斯-克吕格读数，作为地图只有一个带宽），正弦投影，心射投影。

### E.3 对标

- SATSOFT 3.2.0 手册 §1.1.5 与「Map Projection/Coordinate System」：九套显示坐标系，前四种是透视投影的变体（Perspective uv、Perspective θφ、Mod Perspective Az/El、Mod Perspective El/Az），两种方位等距（角与距离两种径向标度），方位等积，正射，等距圆柱。手册原话：Orthographic is similar to perspective, except that the view is from infinity.
- STK 2D 图形窗口据我所知提供等距圆柱、Mercator、Miller、Mollweide、Sinusoidal、Hammer-Aitoff、正射、球面（Stereographic）、方位等距、等积圆柱、Lambert 共形圆锥、Perspective 一类，具体以 STK 帮助为准。

### E.4 建议次序

1. Mercator 先做：最便宜，且能把「投影抽象」（正逆算 + 整份重烘 + 栅格行拉伸）立起来验证，风险最小。按「大改动先单点原型」的教训，先只投陆地与五类边界线，跑通再碰栅格与覆盖场。
2. 卫星视角（垂直透视，带天线 Az/El 轴）：这是本平台相对 STK 的差异化能力，也是 SATSOFT 的默认工作视图。
3. Equal Earth 或 Robinson：出图美观。
4. Albers 中国：报告用区域图。
