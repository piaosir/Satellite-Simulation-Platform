## 1 背景（为什么这么做 —— 调研结论，已核实）

- 用户原先指定的 SatMaster 自带 `TIMEZONE.GIF` 就是 **CIA《Standard Time Zones of the World》2013-09 版**（803569AI (G01802) 9-13，米勒圆柱，栅格 4000×2120，约 11 px/度）。CIA 后来出过 **2021-02 版**（2020-00228-02 2-21），那是最后一版：**CIA《世界概况》已于 2026-02-04 停刊**。NASA 没有出过世界时区图。两版 CIA 图都把台湾单独标注、国界按美方口径，不能直接用。
- Natural Earth 10m 时区（公有领域）的数据停在 **2012-11**（之后只有 2017 年一次编码改动）。
- **timezone-boundary-builder（下称 TBB）2026e**（2026-10-11 发布，配 tzdb 2026e）由 OSM 的 `boundary=timezone` 派生，县级精度，带 IANA 时区号。数据许可 **ODbL 1.0**（OSM 派生）。
- 近年 CIA / NE 都没有的变化：哈萨克斯坦 2024-03 统一 UTC+5；巴拉圭 2024-10 起永久 −3；智利艾森大区 2025-03 起 −3（新时区 `America/Coyhaique`）；2026 年 BC 永久 −7、阿尔伯塔永久 −6、西北地区永久 −6、曼尼托巴永久 −5（tzdb 2026b–e 均把生效建模在 2026-11-01 02:00，照 tzdb 走）；摩洛哥 2026-09-20 起永久 +00；格陵兰 2023 年改 −2；墨西哥 2022 年废夏令时。2013 版另缺俄罗斯 2014 / 2016 两轮、土耳其 2016、委内瑞拉 2016、苏丹 2017、南苏丹 2021、纳米比亚 2017 等。

## 2 口径（全部拍板，照做）

### 2.1 位置与形态
- 主窗活动栏「环境场」视图（`src/pages/ConstellationMap3D.vue` 里 `shellUi.side === 'env'` 那块侧栏）末尾新增一个分区 **「时区」**。它是**独立图层**：有自己的图层开关（拨杆），与 ITU 环境场、实时气象场都可同屏共存，**不受「显示环境场」总开关影响**（现在 `.env-side.hid` 会把整块 `.sec` 压暗到 0.5，时区分区要豁免；它关着时只压暗它自己的参数行）。
- 侧栏收起或切到别的视图不撤图层：`shellUi.side` 只管面板画不画，图层只跟着自己的设置走（平台口径：收起侧栏 ≠ 离开视图）。
- 2D 平面图（全部 6 档投影）与 3D 球体都要画；导出 PNG / 矢量 PDF / 3D 截图 / 视频都要带上。

### 2.2 时间口径
- 时刻一律取全局仿真时钟 `clock.tMs`（`src/stores/simClock.js`）。**在同一拍里更新**：时钟每拍走 `refreshPositions()`，时区层也在这一拍里算完，不许延后到下一帧（平台铁律：一次 onTick = 一个时刻的完整画面）。
- 「夏令时」是一个复选框（缺省勾上）：
  - 勾上＝**当地民用时**：该区在仿真时刻的实际 UTC 偏移（含夏令时）。时钟拨到欧洲夏季，色块和界线跟着变。
  - 不勾＝**标准时**：去掉夏令时。口径是 tzdb 的 **rearguard 语义（夏令时一律为正）**：爱尔兰全年 +0（夏天那 1 h 算夏令时）；摩洛哥 / 西撒 2018-10-28 至 2026-09-20 期间标准时 +00；纳米比亚 1994–2017 标准时 +02。验收数见 §7.1。
- 海区固定偏移，没有夏令时（两种口径下相同）。

### 2.3 陆地：哪块地用哪个时区
- 陆地几何**一律用本平台底图**（`src/viz/globe3d/data/basemap-{10m,50m,110m}.json` 的单元面），按与当前底图**同一档**出图。时区界里与国界重合的那几段，坐标必须与底图弧**逐点相同**（同一量化网格），这样两条线严丝合缝，不出双线。
- 每块地的归属走主权解算层：`povResolver.ownerOf(u, detail)` + 与 `resolvedFeatures()` 同一套「争议叠加」优先级。时区按**归属国**取：
  1. 归属国的有效时区集合 = tzdb 2026e `zone1970.tab` 里国家码含该国 ISO2 的时区。
  2. TBB 在这块地上标的时区若属于归属国 → 用它（多时区国家据此细分到县级）。
  3. 否则用归属国离这块地最近的那个时区；再没有就用该国的主时区（`zone1970.tab` 里该国第一条）。
  4. 归属为 `disputed` / `none` / 无 ISO2 映射 → 用 TBB 在该处标的**事实时区**。
- **中国**：归属为 CHN 的地一律 `Asia/Shanghai`（北京时间）。tzdb 的 `Asia/Urumqi` 是 UTC+6，**不得**出现在任何归属中国的地上（新疆、阿克赛钦、藏南在中国视角下都是 +8）。台湾、香港、澳门三个冻结单元（`CN-TW` / `CN-HK` / `CN-MO`）各用自己的 tzdb 时区（`Asia/Taipei` / `Asia/Hong_Kong` / `Asia/Macau`）：1992 年以来与北京时间逐时刻相同，图上不会出现任何分界；只在 1986–1991 年夏令时期间如实不同。这条规则写进构建产出的数据，运行时代码不出现 `CHN`。
- 南极：有 TBB 南极时区（`Antarctica/*`，或国家码含 `AQ` 的，如 `Asia/Riyadh` 覆盖昭和站一带、`Pacific/Auckland` 覆盖麦克默多一带）的地方用它；其余按 15° 航海时区带（固定偏移）。
- 湖泊：底图单元若把湖挖成洞，洞按 §2.4 的「内陆水域」处理。

### 2.4 海区
- 海上一律 **15° 航海时区带**，固定偏移：偏移小时 = round(经度 / 15)，±12 两带在 180° 分开（+12：172.5°E–180°；−12：180°–172.5°W）。不画领海、不画 CIA 式的岛屿方框。
- **日界线**用 Natural Earth 10m `geographic_lines` 里的 International Date Line（公有领域，2012-11 按萨摩亚 / 托克劳 2011 改线更新，此后未变）。它在三处凸出：
  - 南太平洋基里巴斯凸区（180° 以东，−51° 到 4.94°N）；
  - 白令海峡凸区（180° 以东，59.5°–75°N）；
  - 阿留申凸区（180° 以西，48°–59.5°N）。
- 凸区里的海面偏移**照 NE 10m `time_zones` 那几块面的名义值**（公有领域，与它的日界线同批对齐过）：基里巴斯凸区内分 +12 / +13 / +14 三块（NE 面外接框依次为 [−180,−51,−172.5,−2.5] / [−180,−26,−158.5,−2.5] / [−160.6,−11.6,−150,4.94]），白令凸区 +12，阿留申凸区 −10。凸区以外一律按上一条的航海带。
- **内陆水域**（与世界大洋不连通的水面，如里海、咸海，以及湖洞）：不填色、不画界、不出标注、读数不给值。

### 2.5 界线
- 一条边**两侧当前偏移不同才画**（随仿真时刻与口径变：夏令时期间亚利桑那与犹他之间会冒出一条线，冬天又消失）。岸线不算时区界（陆地与海带偏移不同时，只靠色块变色体现）。
- 两侧偏移相差 ≥ 12 h 的边归为**日界线类**，按日界线样式画。日界线开关关掉时，这类边按普通时区界画。
- 「描亮显示时区」：偏移等于当前显示时区档在仿真时刻偏移（`tzOffMin(tzMode, clock.tMs)`）的那些连通区，外轮廓按界线宽 ×1.8 描，并铺一层同色 0.16 不透明度的淡洗（色块开着时改为该区色块不透明度 +0.20）。

### 2.6 标注
- 内容两行：
  - 第一行是偏移，格式与平台一致，用 `tz.js` 的 `tzOffLabel`（`UTC+8`、`UTC+5:30`、`UTC−3:30`，负号是 U+2212，0 写 `UTC`）。
  - 第二行在「当地时刻」勾上时出现，写该区在仿真时刻的星期与时分。中文 `周二 14:32`，英文 `Tue 14:32`，走 `byLang`。星期跨日界线时自然不同，这正是要表达的。
  - 两种口径下，第二行都用当前口径的偏移算。
- 摆放：
  - 陆地按「同偏移连通区」各标一次，锚点取该区里内切圆最大的那块面的 polylabel 点（构建期预算好锚点与内切半径）。区在屏上小于约 40 px（按内切半径折算）就不标。
  - 标注之间避让，按区面积排优先级；能接进既有国名避让就接进去。
  - 描亮区的标注加粗。
- **2D 顶部标尺**（等距圆柱 / 墨卡托 / 罗宾逊 / 等积地球四档）：
  - 沿地图可见区域上沿、离上沿 6 px，每条 15° 航海带在其中央经线处标一个（中央经线与可见上沿的交点），两行内容同上。
  - 带宽放不下时依次降级：先去星期、写成 `+8` / `14:32`，再隔带标。
  - 海区在这四档不再另出图内标注。Albers 与方位等距两档不画标尺，改为海区连通区的图内标注（规则同陆地）。
- 3D：陆地连通区标注 + 海区连通区标注（锚点同上），背面剔除，按屏上大小做 LOD。
- 字号与样式：偏移 12 px 粗体、时刻 11 px，颜色取时区线色，套边按 `src/viz/labelInk.js` 的底图明度两档。另给「粗体」选项：平台所有地图文字都有粗体开关，这里也要。
- 刷新：时间文字随仿真时钟变，刷新 ≤ 4 Hz（实时档每分钟一次就够）；3D 标注纹理合进一张图集更新，不许逐精灵每帧重烘。

### 2.7 色块（缺省关）
- 按**整点偏移**循环 6 色（CIA 式，相邻带必不同色）：索引 = ((⌊偏移/60⌋ mod 6) + 6) mod 6，色依次 `#E8C88F`（沙）、`#B9D3A0`（灰绿）、`#EDB49A`（橙粉）、`#A9C4D8`（灰蓝）、`#D9B8D6`（藕紫）、`#EFE09A`（麦黄）。
- 陆地用原色，海区用原色与白 1:1 的浅色。
- 半点 / 45 分时区（印度、伊朗、尼泊尔、查塔姆…）用上下两个整点色的 45° 斜纹（CIA 体例）：2D 用 `CanvasPattern`，3D 用屏幕空间斜纹着色器（6 px 周期）；矢量 PDF 兼容模式退成两色均值的实色。
- 不透明度缺省 0.40，可调。
- 层序：2D 画在环境场栅格之后、底图边界线之前；3D 在环境场贴图球之后。晨昏夜区照旧压在下面（夜区是打光，不是数据）。

- 「1970 合并版」：TBB 把 1970 年以来规则完全相同的时区合成一个面，取一个代表时区号。对 1970 年以后的任何时刻，按代表号算偏移逐位不差。`zone1970.tab` 正好是同一口径，国家码已含合并进来的国家（例：`Europe/Berlin` 带 `DE,DK,NO,SE,SJ`，`Asia/Riyadh` 带 `SA,AQ,KW,YE`）。
- 本合并版里没有 `Asia/Macau`（并进了 `Asia/Hong_Kong`）。`CN-MO` 那块显式指定 `Asia/Macau`，规则表里要有它。

### 3.2 分区算法（每档各做一遍；建议用 `jsts` + `polylabel` 做构建期依赖，`topojson-server` 已在 devDependencies）
1. **解码底图**：用 `topojson-client` 把基础单元面与争议叠加面原样解出（坐标就在底图量化网格上）。叠加面落在宿主面之内（NE 的「基础分区 + 争议叠加」模型，不是互斥分区），所以要先做成**平面剖分**：宿主扣掉叠加；叠加之间重叠的，按 `units` 数组顺序后者优先（与 `resolvedFeatures` 的绘制顺序一致）。每个面记 `u`（基础单元）与 `ds`（覆盖它的争议单元，按优先级排）。
2. **多时区单元细分**：仅限基础单元（非争议）。用该单元缺省归属（`own0`，过 `normOwner`）按 §2.3 求有效 TBB 时区。若面积份额 ≥ max(0.5 %, 50 km²) 的有效时区 ≥ 2 个，就切开：
   - 切的方法：单元 ∩ 各 TBB 时区面（TBB 面先按档做**拓扑保持**简化，容差 10m 0.004°、50m 0.02°、110m 0.08°）。
   - 切出的缝隙按「共边最长」并给邻块；碎块同样处理。
   - 结果：国界段与岸线保持底图原坐标，内部界取 TBB。
3. **每块地的候选归属表**：
   - 候选归属收齐：`own0`、`FROZEN`、`CUSTOMIZABLE_DISPUTES[].opts`、全部 `src/viz/geo/povs/*.json` 的 `own` 里出现过的值，都过 `normOwner`。
   - 每个候选求一个时区号，记成 `zt`；另记事实时区 `z0`。
   - 中国规则与台港澳规则按 §2.3 写进 `zt.CHN`。
   - 另出 `principal`（ISO3 → 主时区号）供运行时兜底。
4. **海区**：
   - 海面 = 全球 − 陆地并集。
   - 用这几样线把海面剖开：凸区以外的航海带经线（7.5° + 15°k）、日界线、凸区内 NE 时区面的边、岸线。
   - 与世界大洋连通的面记海区偏移（§2.4），不连通的记内陆水域。
5. **统一结点**：陆地面 + 海面一起过一次结点化，**吸附到该档底图的量化网格**。这样所有公共边逐位相同，国界段与底图弧逐点相等。然后建拓扑。
6. **输出** `src/viz/geo/tz/tz-{10m,50m,110m}.json`（TopoJSON）：
   - `transform` 与同档 `basemap-*.json` 的 `transform` **逐位相同**。别让 `topojson-server` 按包围盒自定：海面到 ±90°，包围盒与底图不同。先在底图网格上量化，再自己写 delta 编码，或者用等价办法。
   - `objects.faces`：每个面的属性 `{k:'land'|'sea'|'water', u?, ds?, z?, zt?, z0?, off?, a:[lon,lat,rDeg]}`。
   - 自定字段 `adj`：弧号 → [面号, 面号]，照底图 `adj` 的形状。
   - `meta`：源版本、sha256、生成日期、档位。
7. **规则表** `src/viz/geo/tz/tzRules.json`：
   - 收全部被引用的时区号，包括 `Asia/Shanghai`、`Asia/Macau`、各主时区、南极与海区用不到的不必收。
   - 解析 TZif v2+：显式跃迁，加上脚注 POSIX TZ 串展开到 2100 年。tzdata 包可能是 slim 格式，脚注展开必须实现。
   - 每段记 `utoff`（分钟）与 `dst`（分钟，**rearguard 正值语义**）。main 格式里负夏令时的几个时区，爱尔兰、摩洛哥 / 西撒 2018–2026、纳米比亚 1994–2017，翻成「偏移大的那段是夏令时」。
   - 1970 年以前不收；2100 年以后取最后状态。
8. **构建期自检**，不过就让脚本失败：
   - 陆地面并集面积与底图陆地面积相对差 < 1e-6。
   - 任意两面不重叠，无缝。
   - 每块陆地面在所有候选归属下都解得出时区。
   - 归属 CHN 的面在所有视角下都不是 `Asia/Urumqi`。
   - 与底图国界重合的弧逐点相等。
   - 三档体积预算：10m ≤ 5 MB，50m ≤ 1.5 MB，110m ≤ 0.35 MB，规则表 ≤ 300 KB；超了先查抽稀与量化。

## 4 运行时模块（全部纯 JS、Node 可单测）

### 4.1 `src/viz/geo/tzRules.js`
- `loadRules()`：动态 import 规则表。**不许带 `with { type: 'json' }`**：dev 期会被浏览器拒掉，50m / 110m 底图踩过。Node 测试里用 `fs` 读后注入。
- `offsetAt(zoneIdx, ms)` → `{ off, dst }`（分钟）。
- `stdAt(zoneIdx, ms)` = `off − dst`。
- `nextChange(zoneIdxs, ms)`：给出下一次任一区偏移变化的时刻。偏移不变时每拍零开销，用它就能做到。

### 4.2 `src/viz/geo/tzLayer.js`（与渲染器无关的核心）
- 按档懒加载拓扑（同样不带导入属性）。
- `resolve(detail)`：按当前视角求每面时区号。订阅 `onPovChange`，视角一变就重解。
- `setTime(ms, mode)`：算各面当前偏移。签名没变就直接返回。
- 产出给渲染器的数据：
  - `fills`：按偏移分组的面（经纬环），含半点区斜纹信息与描亮标记；
  - `lines`：`{ tz, idl, hi }` 三类经纬折线，由弧按 §2.5 选出；
  - `labels`：连通区锚点、两行文字、优先级、是否描亮；
  - `ruler`：每条航海带的中央经线与两行文字；
  - 版本号：几何版本 `geomVer`、文字版本 `textVer`，渲染器按它们决定重建什么。
- `readAt(lat, lon)`：光标读数。用 1° 格网桶 + 点在多边形判。
- 「描亮」用的目标偏移由宿主传进来（`tzOffMin(tzMode, t)`）。

### 4.3 `src/viz/env/useTzLayer.js`（Vue 组合式，仿 `useEnvField.js` 的结构）
- 状态、记忆（§2.10）、开关。
- 宿主回调 `draw(spec)` / `setTime(...)`。
- 宿主在 `refreshPositions()` 里每拍调 `tz.tick(clock.tMs)`。

### 4.4 宿主接线（`ConstellationMap3D.vue`）
- 实例化后接上：时钟、显示时区（`tzMode`）、视角广播、底图档切换（`setMapDetail`、2D 拖着转时降 110m 的 `rotLive` / 背板 `liteBake`，都要跟）、光标读数（`onHoverLL` 里 `cursor.tz = …`）、销毁。
- 2D 平面图是懒创建的：`feedFlat()` 里要补推一次时区层，否则从 3D 切过去是空的。环境场踩过这个坑。

## 5 渲染

### 5.1 2D（`src/viz/flatmap/flatCoverage.js`）
- 新 API，例如 `setTzLayer(spec)`。具体名字自定，与 `setEnvRaster` / `setEnvContours` 同风格。
- 色块进静态层。静态层、背板、几何缓存的键都要带 `geomVer` 与平面键（`planeKey()`），换投影、换切口、换视角、换档、偏移变化时作废。
- 界线走 GPU 线那条路：仿底图五类线（`createLinePacker` / `ensureBaseSet`，见 `glBaseLines.js` / `glLines.js`），新开 `tz` / `idl` / `hi` 三类。
- 标注与顶部标尺走文字 / 动态层，不进静态层。
- 投影档：
  - 经纬环走 `PJ.path`；环的绕向按 `orientRings` 那套纠正。d3 按球面判内外，绕向反了会填补集。
  - 等距圆柱档按 `LON0` 切口解缠，跨切口的面别被撕开。可参照陆地填色与晨昏夜区的处理。
- **导出**：`exportRender` 的层序独立于 `draw()`，两处都要加。矢量 PDF 走 svgcanvas 兼容模式，它**不认 Path2D 入参，也不认 `globalAlpha`**：
  - 兼容分支一律从点数组 `moveTo` / `lineTo` 现画；
  - 透明度写进 rgba；
  - 斜纹退成实色。
  - `packages/core/test/flatExportCompat.test.mjs` 会查「递 Path2D 的 fill / stroke / clip 所在函数必须有 `if (compat)`」。

### 5.2 3D（`src/viz/globe3d/scene.js`）
- **色块**：一张索引网格。用 earcut 三角化，每条边细分到 ≤ 2°，再投到球面；可参照 `buildLandMesh` 与覆盖填充的细分。
  - 半径与细分**成对算**：弦下垂之后，网格最低点仍须高于陆地网格（1.0），否则会与陆地互相穿插出摩尔纹，晨昏线首版就是这么翻车的。建议 r = 1.0003。
  - 逐顶点色。偏移变化只改色属性，不重建网格。
  - `renderOrder` 紧跟环境场（4.5）之后；`depthWrite: false`、`FrontSide`。
  - 斜纹用屏幕空间着色器。
- **界线**：沿用平台的 `fatSegments`（LineSegments2）。压在底图国界之上（国界约 r 1.0005，时区线取 1.0006 左右），按类分批。
- **标注**：精灵。纹理关 mipmap（`generateMipmaps = false; minFilter = LinearFilter`），否则会糊。套边色是烘进纹理的，底图明度换档时整组重烘。时间文字按 §2.6 合图集。
- `clear` / `destroy` 里把几何、材质、纹理全部 `dispose`。切页重挂载会漏，环境场与晨昏线都踩过。

### 5.3 样式数值（缺省，可在面板改）
见 §2.7 与 §2.10。颜色语言：地物线是无彩 / 暖褐，数据是彩色，时区线用橙红系，与国界的暖褐、海岸的冷蓝一眼分得开。

## 6 界面（「环境场」视图末尾的「时区」分区）

照现有侧栏分区写法：
- 分区头：`<div class="sect acc" data-sec="env-tz">`，行首放 `chevron-down` 转动箭头。

参数行，从上到下：
1. `[✓] 夏令时`
2. `[✓] 标注`，同行 `[ ] 粗体`；下面一个从属行 `[✓] 当地时刻`（`.srow.sub` / `.chk2` 体例）。

4. `[✓] 描亮显示时区`

6. 「界线」：颜色框、自动、线宽。
7. 「日界线」：颜色框、自动、线宽。

其他要求：
- 各项口径只写进 `title`，面板上不出解释文字。
- 标签列用 `.srow` 契约（标签宽是下限、整行可换行），中英文都不许截断。

- 分区折叠状态走 `isSecOpen` / `toggleSec`。
- 新分区要进标题栏命令搜索：`data-sec` 打好，跑 `node scripts/cmd-index.mjs` 重生成索引；能顺手登记一条「显示 / 隐藏时区」命令更好（`src/stores/commands.js`）。
- 中英文词条补齐；`npm run i18n:scan` 两关都过。
