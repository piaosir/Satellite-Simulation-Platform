## 4. 太阳亮温模型 v5.3

### 4.1 现状与问题

v5.1 的模型：`T_b(2.8 GHz) = F10.7·λ²/(2k·Ω_d)`（瑞利-金斯，Ω_d 取当日光学盘立体角），再按 `T_b(f) = 6000 + (T_b(2.8) − 6000)·(2.8/f)^1.8` 外推；F10.7 恒取 120。两处不准：

- 谱指数 1.8 对 3–40 GHz 太陡：与野边山逐日实测比（F10.7 = 120），3.75 GHz 偏高 9%，Ku 12.5 GHz 偏低 19%，17 GHz 偏低 19%，Ka 19.45 GHz 偏低 23%，Q 40 GHz 偏低 27%（附录 A 表 2）；
- F10.7 恒 120 与真实太阳活动无关：2026 秋分附近实际约 105–130，2019–2020 谷底约 70，2024 峰年常在 200 以上 —— 同一副天线在谷底与峰年的峰值恶化差 2 dB 量级。

### 4.2 数据与拟合（本任务书作者已做，Opus 不必重做，只需照系数实现；脚本与原始数据见附录 A 末尾）

- **野边山射电偏振计 NoRP 逐日总流量**（国立天文台野边山太阳射电观测所，1 / 2 / 3.75 / 9.4 / 17 GHz，单位 sfu = 1e-22 W·m⁻²·Hz⁻¹，`ftp://solar-pub.nao.ac.jp/pub/nsro/norp/data/daily/nbymYYMM`）2004-10 → 2026-07，与
- **DRAO Penticton F10.7 逐日观测值**（加拿大自然资源部空间天气，`https://www.spaceweather.gc.ca/solar_flux_data/daily_flux_values/fluxtable.txt`，`fluxobsflux` 列，取 20 UT 那次）

按日期配对（7 325 天），逐频作稳健线性回归 `S_f = a_f + b_f·F10.7`（3σ 剔野点，迭代 5 轮）。终值见附录 A 表 1。判据：3.75 GHz R² 0.988、9.4 GHz 0.927、17 GHz 0.611（17 GHz 动态范围只有 ±5%，R² 低是量程小不是拟合差，残差 σ ≈ 2%）；月均回归（242 个月）给出同一组斜率，线性够用（二次项系数 ≈ −1e-3，F = 200 处与线性只差 2–4 sfu）。

**交叉验证**：用这套系数在锚点间 log-log 插值，预测 NOAA RSTN 四个独立台站（Learmonth / San Vito / Palehua）2026-09-15 起 7 天的 4995 / 8800 / 15400 MHz 正午流量，偏差见附录 A 表 3（作者算得均在 ±5% 内）。

### 4.3 模型定义（引擎实现照此）

```
// 锚点：S_f(F) = a_f + b_f·F，F = F10.7 观测值（sfu）。2.8 GHz 是 F10.7 自身，恒等锚点。
SOLAR_ANCHORS = [
  { f: 1.0,  a: -1.979,  b: 0.70334 },
  { f: 2.0,  a: -10.643, b: 0.94073 },
  { f: 2.8,  a: 0,       b: 1       },
  { f: 3.75, a: 17.318,  b: 0.88345 },
  { f: 9.4,  a: 210.379, b: 0.68094 },
  { f: 17.0, a: 592.284, b: 0.45292 }
]                                  // 附录 A 表 1 的终值，别改（出处 docs/research/solar-flux-fit/）
F_QUIET = 67                       // 静日 F10.7（太阳周谷底典型值）
// 17 GHz 以上没有逐日数据：静日谱用 NoRP 自己的绝对标定常量锚定 —— 35 GHz 2400 sfu、80 GHz 9000 sfu
// （NoRP 手册 man_v04e §2：35 / 80 GHz 的流量刻度即固定为这两个静日值），换算成光学盘亮温 9 380 K / 6 730 K，
// 与文献静太阳 8 mm ≈ 8 500–9 500 K、3.7 mm ≈ 6 500–7 500 K 相符；80 GHz 以上按光球层 floor 6 000 K 收敛。
// 活动增量在 17 GHz 以上按【流量恒定】ΔS = b17·(F − F_QUIET)（活动区自由-自由辐射平谱；回旋共振分量 20 GHz 以上消失），
// 换成亮温即 ∝ f⁻²，35 GHz 处峰年也只有 +2.6%。
S_Q_HIGH = [ { f: 17, s: 592.284 + 0.45292·67 = 622.63 }, { f: 35, s: 2400 }, { f: 80, s: 9000 } ]

solarFluxAt(fGHz, F):
  if f ≤ 17:  在 SOLAR_ANCHORS 相邻两锚点之间按 log S – log f 线性插值（S 取各锚点的 a + b·F）；f < 1 取 1 GHz 锚点值
  else:       S_q(f) = f ≤ 80 ? S_Q_HIGH 上 log-log 插值 : 由 T_q(f) = 6000 + (6730 − 6000)·(80/f) 反算流量（S = T·2kΩ₀/λ²，Ω₀ 为 1 AU 光学盘）
              return S_q(f) + 0.45292·(F − F_QUIET)

solarTempAt(fGHz, F, sunDiamDeg) = solarFluxAt(fGHz, F) · 1e-22 · λ² / (2k · Ω_d)，Ω_d = π/4·(sunDiamDeg·π/180)²
```

- Ω_d 仍取**当日**光学盘（`0.26656 / R` 的视半径，与现引擎同），S 是「地球处观测流量」，两者随日地距离同比变化 —— 口径自洽，不做 1 AU 归算。
- 与 v5.1 相同，用户 / SLA 显式传 `solarTemp` 仍直接覆盖（`solarTempSource: 'manual'`）。
- 旧模型整套保留为 `solarModel: 'legacy'`（原 `solarTempAt` 改名 `solarTempLegacy`，不改一个数字），缺省 `'norp'`。金标准用例、以及任何要「与改前逐位一致」的场合传 `'legacy'`。

### 5.3 取值规则 `f107For(equinoxIso, { windowDays: 20 })`

目标日 = 该季分点日（引擎已算，`equinoxDate`；IPC 层用 `core.equinoxDateOf(year, season)` —— 引擎把 `equinoxJDE` 的日期版导出一个小函数，别在 IPC 层再抄一份分点公式）。窗口 = [目标日 − 20 天, 目标日 + 20 天]（日凌事件就落在分点前后两三周）。按优先级：

1. **逐日**：把 `daily30` 与 `forecast45` 合成一条日序列（同一天两者都有取观测）；窗口内 ≥ 10 天有值 → 取均值，`source = 'daily'`（全是观测）/ `'forecast45'`（含预报），`at` 写窗口起止；
2. **观测月均**：目标月在 `monthly` 里且 > 0 → 该值，`source = 'monthly'`，`at = 'YYYY-MM'`；
3. **预测月均**：目标日落在 `predicted` 覆盖范围内 → 相邻两个月中点之间按日期线性插值，`source = 'predicted'`，带 `low / high`；
4. **预测末值外推**：目标日在最后一个预测月之后 5 年内 → 最后一个月的值，`source = 'predicted-tail'`；
5. **缺省** 120，`source = 'default'`（本机连内置快照都没有，或目标日早于 1947）。

规则纯函数化（`packages/core/utils/solarFluxPick.js`，输入合并数据 + 日期，输出取值），主进程只负责 I/O —— 测试才钉得住。

### 5.4 IPC 接线（`register.js`）

- `sunoutage:compute` / `sunoutage:computeBatch`：每项 spec 若无 `f107`，按其 `year` 与 `season`（批量里逐季）用 `solarFlux.f107For(...)` 填 `f107` 与 `f107Meta`；`solarFlux.snapshot()` 同步取数，不等网络。计算完顺手触发一次 `solarFlux.refresh()`（不 await，一天一次闸门自己管）。
- 新增 `sunoutage:solarFlux`（`status()` + 触发 `refresh()`）与 `sunoutage:solarFluxRefresh`（`refresh({ force: true })`）；preload `api.sunOutage.solarFlux / solarFluxRefresh`。两条都是只读查询 / 后台刷新，进 `UNGATED`。
- SLA 那条链路（GSO 窗口 `slaSunSpec` → `computeBatch`）不传 `f107` → 自动按日期取，**入参不用改**；它的日凌分钟数会随之变化，`lbSla.test.mjs` 那两个数（29.98 / 32.07）改成新模型算出的值（保留 ±1 的容差），并在断言名里写明「v5.3 模型 · 测试环境无 F10.7 数据时按 120」—— 测试里 register.js 没装 solarFlux（`sunOutageIpc.test.mjs` 假 electron）时引擎缺省 120；`lbSla.test.mjs` 直接调引擎，也是 120。
