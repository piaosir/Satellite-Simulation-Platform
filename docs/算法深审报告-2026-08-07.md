## 二、三专项定论

### 2.1 瀑布上/下行干扰损失 —— 合理，代数严格成立

- **上行桥接恒等**：stationEIRP 由功放反推沿链回扣后 EIRP/雨衰/带宽项精确对消，upThermal−uplinkCN ≡ uplinkCT−uplinkTotalCT，实测瀑布行与真值差 ≤0.0055 dB（纯 toFixed(2) 量化）。
- **下行干扰损失新口径**（v1.3.12/v3.8.9）：上行主导 = downlinkCT−downlinkTotalCT，下行主导 = (downlinkCT−rain−gtDeg)−rainDownlinkTotalCT，实测差 ≤0.0052 dB。**「干扰 C/T 不随雨变」在引擎构造中为真**——ACI/ASI/IM 的 C/T 无雨项；xpol 含雨致 XPD 但同一值出现在晴/雨两个并联分母中、在差式中对消（单工作点口径，刻意设计）。
- **级联闭合**：GEO/NGSO 全部检查点与引擎权威值差 0.00~0.01 dB；合成 ⊕ 差 ≤0.005 dB。小程序侧上行主导分支闭合到 1e-15，下行主导恒为 0（旧残差被精确分解为「四路并联代价 + UPC 未补偿上行残余雨衰」两笔）。
- **两仓对拍**：补齐默认值差异后 GEO/NGSO × 上/下行主导四种组合的干扰损失、干扰 C/I、下行 C/N 全部 Δ=0.000。
- 残余雨衰行 0.05 dB 门槛、旧存档回退等均为注释明示的刻意取舍，行为验证与设计一致。

### 2.2 NGSO C/I —— 核心准确

- 独立重写实现（独立 ECEF/S.1428/S.1528/cells 指向）对拍：C/I 最大偏差 **1.7e-6~3.6e-6 dB**（Float32 存储舍入），与历史基线同级。
- 几何手算复核全对（天顶/斜视/GEO 拓扑角到 1e-13 量级）；统计链方向全对（分位方向、+∞ 样本入池、bootstrap 历元块重采样、多历元合并 bit-exact）；雨衰卷积量化界与出参口径一致。
- 但存在 2 条确认问题（见第四节 #1、#2）。

### 2.3 PFD mask —— 常规出包可信

- 247/247 断言全绿；六个历史坑（α₀ 归属、哨兵两档、§B5.3 单调化、分离角版本二义、ES 禁用 S.1428、星间聚合逐角度）全部确认未回退。

### 3.2 链路代数链（非传播段）

晴天干净链路从斜距→FSL→天线增益→G/T→C/T→C/N 全程手算与引擎一致到 <0.01 dB；上行⊕下行=carrierTotalCN 闭合 <1e-4 dB。SFD 折算符号方向正确（G/T 正确消去）；噪声带宽=符号率与占用带宽=1.2×Rs 未混用；Es/N0↔Eb/N0 换算 Δ=0；MODCOD 抽查与 EN 302 307-1/-2 一致；玻尔兹曼/FSL/天线增益常数全对。功带平衡算术自洽（PFDc 与级联 arrivalPFD 晴天严格相等）。上行主导雨场景 0.68 dB 正推缺口逐项追溯确认完全来自已锁定不改的 UPPOWER/DOWNPOWER 包络设计。

## 五、驳倒项与重要澄清（不进清单，但值得知道）

1. **云衰封顶 1% vs 式(67) 的 5%**：条文与量级（Ka 0.34~0.49 dB 保守偏置）均核实为真，但此项是 2026-07-23 用户明确裁决保留的口径（「云衰1%封顶…不是问题勿再提」），按已判定项驳回。
2. **p840_logn_v1.bin 被质疑为「拟合残差地图」——不实，反而是好消息**：验证员下载官方 P.840-9 PDF 与 CG-3M ValEx 工作簿证明，该 bin 是官方 §3.3 年度对数正态参数地图（mL/sL/pL）的忠实重打包（8 官方节点逐点吻合、官方验证列复现到 5~6 位有效数字）；所测「偏差」是同一建议书内官方 §3.2（主推）与 §3.3（近似法）两法之差（≤0.045 dB），属方法选型取舍（3 张图 6MB vs 逐 p 档数十 MB）。
3. **XPD θ>60° 钳位**：ITU ValEx 对 85.8° 超域直算而平台钳 60°（差最大 33 dB）——但 §4.1 对 θ>60° 本无定义，钳位带显式注释、方向严格保守（总 C/N 影响 <0.5 dB），属工程取舍非算错。若在意低纬高仰角站的 XPD 行读数，可考虑跟 ValEx 口径直算，需用户裁决。
4. **P.676 混搭近似湿热偏差 +12~15%**：已判定的数据工程遗留（「γ 升级逐线法」在既往清单），方向保守；唯注释「常用 4~50 GHz <5%」分句只对干燥标准大气成立，湿热 Ka 实测 +0.43 dB@30GHz/10°。若要收敛：γ 地面单点逐线求和（44+35 条谱线）性能可忽略。
5. **NGSO+ISL 瀑布残差失配（0.86 dB）**：代数与量级属实，但平台 NGSO 窗自诞生即无 ISL 输入（schema 白名单丢弃 islHops），再生式走独立 buildRegen——属 UI 不可达的休眠死代码，同 §1.4 一类。若未来给 NGSO 窗恢复 ISL 输入，此项与 findIndex 行序失配（'up·上行 C/N' 改名后永不命中）需一并处理。
6. 其余驳倒项：0.05dB 残余行门槛（两仓注释明示的刻意取舍）、eirp_ss 40kHz 落盘（有红色告警且方向实为偏高/保守，非发现声称的偏低）、useMaskWorkbench 忽略 patternSource（死代码）、邻星离轴两仓分歧（双重小众输入+只读参考行+有文档设计依据）、天线噪温自动模式固化（声称的可用度触发链不存在，实测 Δ=0）。

## 九、修复记录（2026-08-08）

清单 #1 / #2 / #3 已修复，未改任何未列入清单的行为。

### #1 自系统排除改按卫星身份（packages/core/utils/interference/ciNgso.js）

新增 `satIdentity()`：以 satrec 的六根数 + 历元作身份指纹，与 `id` 取并集。同一颗星在「本星座」与「勾了同星座的干扰座」里是解析层各解一遍的两个对象（引用不等），但两次都由同一份根数建 satrec，指纹 bit 级相同；`id` 单独并进来是因为 walker 源的 id 带组名（两组组名不同），而编目源的 id 才是 NORAD 号——两者取并集，各来源都对得上。

扫描开始时一次性建 `wantedIdent` 表，对每个 selfSystem 组算出 `selfIdx[i]`（= 它是本星座的第几颗，-1 为不是）；热循环里 `selfIdx[i] === bestI` 即跳过，与浮点无关，且比原判据更省（连 SGP4 传播都免了）。一颗都对不上时如实告警，不假装排除成功。

验证：24/4 Walker、6 h/10 s，本座与自系统座 id 前缀故意设成不同（`M…` vs `X…`），全靠根数指纹识别。修复后 worst C/I = 56.99 dB、全部分位无一坍到 ≈0；对照组（不勾 selfSystem）worst = 14.99 dB，恰等于期望载波与干扰的 EIRP 密度差（−33.01 −(−48)），即「服务星满增益入和」的特征值。

### #2 干扰星座粗筛改用 0° 地平线（同文件 :276）

`orbitCanReach(s.rec, st.lat, minElev)` → `orbitCanReach(s.rec, st.lat, 0)`。粗筛只是性能优化，语义必须与主循环一致（`buildScreen(g.sats, 0)` 与 `up·LOS>0` 一直是 0°）。干扰从旁瓣打进来，与本站愿不愿意在这个仰角上工作无关。

验证：γ(0)=32.69°、γ(5)=28.02°，带宽 4.66°；站纬 60.35°N 处两口径判定恰好相反（旧 false / 新 true）。修复后该站有干扰样本 244/589、worst C/I 61.74 dB，且不再谎报「轨道无法覆盖本站纬度」。

### #3 4~6 GHz 雨致 XPD 按 6 GHz 重算雨衰（两仓 5 处定义 + 9 处调用）

`calculateRainXPD_P618_14` 增加第 6 参 `rainCtx`（{R001, pol, lat, lon, orbitPos, altitude, elevOverride}，字段与 `calculateSinglePathRainAttenuation` 一一对应）；新增 `rainAttenAt6GHz()` 在 f<6 分支按 6 GHz 重查 P.838 并经公式(8) 标到同一时间百分比。缺上下文时**显式抛错**而非退回旧路径——静默高报 16~17 dB 比报错危险得多。f≥6 GHz 完全不碰 `rainCtx`，Ku/Ka 调用方零影响。

未采用 §2.4.1 的长期雨衰频率标度式兜底：该式适用域自 7 GHz 起，4→6 GHz 它给 ×2.2 而 P.838 实际比衰减是 ×6.1，兜不住。

改动点：平台 `linkCalculator.js`、`linkCalculatorNGSO.js`、`rainAttenuation.js`（雨衰计算器页）；小程序 `linkCalculator.js`、`linkCalculatorNGSO.js`。

验证：广州 R=80 mm/h、p=0.1%、圆极化——4.0 GHz 修复前后差 **17.13 dB**（与审计复算逐位吻合），4.2 GHz 差 14.63、5.0 GHz 差 6.28、5.925 GHz 差 0.42（越靠近 6 GHz 越收敛，物理自洽）；6 GHz 接缝连续 0.0027 dB；f≥6 带/不带 ctx 逐位相同。两仓镜像：2304 点对拍平台与小程序 GEO 逐位一致，小程序 NGSO 在不注入 elevOverride 时同样 0.000e+0 偏差。引擎级 C 频段链路下行 XPD 36.33 dB（修复前约 53），总 C/N 与余量不受影响。
