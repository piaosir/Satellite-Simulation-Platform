# 高级计算 · 仪器级改造（NGSO 删除 · CnC 物理约束 · VSAT 组网语义）

> 2026-09-05 由 Fable 5.1 按代码现状、真引擎探针与厂家资料拟定；2026-09-06 由 Opus 5 分四期落地。
> 本文是该次改造的设计依据与落地记录。**代码里的口径以代码注释为准**，本文记的是「为什么这么定」。

---

## 1 目标

1. **NGSO 窗口删掉「高级计算」**（按钮、对话框、advRows/applyAdvPlan 整块）——它是 GEO 转发器账本上的功能，NGSO 不成立（§2.5）。
2. **CnC 载波叠加从「纯功率账」改成带物理约束的模型**（§3）：双工配对校验、频率包含与符号率比校验、PSD 比窗口（按调制）、雨衰对 PSD 比的耦合（含 UPC / CnC-APC）、残余自干扰 C/I 并入载波 C/(N+I)、CnC 可用度；非对称（两份不同载波）放开。
3. **VSAT 组网平衡补齐组网语义**（§4.3–4.4）：载波路数、功放可行性闭式读数、配平目标可指定租用带宽、多载波回退一致性告警、全表占用读数。
4. **引擎新增一个通用入参「附加 C/I」**（载波带内附加干扰，留空 no-op），级联 / 出参 / 报表 / 自定义列跟上（§4.2）。

### 2.2 引擎口径：闭式解为什么成立（`linkCalculator.js`）

- 679 `carrierTotalCT = carrierThreshold + margin`；780 `transponderCapacity = totalCTRain − carrierTotalCT`；786 `uplinkPowerRatio = 10^(−transponderCapacity/10)·100`；817 `downlinkPowerRatio` 同构；829 `powerUsageRatio = max(两者)`；830 `PowerBW = powerUsageRatio · B_tp · 10`（kHz）。
  ⇒ **余量抬 x dB ⇔ 功率带宽恰好 ×10^(x/10)**，载波带宽（410）只由速率 / 调制 / 滚降定。`advBalance.test.mjs` ① 段钉死。
- 845 `UPPOWER` 含 `−transponderCapacity`、863 `DOWNPOWER` 含 `+carrierTotalCT`，两者都随余量 1:1 平移；选哪个（868 `uplinkPowerRatio > downlinkPowerRatio`）不随余量翻转（两比同乘一个因子）。⇒ **功放功率（dBW）也随余量 1:1 平移**，`paRecommendation`（1324）可以闭式预测：P_after(dBW) = P_before + (配平余量 − 当前余量)。本任务用它做功放可行性读数（§4.4），并补一条标度律测试。
- 功率占用是**晴空分配量**：`uplinkPowerRatio` = 令上行残余雨衰（765，UPC 之后）下仍达 `carrierTotalCT` 所需的晴空份额，`downlinkPowerRatio` = 令下行雨衰 + G/T 劣化下仍达标的份额。逐链路取 max 再求和，就是「每条链路各自扛住自己那场雨」的晴空转发器资源，**不是「全站同时下雨」**——这一点无需改。
- 干扰入引擎的构造（696–720）：C/T_I = C/I + 10lg(k·B_tp)，即「按转发器总功率、平铺在转发器带宽上的干扰 PSD」；载波实际 C/I = 名义 C/I + 10lg(功率占用 / 带宽占用)。**CnC 残余自干扰是本载波带内的、按本载波功率定义的 C/I，不能塞进这套并联**——见 §4.2 的注入方式。

### 2.3 CnC 现状 = 纯功率账（用户问的「C/I 可用性 / 使用限制」一项都没有）

现有 `mode === 'cnc'` 只做两件事：`validateAdv` 要求恰好 2 条链路且 **同一份载波配置**（63–66）；`solveAdv` 把带宽只算一份（118 `occBwKHz = max`）、功率两条相加后配平（P₁ + P₂ = B）。缺：

1. **双工配对校验**：不检查 link1 的发站 = link2 的收站且 link1 的收站 = link2 的发站。Hub→A 与 Hub→B 两条同载波链路也能过校验——物理上 CnC 要求各站抵消**自己发出的**载波，这不是一对双工。
2. **非对称载波**：同载波配置 ⇒ 同速率同调制。真实 CnC 多数是非对称（前向大、返向小，小载波完整落在大载波频带内）——现在做不了。
3. **残余自干扰 C/I**：抵消不是无限深。收端 X 的 C/I_res = D − ρ_X（D = 抵消深度，ρ_X = 自身回波 PSD / 期望载波 PSD）。真引擎探针（`hub 9 m ↔ 远端 1.8 m`，同一份 20 Mbps 16APSK 3/4 载波，余量各 3 dB，Ku，可用度 99.9%）：

   | 量 | 值 |
   |---|---|
   | 功率占用 hub→远端 / 远端→hub | 167.75 % / 63.93 % |
   | 晴空 PSD 比（hub 载波 / 远端载波） | 4.19 dB |
   | 目标 C/N（两向） | 15.92 dB |
   | hub 收端 C/I_res @ D = 25 / 28 / 30 dB | 20.8 / 23.8 / 25.8 dB |
   | 对应 C/N 退化 | 1.70 / 0.77 / 0.47 dB |
   | 远端收端 C/I_res @ D = 28 dB | 32.2 dB → 0.10 dB |

   再加厂家给的固有处理损耗（16-QAM 在 PSD 比 0 dB 时 0.6 dB，§3.1），**hub 侧漏算 1.1～2.3 dB**——比很多链路的整个系统余量还大。
4. **PSD 比窗口**：厂家规定收端两载波 PSD 比只能落在一个窗内（BPSK/QPSK/8PSK/8-QAM：−7～+11 dB；16-QAM：±7 dB，§3.1）。现在既不算 ρ 也不查窗。
5. **雨衰耦合（可用度）**：ρ 随上行雨衰漂——对端上行衰落 r_des 把 ρ_X 抬高 r_des，本端上行衰落 r_own 把它压低 r_own，下行雨衰两载波同衰、不改比值。探针里 hub 收端：4.19 + 2.83（远端上行雨衰 @99.9%）= **7.02 dB，正压在 16-QAM 的 +7 dB 窗沿**——C/N 余量还够，CnC 已经先掉线。残余 C/I 同样随之恶化（D − 7.02 而不是 D − 4.19）。这就是「CnC 的 C/I 可用性」：**可用度由 C/N 余量与 PSD 窗口两道门共同决定**，现在只有前一道。
6. **符号率比 / 最小符号率 / 频率包含 / 同转发器同极化**：一条都不查。同转发器在 GEO 窗由「场景级单颗卫星」天然满足；共频要靠行上的 `centerFrequency` / `rxCenterFrequency` / 极化四格比对。
7. **偏置对 CnC 恒被清零**（102、`showCarrierTab` 103）——同载波时确实无意义；放开非对称后两份载波两个未知数一个方程，偏置重新有意义。

### 2.4 VSAT 现状：算术无错，四个建模缺口

`solveAdv` 的闭式解与引擎逐位一致（②③⑥⑧ 段已验证），**没有算术错误**。缺的是组网语义：

1. **一行 = 一路连续载波**，没有「路数」。1 前向 + 20 返向要建 21 行；三条「返向 TDMA」行被当成三路 SCPC 各占各的带宽与功率——若用户本意是三个远端共用一路 TDMA 载波，带宽算了 3 倍、功率求了和（该取最差站）。
2. **应用后一律改成「设置余量」**，行原来的「设置功放功率」（BUC 受限）约束被吃掉，且没有任何功放可行性读数：解出的余量可能要远端开到 400 W。
3. **配平目标只能是 Σ载波带宽 × 10^(组超发/10)**，不能对着「租用 9 MHz」配（保护带、载波间隔留白都进不了账）。
4. **转发器工作点无校验**：卫星条目的 `BOo`/`BOi`（默认 3/6 dB）是单值，多载波组下若填的是单载波回退，Σ份额整体乐观 (OBO_mc − OBO_sc) dB；「转发器资源占用」读数只算本组，不含表里其余行。

### 2.5 NGSO 为什么不该有（删除依据 + 锚点）

- NGSO 每行结果是**各自最差几何时刻**的（1225–1291 逐候选取最差），不同行的最差时刻不同，Σ功率带宽不是任一时刻的物理状态；
- NGSO 容量不按「转发器功率等效带宽」售卖，功带平衡的账本前提不存在；
- CnC 需要稳定的回环路径（时延 0–330 ms 窗内慢变），NGSO 时延 / 多普勒连续变化且频繁切星，厂家 CnC 只面向 GEO；

CDM-Qx §9 算例（Table 9-2，可作回归夹具）：4.5 m vs 2.4 m，192 kbps，常规 274.6 kHz → CnC 166.4 kHz，功率 0.55 % / 0.16 % → 0.37 % / 0.11 %，CnC 比 +5.3 / −5.3 dB，Eb/N₀ 退化 −0.1 / 0.0 dB；雨衰 hub 上 6 / 下 4 dB、远端上 3 / 下 2 dB。（ρ 的符号约定由此算例核对：站 A 份额 0.37 % / 站 B 0.11 % → 10lg(0.37/0.11) = +5.27 dB 落在 A，即 **ρ = 本站自身载波 / 对端载波**，正值 = 自身更强。）

### 3.2 残余自干扰 C/I 与 C/N 退化

设两条链路 L₁（A→B，载波 1）、L₂（B→A，载波 2），份额 f_i（引擎 `powerUsageRatio`）、符号率 Rs_i、载波带宽 B_i。

- 收端 A 期望载波 2、自身回波是载波 1：ρ_A = 10lg(f₁/f₂) − 10lg(Rs₁/Rs₂)（PSD 比；同符号率时就是份额比）。收端 B 反号：ρ_B = −ρ_A。
- **残余 C/I**：C/I_res,X = D − ρ_X（在期望载波带内；自身载波比期望窄时，落入期望带内的残余只有一部分，公式同样成立——PSD 比已经归一到单位带宽）。
- **固有损耗折算**：deg₀(期望载波调制) 折成等效 C/I：C/I_eq = T − 10lg(1 − 10^(−deg₀/10))，T = 目标 C/(N+I) = `thresholdCN + 余量`（引擎 `carrierTotalCN`）。
- **并联**：C/I_X = −10lg(10^(−C/I_res/10) + 10^(−C/I_eq/10))。
- **退化**：Δ_X = −10lg(1 − 10^((T − C/I_X)/10))；C/I_X ≤ T 即不可解（残余比目标还大）。
- 设计点取**雨衰下**的 ρ（§3.3 的 ρ_max），不是晴空值——这才是「C/I 可用性」。

D 的反推：CDM-Qx 算例 QPSK 3/4 Turbo（T ≈ 6.3 dB C/N）在 ρ = +5.3 dB 处总退化 0.1 dB，扣掉 deg₀ 0.3 后残余项 ≈ 0 → D ≥ 28 dB 才压得到 0.05 dB 以内；取 28 作缺省，`title` 写明「按厂家算例反推，实测抵消深度请按设备填」。

### 3.3 PSD 比窗口与雨衰耦合

- 各站上行残余雨衰 r = max(0, A_up − UPC)（引擎出参 `uplinkRainAttenuation`、`UPCmarginResult`，各行自己的设计可用度）。
- 收端 X 的 ρ 区间：**ρ_min = ρ_clear − r_own，ρ_max = ρ_clear + r_des**（own = 本站上行衰落压低自身回波；des = 对端上行衰落压低期望载波）。下行雨衰两载波同衰，不进比值。
- 窗口 [W_lo, W_hi] 按**期望载波的调制**查 §3.1 表（可手填覆盖，留空 = 自动）。读数：ρ_clear / ρ_min / ρ_max 与 **窗口裕量** = min(ρ_min − W_lo, W_hi − ρ_max)，负值着色（`--danger`）。
- **CnC-APC = 开** 时 ρ 视为被保持：ρ_min = ρ_max = ρ_clear，C/I 取晴空值；总合成功率不变的约束不进本任务（§9-6）。
- 允许对端衰落 = W_hi − ρ_clear（dB），与对端设计雨衰 r_des 并列给出。

### 3.5 CnC 可用度

严口径：Unavailability = P(C/(N+I) < T) ∪ P(ρ ∉ 窗)。两事件同源（同一场雨），取**保守近似**：CnC 可用度 = min(L₁ 系统可用度, L₂ 系统可用度, PSD 窗口可用度_A, PSD 窗口可用度_B)。

PSD 窗口可用度_X：对「对端行」的 `uplinkAvailability` 做二分（引擎单调：可用度 ↑ ⇒ A_up ↑），求使 r_des(p) = W_hi − ρ_clear 的 p；A_up 已不足以触窗（r_des(99.999) < W_hi − ρ_clear）时记 ≥ 99.999。同法对 ρ_min 触 W_lo（本端行）。每侧 ≤ 14 次引擎调用，走现有 IPC 批量入口（`compute()` 里逐候选那条批量路径）。三期做，一二期先给「允许对端衰落 vs 设计雨衰」两个数。

### 11.2 偏离任务书之处（逐条有据）

| # | 任务书写的 | 实际做法 | 为什么 |
|---|---|---|---|
| 1 | `carrierExtDegResult` 进 `lbOutputDefs` 的**资源占用**组 | 进**链路质量**组 | 它挨着「上行 C/I / 下行 C/I」才是工程师找它的地方；资源占用组装的是带宽/功率占用 |
| 2 | `cncOpt` = `{cancelDb, ratioMax, minSymKsps, window, apc}` | 另加 **`deg0`** | 固有损耗也须做成参数；且没有它，⑫ 的「D = ∞ 退化为现状」测不出来——D 拉到 200 dB，deg₀ 那 0.3~0.6 dB 照旧在 |

### 11.3 两处诚实边界

**其一，CDM-Qx 算例的 CnC 比对不上量级。** 厂家算例（4.5 m ↔ 2.4 m、192 kbps）给 ±5.3 dB，本平台同款天线给 ±1.23 dB。**方向一致**——发往小站那条占更多转发器功率（算例 0.37 % / 0.11 %，本平台 0.188 % / 0.140 %）。量级差是因为算例的卫星 SFD / G·T / 两端功放这些决定功率劈分的参数手册没给全，拿本平台的缺省星去凑没有意义。故 ⑭ 只断言方向与反号，比值本身按本平台实测记在读数里。

**其二，厂家两份资料互相矛盾。** CDM-625A 数据表说 QPSK 在 PSD 比 0 dB 时固有处理损耗就有 **0.3 dB**，而 CDM-Qx §9 算例给的总退化是 **−0.1 / 0.0 dB** —— 总退化不可能小于固有损耗，两者不能同时成立。本平台按数据表建模（固有 + 抵消残余），故总退化必 ≥ 0.3 dB。可核的是**抵消残余那一项**：置 `deg₀ = 0` 单独看，D = 28 dB 下为 0.099 / 0.056 dB，正是反推 D = 28 的那个依据。

### 11.4 CnC 可用度的口径（§3.5 的落地）

严口径 `Unavailability = P(C/(N+I) < T) ∪ P(ρ ∉ 窗)`。两个事件同源（同一场雨落在同一条路径上），相关系数无从取，故取**保守近似**：

```
CnC 可用度 = min(L₁ 系统可用度, L₂ 系统可用度, 窗口可用度_P, 窗口可用度_Q)
```

并集的真值介于 `max(各项)` 与 `min(各项)` 之间，取 `min` 即取下界——工程上宁可低报。

窗口可用度靠**反解**：ρ 越窗发生在「对端上行衰落吃掉了 上沿 − ρ_clear」或「本端上行衰落吃掉了 ρ_clear − 下沿」的那一刻。把这个衰落量当目标，对那一行的**上行可用度**做二分——引擎在这条路上单调（可用度 ↑ ⇒ 上行雨衰 ↑，实测 `0.00 → 1.10 → 1.74 → 4.52 → 13.13 dB`），故必收敛。二分在**中断率的对数域**做：可用度 99.9 与 99.99 在线性域只差 0.09，对数域是整整一档。14 轮、每轮一次批量 IPC。

到 99.999 % 仍未触窗则记「≥ 99.999」而不外推——再往上没有雨衰模型数据支撑。晴空即已越窗（目标衰落量 ≤ 0）则记 0，不反解。
