## 1 判断

地基是对的：四级数据链路、`buildSsaModel` 单一真值源、屏上与 Word 同数、口径附录。问题在三层，按轻重：

1. **有数错**。第 6 章星座表、第 5/6 章「近 30 天」、第 8 章行名、卫星组的分布图，都有读者一眼能挑出来的错。
   交付文档先得数对 —— 这一层不修，后面加什么都白加。
2. **只有存量，没有变化与风险**。现在每章都是「此刻编目里有多少」，而 SSA 报告读者最先问的是
   「比上期多了什么、哪里在变挤、哪些要掉下来」。同时有一批重复或低信息的表与图在占篇幅。
3. **批处理式交互、与平台割裂**。设置 → 生成 → 看，改一项就亮「输入已变」；报告里的星点不到 3D 场景。

最佳实现 = 先把数做对，再把报告从「编目统计表」改成「态势报告」，最后让它变成平台里的一块活文档。

## 3 第二层：内容结构 —— 从「编目统计」到「态势报告」

### 3.1 加（按读者价值排）

1. **关键指标页（第 0 章，紧跟封面）**。8 个数 + 变化量，纯数字：在轨对象、活跃载荷、本年至今发射次数 / 入轨载荷
   （与去年同期并列，实测载荷 3,439 vs 3,218）、近 N 天发射次数 / 入轨载荷 / 陨落、GEO 带对象、星历覆盖率。
   变化量全部能从发射日 / 陨落日倒推，不需要历史快照。
2. **发射按「次」统计**。国际编号年份 + 序号去重即发射次数（2025 年 315 次）。
   近 N 天明细从 287 行载荷改成 24 行发射清单（日期 / 火箭体 / 发射场 / 入轨载荷数 / 所有者），Word 省约 14 页；
   载荷明细降为附录大表。
3. **碎片与解体事件（新章）**。碎片按母体（国际编号前缀）计数前 N 位（FY-1C 2,314、YUNHAI-3 613、千帆首发 574…）；
   近 N 天新编目碎片按母体归并（YAOGAN-50 02 一次 72 条）—— 这就是「近期解体事件」的纯数字表达，不做事件判定。
4. **LEO 空间密度剖面**。50 km 分层 × 对象类型的堆叠图，ESA 报告的招牌图，取代现在 0–2000 km 近地点直方图
   （同一份数据，信息量大一个量级）。
5. **GEO 保护区全量**。新增 CelesTrak `GPZ-PLUS` 组（走同一条四级链路，加一个组键），GEO 带对象按漂移率分档计数；
   第 7 章由此能对上第 3 章的数。**待拍板**（多一个数据集）。
6. **近地点低于 250 km 的在轨对象清单**（197 颗）。只列根数与历元，不做再入预报、不叫「再入候选」。

### 3.2 砍 / 合并

| 现状 | 处理 | 理由 |
|---|---|---|
| 第 8 章「星历时效」独立成章，直方图 98% 落在前两箱 | 并入第 1 章作数据质量读数（中位 / P90 / > 7 天颗数 / 覆盖率），直方图删 | 是数据质量，不是态势 |
| 第 2 章 kv 与堆叠图重复主表 | 删 kv 的重复项与堆叠图，第 2、3 章合并为「编目与区制」一张类型 × 区制主表 | 同一组数印三遍 |
| 所有者 / 星座排名条图 | 删 | 被 US、Starlink 压扁，其余条读不出；数都在表里 |
| 1° 经度桶前 N | 换 10° 段统计（36 行固定） | 前 N 桶并列截断、且不覆盖全带 |
| 重点弧段表代码列 + 名称列 | 二选一（留名称，代码进附录代码表） | 冗余 |
| 共位簇 92 行 | 只留 ≥ 3 颗（41 行） | 2 颗相邻在 0.2° 判据下大量是巧合 |
| 倾角 × 高度密度格 0–40,000 km 线性轴 | 对数高度轴；HEO 按近地点 / 远地点画而不按平均高度 | LEO 被压成 3 行，HEO 混进 GNSS 带 |

### 3.3 筛选感知

筛选维度上结构性为零或单值的块自动不出：所有者 = PRC 时不出单行所有者表与 1 根条的排名图；
区制 = GEO 时不出 5 行全零的区制表、全零的近地点图。规则写在 `buildSsaModel` 一处（块级 `skipWhen`），
第 1 章「筛选条件」里照常列出 —— 读者知道为什么这一章没了。全零图另补空态（`ssaChartSvg` 现只判了 bins 为空）。

## 4 第三层：交互 —— 活文档

1. **改设置即重出**，删「生成」按钮与「输入已变」。实测：解析 SATCAT 116 ms（之后走缓存）、全量建模 180 ms、
   筛 PRC 35 ms —— 主线程 300 ms 防抖直接重出，不必上 Worker。重出后按章锚点保住阅读位置。
   数据到达仍**不**自动换数（原口径不变：正读着的报告不该自己换一套数），状态栏的「报告 09:37 · 数据 10:12」改成可点的一键更新。
   导出前补算那条逻辑随之简化。
2. **报告 ↔ 平台联动**（通道已有：`api.scene.cmd`，见 `electron/services/sceneCmd.js`）：
   - 表里的卫星名 / NORAD 可点 → `focusSat` 在主窗口聚焦该星；
   - GEO 定点表 / 共位簇 → `faceLonLat` 画面正对该经度；
   - 近期发射 / 陨落清单 → `markTime` 打到主窗口时间轴。
3. **图表悬停读数**（柱 / 点的数值与分箱边界），点柱跳到对应表行。屏上专属，Word 不变。
4. **屏上抬头显示台标**，与 Word 页眉一致（抬头就地编辑本轮已做）。

## 6 可选：本机历史 → 「较上期变化」

发射 / 陨落日期能倒推的变化 §3.1 已经吃掉。倒推不出的是：状态变更（活跃 ↔ 非活跃）、GEO 定点漂移、老发射新编目的对象、所有者变更。
做法：每次取到新 SATCAT，本机存一份摘要（`ssaStats` 总览数字 + 每颗的状态 / 定点指纹，压缩后百 KB 级）到 userData，按日期留最近 N 份；
报告多一章「较上期变化」，上期可选。模块说明 §7 里的 COS 众包逐日摘要是它的二期，补上没开机那几天。**待拍板**。
