## 1 数值标签重复（对地 / 对星，2D 与 3D 同一条路）

**现象**：截图里 42 / 41 / 40 / 38 / 37 每档沿线印了十几遍（"4444444442"），35 / 36 只印一次。

**根因**（`src/viz/grd/coverage.js` `stitchLoops`，约 L1286）：拼环只从起始线段的 `s[1]` 端向前走，走到断头就停，从不回头去补 `s[0]` 那一侧；而起始段取「行主序第一条未用线段」，通常落在链的中段。于是：

- 闭合环没事：向前绕一圈回到起点。
- 开口链（被地平或热区盒切断的等值线；大波束的绝大多数档都是开口的）每次重新起头只吃掉一小截，一条链被剥成十几段；每段 ≥ 4 点就各得一个标签（`useGrdCoverage.js` L946 / `useShellCoverage.js` L299、L367 都是「一环一标签」）。
- 09-16 起线段是 P–M、M–Q 两段式，碎片更碎（起点落在 [P,M] 时下一步就撞上已用段）。

**证据**（`.covharness/cov_harness2.mjs`，用户库 `CS-6C…EIRP.grd`，GEO 130°E，12 档）：

| 档 | 度 1 端点数（= 开口链数 × 2） | 旧算法环数 / 标签数 | 修后链数 / 标签数 |
|---|---|---|---|
| 42.1 | 2 | 11 / 10 | 1 / 1 |
| 40.1 | 2 | 14 / 13 | 1 / 1 |
| 34.1 | 12（+3 闭合） | 36 / 31 | 9 / 9 |
| 44.1（闭合） | 0 | 1 / 1 | 1 / 1 |

碎片中位长度 5 点（= 2 个三角形）。300_X02G（11 波束，全闭合环）旧算法每档 1 环 1 标签，与「只有开口链才复现」一致。修后 12 档逐档满足：链数 = 闭合环数 + 端点数 / 2。

**修法**：`stitchLoops(segs)` 改为双向拼链：起始段先从 `s[1]` 向前走到断头或闭合；未闭合再从 `s[0]` 向后走，反转后前插。O(n) 不变，接口不变（仍返回 `[[lon,lat]...]` 数组），闭合环输出逐位不变（先走的那一圈与旧算法完全相同）。原型 `stitchChains` 在 `cov_harness2.mjs` 里，可直接搬。

受益的调用点（都不用改）：对地标签与拖拽捕获（`useGrdCoverage.js` L946）、对星壳层 / 对星 2D（`useShellCoverage.js` L299、L367）、GXT/KML 导出 `exportContours`（`useGrdCoverage.js` L1607，目前导出的等值线同样是碎的）。

**验证**：
- `packages/core/test/edgeRefine.test.mjs` ③ 里「拼环数一致」断言改为链数；新增：链数 == 闭合环数 + 度 1 端点数 / 2；无度 ≥ 3 结点时每条线段恰属一条链；闭合环坐标序列与旧实现逐位相同。
- 真 GRD 回归：把 harness 的 ① 段搬进测试（本机有文件才跑，与 edgeRefine.test ⑥ 同款）。
- 2D / 3D 各截一张图：一档一条链一个标签。

## 2 等值线平滑性 vs SatSoft

### 2.1 差在哪（分析结论）

- SatSoft 默认 Whittaker 插值密度 5：先把复场 FFT 零填充上采样 ×5（sinc 重建），再在 5 倍细网格上做线性 marching squares，所以每个原始格子里 ≥ 5 段折线。密度填 1 时与本平台完全一致（2026-08-22 用户实测）。
- 本平台（09-15/16 后）：线顶点全部落在 bicubic 复场插值的等值面上（线 = 表，|Δ| ≤ 1e-5 dB），但每格只有 P–M–Q 两段。用户库 0.05° / 0.1° 文件上 bicubic 与 sinc 的差 ≤ 0.01 dB（08-22 实测），所以差别不在插值核，在**折线的采样密度**：每格 2 段 vs 5 段。
- 折线看起来平不平滑取决于顶点处的**转角**（与缩放无关），不是偏离量。实测（网格域，`cov_harness2.mjs` ②）：

| 数据 | 转角 p50 / p95 / max | > 8° 顶点占比 | 弦中点矢高 p95 / max（格） |
|---|---|---|---|
| CS-6C 12 档（现行 P–M–Q） | 1.5° / 8.8° / 81° | 4.8% | 0.007 / 0.32 |
| 300_X02G 8 档（现行） | 1.3° / 6.9° / 56° | 3.8% | 0.006 / 0.16 |
| 不细化（旧路） | 2.6～5° / 14～24° | 13～33% | — |

峰附近 −1 ～ −3 dB 档最差（曲率半径只有几格）：p95 12～18°，> 8° 占 10～16%。这就是「放大后像多边形」的来源。

- 另一类锯齿是**尖刺**：个别弦中点沿法线求根跳到了等值线另一支（守门只限「±0.5 格内、在三角形内」），形成 81° / 56° 的尖角，特征是 M 两侧弦等长（0.457 / 0.457）。

### 2.2 终极方案：按曲率自适应插弧点（推荐）

在现有「弦中点」机制上推广：每条弦 P–Q 不是最多插 1 个 M，而是递归二分：中点法向求根得 M；若 ∠(P,M,Q) > θmax 或矢高 > ε，对 P–M、M–Q 继续，深度 ≤ 3（最多 7 点 / 弦）。

- 同一份 bicubic 插值求根（线 = 表不变），没有 Whittaker 的截断振铃，也没有 ×25 的点数。
- 曲率大的地方（小波束、峰附近、副瓣）自动加密，大波束的平直段不加点。
- 原型实测（同上两文件）：θmax = 3°、ε = 0.005 格、深度 3：顶点 +25～47%，转角 p95 8.8° → 4.6°、> 8° 占比 4.8% → 0.5%（300_X02G 降到 0%），残余矢高 max 0.013 格；约 13 万次 bicubic 求值，未优化原型 36 ms，一次性、随细化表缓存，拖拽 / 播放零代价。另一档 θmax = 4°、ε = 0.01、深度 2：顶点 +13～27%，> 8° 占 0.2～1.9%。

改动点：
1. `buildEdgeRefine`（`coverage.js` L746–920）弦中点段：记录改为「每 (格, 三角形, 档) 一段**有序**弧点」。现有 `mt / mk / mu / mv / ms` 保留，同一弦的弧点按 P → Q 顺序连续存放；`midOf(m0, m1, tri, k)` 改为返回区间 `[a, b)`。守门在原有基础上加两条：拒绝 ∠(P,M,Q) > 60°（尖刺）；新弧点须与同弦已有弧点在弦上投影单调（不回折）。
2. `projectRefine`（L937）：`mlon / mlat / mvis` 随记录数自然扩展，掠地格子逐点求交逻辑不变。
3. `bandGeometry`（L992）：
   - 线：`cnt === 2 && exact === 2` 分支输出 P, a1 … ak, Q 连段（拼链天然支持）。
   - 填充 `pushBand`：凹口一侧把全部弧点插进弦；扇心不能再默认取 M。做法：扇心取「离弦最远的多边形顶点」，校验以它为扇心的全部三角形同向（同向即该顶点在核内，扇形三角化合法），不满足回退耳切（多边形 n ≤ 3 + 档数 + 7，O(n²) 可忽略）。薄片一侧 = 以 P 为扇心沿弧的三角带，同样做同向校验。★ 3D `updateFill`（`scene.js` L2160 起）以每个多边形的 0 号顶点为扇心，凹口多边形必须旋转到扇心为 0 号（现有 `_fillPushFlatRot` 的做法）。
4. `glField.js buildMeshIndices`（L100–300）：同规则改 `midOf` / `sliver`（薄片三角带每个三角 3 个专属顶点，d 取带内值，理由见文件注释）、扇心校验 / 耳切；索引上界按记录数重算。
5. `limbEnd`、掠地精确位置那条路不动。

性能预算：一次性建表 HTS 94 波束 12 档目前 326 ms，允许到 ≤ 500 ms；每帧 bandGeometry 允许 +25%（顶点多 30～50%，但只在跨档三角形）；`autoStride` 的「一格 ≤ 2 px 不细化」口径不变。

**验证**：
- edgeRefine.test：全部弧点在表插值下 |Δ| ≤ 1e-4 dB；随机点 CPU 填充多边形不重叠、与 GPU 三角逐点同档（现有 ⑤ 扩展）；无 NaN 顶点；真 GRD 上转角 > 8° 占比 ≤ 1%。
- 金标准 `fixtures/bandGeometry.golden.json`（不细化路）逐位不变；`glFieldMesh.test.mjs` 62 项绿；`npm test` 全绿。
- 屏上：CS-6C 的 −1 / −2 / −3 dB 档放大到一格 ≥ 40 px，前后截图并排；3D 同一处。

### 2.3 不选的方案（写明理由，免得再议）
- Whittaker 密度选项：08-22 已定不加。用户文件边界电平 −4.5 … −11 dB，不满足手册要求的 −30 dB，FFT 上采样会振铃；点数 ×25。
- 显示层样条（Catmull-Rom / 贝塞尔）：只美化，不保证点在等值面上，线 ≠ 表，否。
- 提高自产网格密度（synth `cell=th/7`、repack `ptsPerBw=8`）：只对自产文件有效，厂家文件不受益。

### 2.4 顺带一条（需拍板）
`displayQuality` 的「低」画质档 `gridStride = 2`，而细化只在 stride === 1 时启用；用户若在「低」档，无论放大多少都是旧路的粗线。建议 `autoStride` 里「一格 ≥ 8 px」时无视 base 强制 stride 1（只影响线 / 填充密度，不改任何数值）。

### 2.5 二轮定位（2026-09-21）：把 SATSOFT 的算法复现出来逐档对比

`.covharness/cov_harness3.mjs`：按手册 §11.1 复现 SATSOFT 等值线（四个复场分量各自 FFT 零填充 ×5 的 Whittaker 重建 → RSS 功率 dB → 5 倍细网格线性 marching squares），与本平台线逐档比。三份真 GRD（CS-6C 单波束、300_X02G 首波束、CS26GT HTS 首波束，均 181²）。「锯齿」拆成三个互不相关的因素，各有数字：

**因素 A：折线密度 / 拐角（方案 2.2 解决）**

| 线 | 每格段数 | 转角 p95（中间档 −4～−10 dB） | 转角 p95（−1～−3 dB） | > 8° 顶点占比 |
|---|---|---|---|---|
| SATSOFT 密度 5 | 5 | 3.1～4.4° | 7～11° | 0.1～9.5% |
| 本平台现行 P–M–Q | ≈4.3 | 4.0～6.7° | 10～14° | 0.5～15% |
| 本平台自适应细分（3° / 0.005 格 / 深 3） | 5～13 | 3.3～4.9° | 4.3～5.2° | 0～1.9% |
| 旧路（不细化，stride 1） | 2 | 14～24° | 28～35° | 26～47% |

自适应细分后本平台线在每一档都比 SATSOFT 自己的折线更平滑（SATSOFT 在 −12 dB 以下与 −1 dB 档也有 9～20% 的 > 8° 拐点，是 sinc 重建的振铃）。

**因素 B：步长陈旧（最可能是屏上看到的锯齿，代价最小）**

`autoStride` 只在 `recompute / recomputeActive` 里经 `refreshView()` 取一次视口像素密度（useGrdCoverage.js L1054–1058、L1083）；2D `flat.setOnZoom` 与 3D `scene.setOnZoom`（ConstellationMap3D.vue L3950、L6880）只存视图不重算。缩小时定下的 stride 2～4，放大后仍是这份，直到某个设置改动才重算。且细化只在 stride === 1 启用。实测 stride 2 / 4 的线：转角 > 8° 占 34～84%、弦长 0.9～1.9 格（`cov_harness3` 「步长 2 / 4 全档」行）。另外两种同样关掉细化的状态：画质「低」（gridStride = 2）、路径损耗 ≠ none。
在真软件里核实：放大到一格 ≥ 20 px，再随手改一下线宽或透明度；若线当场变平滑即命中。
修法：缩放结束（onZoom 回调 / 3D 相机 change 结束）时比较 `autoStride` 新旧值，变了就 `scheduleRecompute()`；不变不动（保持 09-06「视区一动不整轮重建」的原则，只在步长档位跨越时重建一次）。

**因素 C：插值核差异（sinc vs bicubic），决定「位置能否与 SATSOFT 重合」**

| 文件（边界最高电平） | \|sinc − bicubic\| 离边界 > 10 格 p50 / p95 / max (dB) | 离边界 < 2 格 p50 / p95 / max (dB) | 本平台线 → SATSOFT 线距离 ≤ 6 dB 档 p50 / p95 / max（格） | 6～12 dB 档 p95 / max |
|---|---|---|---|---|
| CS-6C（峰下 6.5 dB） | 0.015 / 0.094 / 0.54 | 0.50 / 1.6 / 4.1 | 0.021 / 0.20 / 0.54 | 0.25 / 0.85 |
| 300_X02G（峰下 11 dB） | 0.008 / 0.072 / 0.38 | 0.68 / 1.3 / 1.7 | 0.008 / 0.064 / 0.27 | 0.073 / 0.64 |
| CS26GT HTS（峰下 36.7 dB） | 0.025 / 0.24 / 0.82 | 无样本 | 0.005 / 0.028 / 0.13 | 0.018 / 0.023 |

「bicubic 细网格 MS → sinc MS」的距离与「本平台线 → SATSOFT 线」几乎相同（如 CS-6C ≤ 6 dB：0.21 vs 0.20 格 p95），说明剩余的位置差**全部**来自插值核，与折线密度无关。差值集中在两处：网格边界附近（SATSOFT 的 FFT 周期延拓在边界电平不够低的文件上振铃 0.5～4 dB，正是手册 p164 警告的情形）和欠采样的小波束（HTS 0.1°，5 点 / 波束宽）。p95 0.03～0.2 格：一格 8 px（截图缩放）时 ≤ 1.6 px 看不出；一格 60 px 时 2～12 px 可见。

**结论**：要「看着一样平滑」，方案 2.2 + 因素 B 的修复即可，且比 SATSOFT 更平滑；要「线的位置逐点重合」，唯一办法是同一套重建（Whittaker 密度 N 的 FFT 零填充），作为可选项「等值线插值：本平台（bicubic，线 = 表）/ SATSOFT 兼容（Whittaker 密度 N，默认 5）」只作用于等值线：每波束每 (极化, 增益) 一次 FFT（需真 FFT，任意长度用 Bluestein；本 harness 的直接求和 1.6～2.3 s / 波束不能上线）+ 细网格 marching squares，按绘制中的波束懒算并缓存网格域折线；填充仍走原网格（3D 25 倍三角形不可承受），高倍放大时填充边与线可差到 0.2 格，且边界附近会连 SATSOFT 的振铃一起复现。是否做这个选项待拍板。

## 3 近地平填充与等值线不贴合

两处不同的根因，均已离线量化（CS-6C 覆盖到地平，`cov_harness2.mjs` ③）：

**A. 3D / 导出路径（CPU 填充 + 地平弧 hull）**：跨地平三角形走 `clipToHull` 分支时跳过了弦中点（`emitTri` 里 `if (fillHull) clipToHull… else if (hasM) pushBand`），填充边界是直弦 P–Q，线是 P–M–Q。实测 215 个线顶点不在填充上，到填充边的距离中位 34 km、p95 354 km。数值这么大是因为这些三角形把「延伸到地平外的垂足假坐标」当顶点，直弦本身方向就是错的。

**B. 线的地平端点 `limbEnd`**（二维求根到 m = 0 且 d = L）与填充的地平角点（沿边线性 m 交点，或弦 ∩ hull）不是同一点：42 个端点，偏差 p50 16 km / max 39 km。2D 无 hull 的 CPU 路径也一样。

**2D GPU 路径**（屏上 2D 默认走 glField）：地平按片元精确（dot ≥ 1 discard），但带边界在跨地平子三角形里仍是朝「垂足」假坐标线性插的，同 A 的方向误差，再加 B 的端点差。

**A 期（建议做，3D / 导出）**：跨地平三角形改为「先按 m ≥ 0 用 `limbSolve` 精确裁（现有 `_bgVis`），再按档裁 + `pushBand`（弦中点 / 弧点照常），最后把每个带多边形上的地平边（两个 m = 0 顶点之间）替换成 hull 环上落在两点之间的弧点」。外缘仍是平滑地平弧（hull 保留作弧源），带边界与线由构造重合；填充在地平边上的档交点改调同一个 `limbEnd`。预期 harness 的「线顶点不在填充顶点集」由 257 → 0。改动集中在 `bandGeometry` 的 `emitTri` 填充分支，线的代码不动。

**B 期（2D GPU，可选）**：跨地平格子由 CPU 预切成「内侧多边形 + 地平弧新月带」交给 mesh（glField 顶点 / 索引拼装要加一类顶点），代价大。先做 A 期，看 2D 观感再定。

## 4 搜索框（长时间挂机后）

静态审查没有找到必然复现的缺陷。**需要你补充**：是哪个框（标题栏命令搜索 Alt+Q，还是侧栏卫星搜索）、表现是什么（打不开下拉 / 输入无结果 / 高亮乱跳 / 回车执行了别的命令 / 标题栏拖不动 / 卡顿）。

## 5 链路预算表点序号不聚焦

**根因**：`src/linkbudget/StationGrid.vue` 序号格 `@mousedown.left="onRowDown"`（L747）→ `selectRowRange / syncRangeToRows → selectFullRows`（L1330）直接改写 `range`，不经 `setFocus`，所以不 emit `rowFocus`；父窗 `onRowFocus`（`LinkBudgetApp.vue` L1372）收不到，表脚读数与详细预算不切。E2E 是整行 `@click="curIdx = i"`（`E2eLinkBudgetApp.vue` L1501），所以对。

**修法**（两份副本同改：`src/linkbudget/StationGrid.vue`、`src/ngso/StationGrid.vue`，后者 NGSO 与再生共用）：
- `onRowDown` 普通点击与 Ctrl 点击后 `emit('rowFocus', i, props.stations[i]._id)`（Excel：点行头即活动行）。
- Shift 扩选不 emit（Excel 活动格留在锚点）；拖刷 `onRowEnter` 不 emit。
- 右键 `onIdxContext` 同样 emit（Excel 右键行头即选中该行）。需拍板。
- 父窗 `onRowFocus` 幂等；未计算的行只更新「本行读数」不切详细预算（现有口径，不动）。

**验证**：四窗（GSO / NGSO / 再生 / E2E）点序号后 `#n` 实底标记与「本行读数」跟随；Shift / Ctrl / 拖刷 / 右键 / 列头 / Ctrl+A 行为不变；renderer 预览各点一遍。
