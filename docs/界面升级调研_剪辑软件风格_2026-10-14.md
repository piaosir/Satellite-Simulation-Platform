# 界面升级调研与方案：向专业剪辑软件看齐

2026-10-14 · 调研对象：DaVinci Resolve 18–21、Premiere Pro 25 / After Effects（Adobe Spectrum 2）、Final Cut Pro、Blender 4、Unreal Engine 5、Nuke、NASA Open MCT、STK、Grafana、Blueprint

---

## 0 结论

1. **「剪辑软件那味」可以拆成五件事**，达芬奇、Premiere、Blender、UE5、Open MCT 在这五条上高度一致：
   - ① 中性灰的**明度阶梯**分层，不靠线；
   - ② 面板之间**留缝**，画面是主角；
   - ③ 界面上**只有一种彩色**，数据色只留给数据；
   - ④ 数值能**拖拽改**（hot text），键盘优先；
   - ⑤ **时间轴是主控台**：大时码、播放头、入出点、JKL。
2. 平台差在 ①②③④。⑤ 已有八成（2026-09 精修的「精密仪器」时间轴）。
3. 方案是新增一档外观，暂名「专业深色」，与 浅色 / 深色 并列：
   - **取值**：色值整套取自 **Adobe Spectrum 2 官方 token**。这是 Premiere / AE 的设计系统，Apache-2.0，数值从 npm 包逐个读出，不手调。
   - **结构**：改成「缝 + 面板块 + 面板头 + 焦点面板指示」。
   - **交互**：补「数值拖拽」，时间轴补「入出点 / JKL / 大时码」。
4. **不动的部分**：布局、Lucide 图标、Arial + 等线字体、浅色主题。不切外观的老用户看不到任何变化。
5. **先做 P1 单点原型**：只做主窗外壳 + 一套 token，在真软件里切换对比，满意再往下铺。

|---|---|---|---|---|---|
| 1 | **中性灰明度阶梯** | 不能换主题，只有中性灰（可选更亮一档的 Gray Background Interface）。v12 起放弃纯黑高反差，改为多级灰 | 深色：#111111 底 / #1B1B1B 一层 / #222222 二层 / #2C2C2C / #393939 / #444444 | Blender 默认 #161616–#545454 五级；UE5 #0F0F0F–#383838；Open MCT #222 / #2c2c2c / #393939；Grafana #111217 / #181b1f / #22252b | 深色是暖灰（#1c1c1a / #2a2a27 / #333330，偏黄）。菜单栏、工具栏、活动栏、侧栏、状态栏是同一块 `--surface`，全靠 1px 线分隔，读作「满屏格子」 |

| 6 | **输入框凹陷** | — | — | Blender 文本框 #1D1D1D 比面板暗；UE5 Input #0F0F0F 是全界面最暗的一档 | 深色已是凹槽式（`--field-bg` #171715 < 面板），保持 |
| 7 | **时间轴是主控台** | 播放头贯穿；时码大号等宽；v20 起有关键帧编辑器 | 时码是蓝色 hot text；播放头带帽 | **STK Timeline View**：全区间概览条 + 可缩放刻度 + 访问区间条带。**Open MCT**：「实时 / 固定」两种时间模式用色区分。NLE 通行：入出点、JKL 穿梭、标记 | 有播放头握柄、三级刻度、实时红。缺入出点、JKL、概览条；时码 15px |

**为什么一定是中性灰，不是暖灰**：

- ITU-R BT.2035 规定的参考观看环境是 D65 中性背景、约为峰值白的 10%。偏色的环绕会通过同时对比和色适应，把画面看偏。
- 平台的画面（覆盖等值线色标、气象云图、影像底图）和调色台上的画面是同一类东西。所以这条在平台上同样成立。

**调研里明确被吐槽、不抄的**：

- Premiere 25 的时间线片段圆角和粉彩标签色：用户抱怨窄轨下看不清片段边，Adobe 后来补了「经典」配色。
- Resolve 只在悬停时才出现的控件，以及几乎看不见的绿色 Solo 状态灯。
- Cesium 时间轴的玻璃渐变条。

**关于深色的代价**：

- NN/g（Budiu 2020）的结论：浅底深字时视力敏锐度和校对准确率都更高，字越小差距越大，而用户自己察觉不到。
- 对应做法：画面类工作区适合深色。小字长读的面（详细预算、报表预览）在深色外观里仍保持纸色，见 §3.5。

## 3 方案

### 3.1 取值来源：Spectrum 2 官方 token

**为什么选它**

- 它是 Premiere / After Effects 的设计系统本体。
- `@adobe/spectrum-tokens` 15.5.0 是 Apache-2.0，闭源商用可以用。条件是保留 LICENSE / NOTICE，不用 Adobe 商标。
- 它的灰阶与 Blender、UE5、Open MCT 落在同一灰带，说明是行业共识，不是某一家的口味。

**只取数值的边界**

- **不引组件**：Spectrum Web Components 没有 Vue 官方文档，主题 CSS-in-JS 近 100 KB，还会和 `controls.css` 打架。
- **不用 Adobe Clean 字体**：许可写明「仅限 Adobe 自家产品」。
- **Figma 套件**：S2 官方套件未公开。

### 3.2 结构：缝 + 面板块 + 面板头（主窗）

- **外壳与面板块**
  - 窗口底是 `--bg #111`。
  - 侧栏、舞台、右侧信息栏、时间轴、日志各成一块：`--surface`，圆角 4px，块间 4px 缝。
  - 菜单栏 + 工具栏 + 活动栏 + 状态栏是**外壳**，用 `--surface-2` 连成一片，不分块。Resolve 的页面条、Premiere 的工作区条都属于外壳。
- **舞台（3D / 2D 画面）**：不加头条，四周就是缝，画面最大。剪辑软件的监视器就是这样。
- **面板头合一**：`.dock-hd` 与 `.rdk-hd` 合成一个，现在是手抄的两份。规格为 26px、`--surface-2`、标题 `--fs-2` / 600 / `--text-muted`、右侧放动作钮。
- **焦点面板指示**
  - 当前接键盘的那块面板，头条顶缘画 1px `--accent-ui`。这是 Premiere Focus Indicators 和 Resolve 红线的同类做法。
  - 判定方式：面板根元素上的 `focusin` / `pointerdown`。
- **分隔条落进缝里**：缝本身就是拖拽热区，可见 4px，命中扩到 8px。拖动中缝亮机位色。
- **代价**：画面四周各让出约 4px。

### 3.3 控件语言

- **选中**
  - 分段、页签、主按钮：蓝底白字，即 Spectrum / Premiere / Blender / UE5 的口径。
  - 列表行选中：蓝 28% 淡罩 + `#F2F2F2` 字。
  - 拨杆开、复选勾：蓝底。
- **图标**
  - 默认 `#AFAFAF`，悬停 `#F2F2F2`，开态 `#5681FF`。
  - 开态只点亮图标，不铺色块。这是 Resolve 口径；工具栏 `.tbtn.on` 去掉实底。
  - Lucide 原图、尺寸、笔宽一律不动。
- **输入框**：凹陷 `#111`，描边 `#6D6D6D`，悬停 `#8A8A8A`，聚焦 2px 蓝。
- **菜单 / 浮层**：`--surface-2` + `#444` 边 + `--shadow-3`。暗底上层级主要靠明度，投影只是辅助。
- **滚动条**：拇指 `#444`，悬停 `#6D6D6D`，槽透明。
- **数值拖拽（hot text）**
  - 挂在哪：统一挂在 `src/shared/ui/controls.js`，与 controls.css 一样，一处生效、11 个窗口全有。
  - 怎么用：
    - `.srow` 的标签区按住横拖，改同一行的 number 输入；光标为 `ew-resize`。
    - 用 Pointer Lock 实现无限拖。
    - Shift ×10，Alt ×0.1；步长取输入框自己的 `step`，并遵守 `min` / `max`。
    - Esc 撤回到拖前的值。
  - 数据路径：每一步派发 `input`，松手派发 `change`，与键入走同一条数据路径。这样避开「输入框跳变陷阱」的三个根因（Vue 回写吞输入、number 台阶吸附、负号中间态）。
  - 实际生效范围：主窗侧栏（3D 页约 362 处 `.srow`、GrdSetSections、SatCovPanel、姿态 / 高斯字段）、模型工作台、SSA。脚本虽在 11 个窗口都加载，但只匹配「`.srow` 标签 + 同行 `type="number"`」。
  - 不覆盖：
    - 两张 Excel 式表格，它们有自己的编辑态。
    - **链路预算四窗的参数框**。它们是文本框（`.bb-i` / `.sp-i`），不是 number，并且带着「留空 = 走默认值」、自动回填（managed / 只读）、`3/4` 这类非数值写法。从空格子一拖就会把「默认」变成显式手填值，触发自动回填的指纹判归属。要做得单独设计。
    - C/I、PFD 窗口：不用 `.srow`，本期不匹配。
  - 数值不染成蓝色：密排表单里那会把整片数值染蓝。可拖的提示交给光标和标签悬停态。

### 3.4 时间轴

- **时码**：读数第一行 15 → 18px，等宽数字。
- **入点 / 出点**
  - 操作：`I` / `O` 在播放头处打点，刻度尺上画出范围带；`Alt+X` 清除。
  - 用途一：视频导出起止默认取入出点（`VideoExportPanel` 现有起止字段）。
  - 用途二：「循环」只在区间内循环。时间轴设置里已有 终止时停止 / 循环 / 继续。
- **JKL 穿梭**
  - `J` 倒放、`K` 停、`L` 正放；连按 `L` 逐档加速，按住 `K` 再点 `J` / `L` 逐步。
  - `←` / `→` 一步，`Shift+←` / `Shift+→` 十步，`Home` / `End` 跳起止。
  - 开工前先盘点 3D / 2D 视图现有快捷键，避免冲突。
- **实时 / 仿真两种时间模式**：沿用现在的实时红（Open MCT 也是按模式着色），不改。
- **不做**：轨道 / 片段剪辑式编辑（trim / ripple）。那不是仿真时间轴的需求。

### 3.5 计算类窗口

- **跟随外观的窗口**：链路预算四窗、C/I、PFD、雨衰、日凌、频率计划、性能表、模型工作台。功能区 `.lbr` 换用新 token。
- **文档面恒为纸**：`.lbx-doc` 详细预算区、报表预览、频率计划出图，在深色外观下仍是白底黑字。
  - 判据与字体分两族时相同：「会不会原样进交付文档」。
  - 剪辑软件里，监视器画面同样不跟界面主题走。
  - NN/g 关于小字长读的结论也支持这一条。
- **写死色清扫**：先清 ConstellationMap3D（49 处）、lbworkbench.css（24 处）、三个 SatPanel（同一套轨道类型徽章色，抽成 token）。图面配色不动。
- **Electron 开窗白闪**
  - 13 处 `backgroundColor: '#ffffff'` 改为按当前外观取色。
  - 外观选择要同步给主进程，可存一份到用户数据目录；`titleBarOverlay` 初值同理。

### 4.5 第五轮：两档各自的专属蓝（2026-10-14 同日）

用户：「专业浅色和专业深色使用的蓝色，尤其是专业浅色的蓝有点炸」「浅色的蓝应该浅，深色的蓝可以深」「饱和度都别太高」「浅色主题有它自己专属的浅蓝色，深色主题有它自己专属的深蓝色，而不是统一一个蓝色，各选一个最好的」。

**病根**：两档都是 Spectrum 2 蓝（浅 `#3b63fb`、深 `#4069fd` / `#5681ff`），OKLCH 色相 h≈267 偏紫、彩度 C≈0.22–0.23 几乎顶到 sRGB 色域边。软件里其余的蓝——地图大海出厂色 `#a3ccff`、画面底 `#070b12`、色标蓝阶、搜索框焦点环、原机位色——都在 h 250–256、C ≤ 0.16。界面蓝比画面里的蓝偏紫十几度、彩度高一倍，读作「炸」；两档又是同一个中明度蓝，浅底深底上都是全屏最跳的东西。

**定稿**：每档一个专属蓝 = 所有色块的颜色，两档各自独立挑（不共用色相 / 彩度公式）。

| | 专业浅色 | 专业深色 |
|---|---|---|
| 专属蓝（块：选中段、主按钮、勾选框、拨杆、菜单高亮、眼睛钮、当前行序号格） | `#588abd` = OKLCH .62 / .095 / 250 | `#3e5b87` = OKLCH .47 / .08 / 258 |

**为什么是这两个值**

- 两档的蓝都贴着各自可读性边界取：浅色档取「仍托得住白字、当指示线对面板仍 ≥ 3:1」的最浅位；深色档取「白字充裕、色块对面板 2.5:1 仍一眼可辨」的深位。再浅 / 再深都对拍过：
  - 浅色档「淡蓝底 + 深字」（`#c5def8`，工程软件 / Office 选中色那套）最「浅」，但拨杆成了淡轨黑钮、主按钮「完成」没了分量，且与「状态标记一律上实底」的旧口径（当前行序号格、眼睛钮都是因为淡底不醒目才改的实底）相冲。
  - 深色档 `#354a70`（.41）最雅，但选中态对面板只剩 1.9:1，又回到「深色不够醒目」。
- 色相：浅色档 h 250，与大海出厂色 `#a3ccff`（h 254）同族，即「海的颜色加深一档」，也是 Office 2007 / Tableau 经典工程蓝的色相带；偏青（h 244）读作发灰的牛仔蓝、偏紫（h 256）开始往原来那种艳走。深色档往靛青偏到 h 258，与画面底 `#070b12`（h 260）同色相，读作藏蓝；h 264 已带灰紫味。
- 彩度：浅 .095、深 .08，都不到原 Spectrum 蓝的一半。
- 「线与字」为什么不直接用块色：深蓝当字只有 2.4:1，功能区「计算」、各处开态图标会比旁边的灰字还暗、主次颠倒（对拍实测）。同一个蓝只沿明度推到「刚好 4.5:1」，色相彩度不动——细线与小字靠明度被看见，读起来还是同一个蓝。浅色档这一推只有 ΔL .07，肉眼看不出。
