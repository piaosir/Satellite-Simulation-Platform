## 0 结论

1. **骨架已经到位，刺不在「风格」。** 10-14 升级后的主窗——缝 + 面板块、单一机位色、精密仪器时间轴、信息栏读数网格、命令搜索——是全平台完成度最高的部分。不建议再换视觉方向。
2. **真正的刺分三层：**
   - **读数与交付物硬伤（§1，9 条）**：NGSO 分位表行序错乱、干扰分析图字号随栏宽缩放、深色外观下导出图件和报告图是黑底、瀑布表小数位浮动、链路表数字左对齐、功能区溢出吃掉通知条、过期结果与新结果同形、GCJ-02 十进制度读数错、三窗门限标签漏字。
   - **今天新落地的回归与口径冲突（§2，4 条）**：专业深色下蓝块上 9 处黑字、融合数值条刻线穿读数、专业浅色悬停与拨杆关态几乎看不见、系统「减弱动效」闸让你本机的忙碌转圈静止。前三条都还没提交，趁实测期一起修成本最低。
   - **同一概念多种做法（§3）**：主操作 5 处位置、保存口径 4 套、对话框外壳 8 套以上、弹出层 10 种底色、按钮类 22 种以上、状态色 2 套、分段 6 份副本、图表 7 套口径、空态措辞 3 套。
   - **文案、英文界面与可访问性（§6）**：CLAUDE.md 禁止的说明文字在干扰分析 NGSO 结果区、NGSO / 再生选星读数行等处回潮，报错里 77 条「请…」教学从句；英文界面下系统文件框和多数导出文件仍是中文；909 个可点击的 span / div 键盘够不着。
3. **根因不是没有基线，而是基线没被推广。** controls.css 的 `.btn` / `.srow`、NoticeLine、性能表外壳、链路预算功能区、lbPlotTheme 色板都是好样板，但各窗口靠整块手抄 scoped 副本起家，抄完就漂：同一选择器跨 ≥3 个文件的 156 组里有 101 组已经不一致。结构上（§7），主窗单文件 `ConstellationMap3D.vue` 18,602 行、占全库 Vue 代码近四分之一，是多会话冲突与「每拍整页重渲」的共同根因；四个链路预算窗有 60 个同名函数靠复制同步；Cesium 7.7 MB 死资源仍打进安装包。
4. **提升空间最大的是「收敛」，不是「新做」。** 路线分四期，见 §9：先修 §1 + §2 + CLAUDE.md 违规（零争议，大多 S 级），再做公共件底座，然后用雨衰窗做单点原型收敛窗口外壳，最后做零行为变化的架构拆分。

## 1 先修：读数与交付物

### P0-1 NGSO「CDF 分位」表行序错乱 · S
- **现象**：每次 NGSO 计算，主结果表按 1 → 5 → 10 → 50 → 0.001 → 0.01 → 0.1 % 排列，最关心的尾部被甩到表底。I/N、C/(N+I)、ΔT/T 三列跟着一起乱序，数值本身没错。
- **证据**：`packages/core/utils/interference/ciNgso.js:1398–1404` 用 `const pct = {}` 逐档写入；`src/ci/CiApp.vue:934` 直接 `v-for="(v, k) in ngso.result.percentiles"`。JS 对象的整数键恒排在小数键前面。
- **修法**：界面按数值排序出行（`CiCdfPlot.vue` 的 marks 已经这样做）。引擎输出不动。

### P0-2 干扰分析的图表字号随栏宽缩放 · M
- **现象**：出厂窗宽（1560）下，C/I 时序图刻度约 6.8 px，读不出；紧挨着的 CDF 图刻度是 13.6 px。窗宽 ≤ 1180 塌成单栏后，CDF 刻度变成 24 px。同一栏里两张图字号差一倍。
- **证据**：`CiCdfPlot.vue:31` `W = 320`、`CiSeriesPlot.vue:30` `W = 640`、`CiPatternPlot.vue:28` `W = 460`；`.pl-tick { font-size: 7px }` 写在 viewBox 单位里，再用 `svg { width: 100%; height: auto }` 拉伸。
- **修法**：按 ResizeObserver 取实宽作 viewBox（`SsaChart` 已是这样），字号恒定 11 px 或跟 `--lb-fs`。出图倍率另算。雨衰、模型、LbSurfacePlot 都已是这个口径。

### P0-3 深色外观下，导出图件和报告里的图是黑底 · M
- **现象**：外观出厂是「跟随系统」。系统为深色时，导出的地理场图 PNG、3D 链路视图，以及 Word / PDF / Excel 报告里每条链路的图，都是 #111 黑底加浅灰字，嵌在白底 A4 页里。干扰分析的 PNG 同样如此。交付物的样子随用户屏幕主题而变。
- **证据**：
  - `LbSpacePane.vue:338–347` 的 `pngDataUrl` 把屏上的 `--bg` 等变量写进导出 SVG。
  - `viz/lbglobe/linkGlobe.js:520–541` 的 `snapshot()` 只把字体换成衬线；清屏色和地球贴图仍是屏上主题（`applyTheme`，:494–498）。
  - `useLbReport.js` 的 `harvestFigures` 直接取这两张图。
  - `ci/ciFigureExport.js:90–93` 底色取 `--surface`。
  - 对照：雨衰（`RainPlot.vue:113`）、模型时间线、频率计划、空间态势的出图都已是白纸。
- **修法**：导出路径一律用浅色「纸」token，与屏幕主题解耦（可复用 `ssaChartSvg` 的 print 档）。`linkGlobe` 出图那一帧先切浅色，在现有「换衬线」的 finally 里一并换回（浅色贴图要预取，`applyTheme` 是异步的）。先例：MATLAB `exportgraphics` 的背景缺省是白色，与屏上主题无关。

### P1-4 瀑布表小数位随值浮动，小数点对不齐 · S
- **现象**：这是全平台「定调」的那张表。GSO 级联表「上行」列 21 个数，小数位有 0 / 1 / 2 / 3 四种（`0`、`3.5`、`13.58`），小数点横向散布约 21 px。导出的 Excel / PDF 用的是同一串，交付物也一样。
- **证据**：`packages/core/utils/waterfallBuilder.js:453–456` 的 `_fmt` = `'' + Math.round(n * 100) / 100`，裁掉了尾零。
- **修法**：级联行（base / gain / loss / sub）固定 2 位小数；参考行按量纲定位数。数值仍从显示串解析，「屏幕 = 报表」的口径不破。改完要更新报表快照测试。

### P1-5 链路表的数字全部左对齐 · S–M
- **现象**：GSO / NGSO / 再生 / 雨衰 / 日凌五窗的主表里，经纬度、海拔、G/T、可用度、余量、C/N、占用……一律左对齐，`116.4074` 和 `39.9042` 上下错位，`tabular-nums` 等于白开。这是窗口里面积最大、扫读最多的一块。
- **证据**：`linkbudget/StationGrid.vue:1856` `.sg-tbl th { text-align: left }`，`:1933` `.sg-v` 没有设对齐（两份副本相同）。对照：`ExcelGrid.vue:406` `.eg-tbl td.n { text-align: right; font-family: var(--font-mono) }`；E2E 链路表 `td { text-align: right }`（`E2eLinkBudgetApp.vue:2271`）。
- **修法**：列定义加数值标志：数值输入列和数值结果列右对齐，表头跟着右对齐；文本列和下拉列保持左对齐。占用数据条仍从左铺（Excel 的数据条就是数字右齐、条从左起）。先例：Excel 数字缺省右对齐；AG Grid `numericColumn`。

### P1-6 功能区一溢出，「通知条」和「输入已变」就跑到视野外 · M
- **现象**：你的屏幕缩放是 150%；1920 宽的屏最大化即 1280 CSS px。此时链路预算窗打开资源库（460 px），四窗功能区全部溢出：常驻的红字报错、导出回执「打开 · 在文件夹中显示」、「输入已变」都落在右缘之外，还冒出一条 10 px 的横向滚动条。
- **证据**：`lbworkbench.css:48` `.lbr { overflow-x: auto }`，`:93` `.lbr-status { margin-left: auto }`，NoticeLine 与 `.lbx-stale` 都挂在这个状态位上。实测功能区所需宽度：GSO 849 px，NGSO / 再生 918 px，E2E 934 px；自动最差几何 1043–1059 px，指定起点 1155–1171 px。（同处注释还写着「达标徽章」，是已删功能的残留。）
- **修法**：状态位移出可滚动的功能区，放到窗口底部状态栏（MATLAB App、Excel 的做法），或至少 `position: sticky; right: 0` 加不透明底。窄宽时按 Office 功能区的方式缩放：「单位」「字号」先收成一枚下拉。

### P1-7 过期结果和新结果长得一模一样 · S–M
- **现象**：改一格参数后，表里的余量和占用、本行读数、容量汇总、级联表、图表照旧是正常墨色。唯一的提示是功能区的「输入已变」，又会被 P1-6 挤出视野。照屏幕抄数、截图进汇报时最容易用到旧数。
- **证据**：四窗 `resultsStale` 只渲染成功能区的「输入已变」（GSO 2488 / NGSO 2647 / 再生 2849 / E2E 1960 行附近）；结果列、`LbCapFoot`、瀑布表、图表区都不读这个状态。
- **修法**：过期时整组结果退一档墨色（muted），「详细预算」节头挂同一枚琥珀点，只表状态，不加句子。先例：Jupyter / MATLAB Live Editor 把过期输出置灰。

### P1-8 状态栏坐标：GCJ-02 在十进制度档读数错，且经纬次序与全平台相反 · S
- **现象**：在「坐标系」选了 GCJ-02 的用户，十进制度档下状态栏显示的是 WGS-84 的数，却挂着 GCJ-02 标签（国内偏差可达数百米）。另外状态栏是「经前纬后」，标记列表、信息栏、录入框、度分秒档都是「纬前经后」，照着状态栏往表单里填会填反。
- **证据**：`App.vue:195–199` 的 `fmtCoord` 先算了 `fmtLL`（含 `toDisplay` 换基准），但在 `deg` 档直接用原始 `ll.lon / ll.lat` 自拼字符串返回；`App.vue:704` 照常显示 `datumTag()`。`stores/mapCrs.js:124–129` 的 `fmtLL` 才是正路。
- **修法**：状态栏直接用 `fmtLL`，删掉 App 里的特例；全平台只留一种次序。

### P1-9 三窗的 Es/N₀ 门限标签漏了「门限」二字 · S
- **现象**：NGSO、再生、E2E 的载波面板上，门限字段读作「Es/N₀ ⇄ (dB)」（Eb/N₀ 口径下同理），像是实际 Es/N₀；GSO 那份是「Es/N₀ ⇄ 门限 (dB)」。
- **证据**：`linkbudget/BasebandPanel.vue:457` 与 `ngso/BasebandPanel.vue`（三窗共用）对应位置。这是两份镜像里唯一的语义漂移，2026-08-16 起就在。另外 StationGrid 两份只差 1 行 import、WaterfallTable 两份只差注释。
- **修法**：补回两字；照 StationGrid 的做法给 BasebandPanel 加一条逐字一致的守门测试。

## 2 今天新落地的回归与口径冲突

### R1 专业深色：蓝块上 9 处还在用 `var(--bg)`，黑字压深蓝 · S
- **现象**：时区拾取器（时间轴、链路预算功能区、可见性）当前档的 UTC 偏移几乎看不见；再生式窗口当前模块页签上的链路条数、已算 / 已变状态点、关闭 × 几乎看不见；查找卫星和「加入组」菜单的「＋新建」悬停变蓝底黑字；模型工作台表格勾上后看不到勾。按 10-14 晚定稿的深色专属蓝 #3e5b87 算，对比度约 2–2.7:1。
- **证据**：`SatFinderDialog.vue:126` `.fd-mi.new:hover`；`ConstellationMap3D.vue:17258` `.lmi.new:hover`；`TzPicker.vue:143` `.tzp-i.on > em`；`RegenLinkBudgetApp.vue:3352/3353/3356/3361`（`.rlmode-dot` / `.rlmode-n` / `.rlmode-x:hover` 的 on 态）；`model/model.css:16/21` 勾选列。
- **成因**：今天未提交的迁移把母规则改成了 `-fill` 配 `-on`（调色会话记录「76 行已转」），这 9 条子规则和兄弟规则没跟着改。旧口径「实底字一律 `var(--bg)`」对 `-fill` 块已经失效（专业深色的蓝块往深里走）。浅色两档 `--bg` 恰好等于 `--accent-on`，所以只在深色坏。
- **修法**：9 条 `var(--bg)` 换成对应的 `--*-on`，`color-mix(var(--bg) N%)` 换成 `color-mix(var(--accent-on) N%)`。蓝值怎么定都不影响这条；调色会话还在改同一批文件，**建议交给那边一起收尾**，免得两边并改。

### R2 融合数值条：末端刻线穿过叠放的读数 · S
- **现象**：值靠右时（约 ≥ 80% 量程，透明度这类参数很常见），2 px 机位色刻线正好落在读数上，「透明度 0.90」显示成「0|90」。见截图 `z-focus-range.png`。
- **证据**：`controls.css:153–159` 的 slider thumb（2 px 刻线）与 `rangeField.js` 叠进条内右端的透明底读数。
- **修法**：读数给一块与条底同色的衬底（刻线从下面过去），或刻线进入读数区时淡出。Blender / UE5 的融合条都只画填充、不画刻线，也是一个选择。

### R3 专业浅色：悬停几乎看不见，图层拨杆的「关」也几乎看不见 · S
- **现象**：在专业浅色（系统浅色时的出厂外观）里划过卫星集行、分段控件、工具栏，几乎没有反应，正是「寡淡」的来源；环境场、标记、Polygon、设置窗里的拨杆，关态只剩一条淡灰胶囊。
- **证据**：20 条悬停规则用 `--surface-2` 做底，`#f3f3f3` 对面板 `#f8f8f8` 只有 1.045:1（旧浅色 1.098）；另 13 条用 `--bg`，1.06:1。拨杆轨道 `controls.css` `.layersw { background: var(--border-strong) }` = `#c6c6c6`，对面板 1.61:1，白钮对轨道 1.71:1；深色那侧已单独修过。
- **修法**：两档各加一个 `--hover-fill`（浅色取 Spectrum gray-100 / 200 一档，对面板约 1.10–1.17；深色 `#2c2c2c`），或统一改用已有的 `--wash-hover`。拨杆关态轨道改走 `--field-border`（3.05:1）。**涉及外观取值，建议与调色会话一起定。**

### R4 系统「减弱动效」闸：你本机的忙碌转圈是静止的 · S
- **现象**：你的机器关了 Windows「动画效果」，Chromium 恒报 reduce。于是链路预算功能区的「刷新」转圈停住并压淡、检查更新的转圈不转，09-24 精修的菜单 / 对话框入场与按钮过渡也从未生效。忙碌反馈丢了。
- **证据**：`controls.css:537`（入场关键帧只在 `no-preference` 下存在）、`:672–680`（reduce 下全部过渡归零）；`lbworkbench.css:282–284`（reduce 下功能区刷新转圈停住并压淡）；`UpdateDialog.vue:125`、`LbLibrary.vue:217`。滚动那一路已经改成只认应用内开关（`panelSections.js:43`），所以现在有两道闸。
- **修法**：删掉这几段 media 闸，统一以 `--dur-*` 为准（与「动效只认应用内开关」一致）。转圈是状态指示，不是装饰，恒转。
