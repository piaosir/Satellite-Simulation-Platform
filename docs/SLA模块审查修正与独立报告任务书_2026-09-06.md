## 3. 第一期：算法修正（按优先级）

每条给「现状 → 问题 → 改法 → 依据列 → 测试」。数值见附录 A。

### 3.1 丢包率：随机误码模型换成帧差错模型（硬伤）

**现状** `deriveSla` 744–759：`n = berExpOf(data.berResult)`，`packetLossPct(n, pktBytes) = 1 − (1 − 10⁻ⁿ)^(8L)`，再向上取档。引擎里 `ber` 字段只生成显示串（`linkCalculator.js:285`、1146），与门限 C/N、余量没有任何计算关系；端到端 `e2eBerResult` 是各段设计 BER 之和（`linkChain.js:795`）。

**问题** 这是**无编码、比特独立随机误码**的教科书式子。DVB-S2 / S2X / RCS2 的门限按 QEF 定义（ETSI EN 302 307-1 §4.1：约合 PER < 10⁻⁷），LDPC+BCH 译码后的错误是**帧级突发**，不是比特级独立。实测：n = 7、L = 1500 B → 0.1199 % → 取档 **0.5 %**；按帧差错口径 ≈ 10⁻⁵ % 量级 → **0.001 %** 档。差 3–4 个数量级；把 0.5 % 丢包写进合同是不可交付的承诺（TCP 吞吐随 1/√p 崩）。

**改法**
- 新增场景级参数 `ferExp`（「帧差错率 10⁻ⁿ」，缺省 7 ＝ QEF；进 `DEFAULT_SLA_PARAMS` / `normSlaParams` / `SLA_PARAM_LABELS` / 面板 `PARAMS`，`needs: ['loss']`）。
- `deriveSla` 按 `carrierForm.dvbStandard` 分支：
  - **编码标准**（`dvbStandard !== 'custom'`，含 3GPP NTN 的 snr 行）：帧差错模型 `p_loss = 1 − (1 − 10⁻ⁿ)^N_f`，n = `ferExp`，`N_f = ⌈8L / K⌉`，K ＝ 一帧净荷 bit：DVB 家族取 `64800 × FEC 码率`（正常 FECFRAME；表里没有 K_bch，用这个近似，误差 < 0.5 %，依据列只写 N_f 不写 K）；NTN 取 `phyTbsResult`。L ≤ 6 kB 时 N_f = 1，于是 p_loss ≈ FER。
  - **自定义 / 无编码**（`'custom'`）：保留现在的随机模型（`packetLossPct` 原样）。
  - 端到端：各段体制可不同，取链首载波的 `dvbStandard` 判分支；帧差错支的 FER 用 `ferExp`（不再用 `e2eBerResult` 之和）。
- 新增只读条款 `berTarget`（组 `delay`，`kind: 'text'`，无采用值格）：原样带出 `berResult`（端到端 `e2eBerResult`），依据「—」。合同里这一行叫「设计误码率」，是载波配置的转述，不是算出来的。
- 组名 `delay` 的 label 从「时延与丢包」改「时延与差错」（EN `Delay & Errors`）。
- `loss` 的 `tip` 补一句口径：**只在可用时间内考核**（中断时段不计入丢包统计）。

**依据列** 编码标准：`1 − (1 − 10⁻⁷)^1 = 1.00e-5 % → 0.001 %`（`expText(n)` 与 `pctText` 照用）；自定义：现状不变。

**测试** DVB-S2 QPSK 3/4、1500 B、ferExp 7 → 建议 0.001；custom BER 1e-7 → 0.5（老路径不变）；NTN 走 TBS；`berTarget` 文本原样、英文版无汉字；`ferExp` 进分享包往返。

### 3.2 最大 EIRP / 最大 PSD：计入 UPC 抬升（硬伤）

**现状** `txEirp = stationEIRPResult + eirpTolDb`、`txPsd = stationPSDResult + 36.02 + eirpTolDb`（801–816）。引擎 `stationEIRP = selectedPower + txAntennaGain − feederLoss`（913）是**晴空工作点**；`uplinkPowerControl` 为「是」时 `UPCmarginResult` = 上行雨衰（784–800、1383），「自定义」时 = 用户给的 dB；雨天发信站会把 EIRP 抬到 `EIRP + UPC 余量`。NGSO 同（`linkCalculatorNGSO.js:1629`）；端到端各 hop 带 `upcMargin`（`linkChain.js:1085`，核对键名）。

**问题** 运营商入网核准的是**雨天峰值 EIRP / PSD**。UPC 开启时条款低报了整个 UPC 范围（Ku 波段常见 3–8 dB）——客户按这份 SLA 报备，一下雨就超标。

**改法** 建议值 = `EIRP + UPC 余量 + 容差`（PSD 同），UPC 余量取 `UPCmarginResult`（端到端取链首上行 hop 的 `upcMargin`）；为 0 或取不到时那一项不写（依据列不摆 `+ 0.00`）。`txEirp` / `txPsd` 的 `tip` 改成「发信站晴空 EIRP + UPC 余量 + 容差」。

**依据列** `62.30 + 5.80 + 1.0 = 69.10 dBW`（三项一片一个数）；无 UPC 时仍是 `62.30 + 1.0 = 63.30 dBW`。

**测试** GSO 算例 `uplinkPowerControl: '是'` → EIRP 建议 = 晴空 EIRP + 上行雨衰 + 容差（±1e-6）；「否」→ 与现在逐位相同；`.slaharness/fixtures.js` 加一条 UPC 用例。

### 3.3 处理时延预留：「ms/端」与公式不符（口径修正，数值不变）

**现状** 参数 `procMsPerEnd` 标签「处理时延预留 ms/端」缺省 20；RTT = ⌈(2·单程 + 2·预留)/10⌉×10。

**问题** 一次往返穿过两端各两次（发端调制 + 收端解调，两个方向），「每端」口径应乘 4；公式乘 2 对应的其实是「每单程」（发端 + 收端合计）。数值上 20 ms/单程恰是 DVB-S2/RCS2 调制解调器公开的单程时延量级（10–50 ms），所以**改口径不改数**。

**改法** 键名不动（存档兼容），`SLA_PARAM_LABELS` / 面板 `PARAMS` 的单位改 `ms/单程`（EN `ms/one-way`），tip 改「发端调制 + 收端解调的单程处理时延预留」；RTT 依据列写成 `⌈2 × (119.6 + 20) / 10⌉ × 10 = 280 ms`（与现在恒等）。`rtt` 的 `tip` 同步。

**测试** 原 RTT 断言数值不变；标签断言更新；`uiDict` 补新串。

### 3.4 考核周期：年均 vs 最坏月（交付级缺口）

**现状** 可用度建议值是 P.618 **年均**统计；合同 SLA 几乎都**按月考核、按月赔付**。P.841 换算：年 99.8 % ≈ 最坏月 99.30 %，年 99.9 % ≈ 99.62 %（附录 A）。承诺 99.9 % 按月考核，在雨季那个月必然违约。平台雨衰页已有这一换算（`rainAttenuation.js:291`），SLA 没接。

**改法**
- 新增场景级参数 `monthly`（0/1，缺省 0 ＝年口径；★ 值是数不是布尔），面板参数轨「考核周期」用勾选闸（同 `groundOn` 的做法：勾选框 + 名字，无数值格）。
- `monthly = 1` 时：传播可用度先换到最坏月 `A_wm = 100 − p_w`，`p_w = ((100 − A)/0.30)^(1/1.15)`（与 `rainAttenuation.js:291` 同式；ITU-R P.841 全球模型），**再**乘设备因子（设备可用度本就是长期平均，不换算）；系统可用度按换算后的综合值向下取档；年中断改**月中断时长上限** = (100 − A)/100 × `MIN_PER_MONTH`（= `MIN_PER_YEAR / 12` = 43830 min）。条款名随口径：「系统可用度（月）」/「月中断时长上限」（EN `System availability (monthly)` / `Monthly outage (max)`），`SLA_ITEMS` 里加 `labelMonthly / labelMonthlyEn`，`slaRows` 按 `monthly` 选。
- 档位扫描表：「档位」列仍是引擎的年口径；「综合」列改为 `tierWm × eqFactor`（`tierWm = 100 − p_w(100 − tier)`），年中断列改月中断；列头 `title` 写明「综合 = P.841 最坏月折算 × 设备因子」。`feasibleTier` 的参照 `ref` 同样折算。
- 端到端：各星地跳之积先算年口径系统可用度，再整体换算（P.841 是对单站统计的经验式，逐跳换算再相乘会把保守叠两次；写明这是近似）。
- 报告（§4 与第二期的独立报告）在 SLA 参数行印「考核周期 年 / 月」。

**依据列** 月口径的传播行：`100 − ((100 − 99.800) / 0.30)^(1/1.15) = 99.297 %`（`bal` 容差 1e-3）；系统行照旧连乘 `传播 99.297 % × 发信射频 99.990 % × … = 99.267 % → 99.000 %`。

**测试** 年口径全部断言不变（缺省 0）；月口径：99.8 → 99.297（±1e-3）、99.9 → 99.615、取档 99.0；月中断 = 43830 × 0.01；扫描表综合列折算；`monthly` 进分享包往返。

### 3.5 日凌预计中断：列为免责事件（交付级缺口）

**现状** 平台有 v5 物理判据的日凌计算器（`calculateSunOutage`），SLA 未引用。粗算 Ku 2.4 m 站年日凌约 30 min、1.2 m 站约 75 min，与 99.99 % 一年 52.6 min 的预算**同量级**（附录 A）。专业 SLA 要么把日凌列为免责事件并给出预计窗口，要么计入可用度——现在两者都没有。

**改法**
- 新增组 `excl`「免责事件」（EN `Excluded events`），只读条款 `sunOutage`「日凌预计中断」（EN `Sun outage (predicted)`），单位 min，年两季合计；不参与连乘、不进中断预算。**只对 GEO 出**（NGSO 跟踪运动星、再生式与端到端不出）。
- 输入按引擎留底入参（`sweepParamsByRow[rowId]`）取：收信站 `rxLatitude / rxLongitude`、口径 `rxAntennaDiameter`、卫星 `orbitPosition`（三者已核实在 `src/linkbudget/params.js` FIELD_GROUPS 里）；下行频率与收信系统噪温的键按 FIELD_GROUPS 查；`degThreshold` 缺省 1 dB（行业预报惯例，与日凌窗口一致）；`year` 取当前年。
- 计算走已有 IPC `api.sunOutage.compute`（春分、秋分各一次），在 GSO 窗加 `refreshSlaSun(out, store)`：**惰性**——弹窗打开或导出报告时才算，按 `rowId + 入参哈希` 缓存到会话态 `slaSunByRow`，重算即作废（同 `slaScanByRow` 的生命周期）。`deriveSla` 收 `ctx.sunOutage = { vernal: { minutes, days, rows }, autumnal: {...} }`。
- 参数轨不加新参数；条款 `tip` 写判据（C/N 恶化 ≥ 1 dB、收信站口径）。

**依据列** 署名两片：`春分 24.1 + 秋分 23.7 = 47.8 min`（`L('春分','Vernal')`、`L('秋分','Autumnal')`）。

**报告** 第二期的逐链路详情里附「日凌预计窗口」表（日期 / 起 / 止 / 时长，UTC 与北京时间两列——引擎的 `dailyResults` 两套都给）。

**测试** 用 `calculateSunOutage` 直接算一组固定站（北京 → 110.5°E、2.4 m、12.5 GHz）钉住合计分钟数（±1 min）；非 GEO 体制不出该组；`sunOutage` 为空时整组不出。

### 3.6 星间微波与激光同口径（口径不一致）

**现状** 引擎里星间微波（isl）的 `systemAvailabilityResult` 与激光一样是**几何互视占比**（`linkCalculatorRegen.js:414–427`、553–560）。`deriveSla` 566 只排除 `laser`：isl 被当成传播可用度取档、再乘 `spaceAvail × 2`；激光整组不出。同一物理量两种待遇。

**改法** isl 与 laser 一律：只读行「互视可用度」（key `visAvail`，替代该体制下的 `propAvail`），系统可用度 = 互视 × 卫星与载荷 × 2，向下取档照旧；手动几何（引擎给空串）整组不出（现状行为）。`AV_LABEL` 加 `vis: L('互视', 'Visibility')`。`equipSlots` 的 isl 分支照旧，laser 分支改成与 isl 相同（`spaceAvail × 2`）。

**测试** 原 ⑥「激光无可用度组」改为「激光有可用度组且依据署名互视」；isl 同。

### 3.7 端到端中间转接站计两条射频链

**现状** `equipSlots` E2E 分支：链首按发信射频 ×1、其余地球站按收信射频。中间转接站在链上既收又发，两条射频链都可能坏。

**改法** 发信射频 × (nEs − 1)（除末站外每站一次）、收信射频 × (nEs − 1)（除首站外每站一次）；两站链结果不变，三站链多乘一次。测试 ⑧ 的端到端断言更新（`esCount: 3` → `esTxAvail×2, esRxAvail×2`）。

### 3.8 同站回环时上下行雨衰完全相关

**现状** 传播可用度 = 上行 × 下行，假定两站雨衰独立。发信站与收信站坐标相同（回环测试、自环）时两侧同时衰落，A = min(上行, 下行) 而非乘积。

**改法（仅 SLA 层）** `|Δlat| < 1e-6 && |Δlon| < 1e-6` 时传播行取 `min`，依据列 `min(上行 99.900 %, 下行 99.900 %) = 99.900 %`（署名照旧）。引擎那份 `systemAvailabilityResult` 不动（链路表口径由用户另拍板，见 §5）。

### 3.9 可用度低于 99 % 时建议值留空

**现状** `snapDown(AVAIL_TIERS, comp)` 够不着 99 返回 null → 条款表与报告里空格。Ka 波段小站、月口径下很容易落到 99 以下。

**改法** `AVAIL_TIERS = [98, 98.5, 99, 99.5, 99.7, 99.8, 99.9, 99.95, 99.99]`；仍够不着最低档时建议值 = 综合值向下取到 0.1 %（`Math.floor(comp × 10) / 10`），依据列照写 `→`。扫描样本随之 9 档 + 晴空（`MAX_STEPS` 400 远够）。`slaScan.test` 的「样本 = 7 档 + 晴空」改 9。

### 3.10 新增合同条款与一条一致性读数

- **时延抖动** `jitter`（组 `delay`，`kind: 'num'`，单位 ms，`dec: 0`，`cmp: 'lt'`）：纯合同参数，缺省 30 ms（新增场景参数 `jitterMs`），依据「—」，`tip`「按运营商入网要求填；IP 业务惯用 ≤ 30–50 ms」。
- **隐含年故障次数上限**（参数轨末尾一行只读读数，含运行时数据故允许）：`(1 − eqFactor) × MIN_PER_YEAR / (restoreH × 60)`，例 `157.8 min ÷ 240 min = 0.66 次/年`。它回答「99.99 % × 4 h 恢复时间」自洽不自洽——一年坏一次就已违约。`eqFactor = 1` 时不出这一行。

### 3.11 依据列署名补齐（端到端）

`owd` 端到端依据 `0.238 + 5.000 = 245.2 ms` 与 `rtt` 的 `2 × (245.2 + 20)` 两处的「处理」是两个不同的量（星上处理 vs 地面调制解调）。前者署名 `传播` / `星上处理`，后者署名 `地面处理`（`L()` 各自一片）。

### 3.12 措辞小修
