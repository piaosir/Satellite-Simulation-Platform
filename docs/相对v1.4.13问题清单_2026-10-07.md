## P0　会丢数据

### 1. 日凌 / 雨衰：从主窗口「分析 ▸」带星打开，会清掉没存的表
- **现象**：
  - 条件：日凌或雨衰窗口里的内容没存成配置。显示「暂无配置」也算在内，没保存过配置的用户一直处在这种状态。
  - 操作：在主窗口右键一颗卫星，选「分析 ▸ 日凌预报」或「分析 ▸ 雨衰计算」。
  - 结果：窗口直接换成一份空白「新配置」，原来的站表或算例表没了，没有任何提示。
  - 另一个症状：每带一次星，配置列表就多一份「新配置」。存进去的是出厂空白，不是带来的那颗星；之后关窗还会弹保存提示，选「不保存」的话，空白配置就留在列表里越积越多。
- **原因**：带星时走「新建空白配置」。离开前的保存提示只在「有当前配置且改过」时才弹，没有当前配置时直接覆盖。
- **怎么改**：
  1. 带上下文时不调 `addBlankConfig`。
  2. 如果没有当前配置、且工作区不是出厂空白，先把它自动另存一份，或者按「改过」走保存提示。
  3. 再把带来的星和站套到空白状态上，用默认名（星名 + 年份）一次存盘，并 `setBaseline`。
- **位置**：`src/suntool/SunOutageApp.vue`、`src/rain/RainApp.vue` 各自的 `applyToolContext`；`src/shared/useConfigTree.js` 的 `addBlankConfig`

### 2. 主窗口「卫星模型」侧栏的「移除缓存」会永久删掉本机模型，不确认
- **现象**：
  - 在模型库卡片上右键，选「移除缓存」。
  - 对本机导入的模型和工作台里自建的装配件，这一项实际是删除原文件：不问一声，删了找不回。
  - 绑了这个模型的卫星，之后也不再显示模型。
- **原因**：
  - 侧栏对本机件也放开了这一项，直接调删除。
  - 工作台库页对同一操作有「删除本机模型？」确认，侧栏没照着做。
- **怎么改**：
  1. 侧栏的「移除缓存」只给远端下载下来的缓存件。
  2. 本机件改成「删除」，照工作台加确认；也可以侧栏干脆不给删。
  3. 顺带把灰掉的菜单项的点击真正拦住。
- **位置**：`src/components/ModelSidePanel.vue` 的 `doRemove`，以及右键菜单里「移除缓存」那一行

## P1　明显影响使用

### 3. 四张表格按老列序粘贴会错列（回归）
- **现象**：这几张表新加了列。选中单元格后 Ctrl+V 粘贴 v1.4.13 列序的数据（例如 Excel 里的「名称 / 经度 / 纬度」），按位置填就错了：

  | 表格 | 结果 |
  |---|---|
  | 标记批量表格·地球站 | 经度进了「天线口径」（116.4 m，在合法范围内不会被拒）；经纬度为空，站不上图 |
  | 标记批量表格·点标记 | 经度变成名称，纬度进了经度 |
  | 对地性能指标表·城市列表 | 纬度进了「高度」，经纬度为空；覆盖已有行时名字换了、坐标还是旧的，结果静默算错 |
  | 气象指标表 | 纬度写进经度，得到一个看着正常的错坐标 |

  以下三种方式是对的，可以绕过：不选格直接粘贴（整块追加）、「粘贴剪贴板」按钮、「从 Excel 导入」。
- **原因**：新列插在经纬度前面，而定位粘贴严格按列位置对应。
- **怎么改**：在定位粘贴里加一条判断：块宽少于「起始列到经纬度」的列数、并且每行末两格是数字时，按「末两格 = 经度 / 纬度，前面依次填文本列」落位，与整块追加同一约定。四张表一起改。
- **位置**：
  - `src/viz/markers/useMarkerTable.js` 的 `pasteBlock`（`ST_COLS` / `PT_COLS`）
  - `src/viz/grd/usePerfTable.js` 的 `pasteBlock`（`EDIT_COLS`）
  - `src/perf/MetTableWin.vue` 的 `pasteBlock`

### 4. 飞行航迹航点一多就卡（回归）
- **现象**：有一条几千航点的飞行航迹时（例如导入的 ADS-B 记录）会卡顿。航行航迹不受影响。
  - 每次点选卫星、拖标记样式滑块、拖动标记都会停顿：3000 点约 0.1 s，6000 点约 0.35 s，9000 点约 0.8 s。
  - 标记批量表格「航迹」页打开或改一格：3000 点要等 6 s，6000 点要等 26 s。
- **原因**：
  - 按实际高度画飞行航迹、航迹表的推算列，都对每个航点把整条航迹重新核对一遍，复杂度是平方级。
  - 页面每次重推标记都清掉缓存重算。
  - 表格还是经过响应式代理算的，更慢。
- **怎么改**：
  1. `trajWaypointInfo` / `trajLine3` 只取一次计划；逐点取状态改用直接接收计划的内部函数，不再每点调 `trajPlan`。
  2. 表格计算前先 `toRaw`。
  3. `pushMarkers` 不要无条件清航迹缓存，按航迹内容变化作废。
- **位置**：
  - `packages/core/models/trajKinematics.mjs` 的 `trajWaypointInfo`、`trajLine3`、`trajStateAtS`
  - `src/pages/ConstellationMap3D.vue` 的 `pushMarkers`、`mkWpInfo`

## P2　小问题

### 5. 无名点标记带进日凌 / 雨衰后站名变「北京」，带进 C/I 沿用上一个站名
- **现象**：
  - 地图点标记默认没有名字。
  - 从「分析 ▸」带进日凌或雨衰后，站名显示为列缺省值「北京」，导出的 Word / Excel / ICS 里也叫「北京」，坐标却在别处。
  - 带进 C/I 时，站名还是上一个站的。
- **怎么改**：接收端没有名字时用经纬度兜底；或者在发送端给点标记补「点标记 N」。
- **位置**：`SunOutageApp.vue`、`RainApp.vue` 的 `applyToolContext`；`src/ci/CiApp.vue:46`

### 6. 2D「跟随卫星」退出后，地图投影中心和星下点参考被永久改掉
- **现象**：
  - 退出 2D 跟随后，地图中心停在那颗星最后的星下点，等距圆柱投影的切口也跟着移了。
  - 原来设的星下点参考被换成这颗星，重启软件后仍是这样。
  - 对比：3D 跟随退出时会复原，2D 不会。
- **怎么改**：进入 2D 跟随时记下 `lon0 / lat0 / subPt / subFollow`，退出时还原；或者跟随时只平移画面，不写投影设置。
- **位置**：`src/pages/ConstellationMap3D.vue` 的 `startFlatFollow` / `stopFlatFollow`

### 7. 2D「跟随」对导入星历文件的卫星（OEM / SP3 / .e）不起作用，按钮却显示在跟随
- **怎么改**：`subPtPos` 里的 `if (!e || !e.rec) return null` 改成 `if (!e || (!e.rec && !e.eph)) return null`。
- **位置**：`src/pages/ConstellationMap3D.vue` 的 `subPtPos`

### 8. 链路预算自动保存：写盘那一瞬间动了配置树，最近一笔改动可能丢（概率低）
- **现象**：
  1. 改完一格约 1 秒后，自动保存开始写盘。
  2. 恰好在写盘的几十毫秒里，在配置树上拖动、改名或新建文件夹。
  3. 之后切到别的配置再切回来，看到的是旧内容。
  4. 再改一笔，就把旧内容写回盘，刚才那笔改动丢了。
- **原因**：写盘前取到的那条配置对象，在写盘期间被配置树重读整表替换掉了；写完更新的还是旧对象。
- **怎么改**：写盘成功后按 id 重新取列表项再更新（`const cur = itemById(id) || it`）。历史版本「还原非当前配置」那条分支（`c.state = st`）同样处理。
- **位置**：`src/shared/useConfigAutosave.js` 的 `runOnce`；`src/shared/useConfigVersions.js` 的 `restoreVersion`

## 口径变化（不是 BUG，但老配置算出来会和 v1.4.13 不同）
- **NGSO / 再生式 / 端到端「自动最差」**：搜索起点的缺省值从「点计算那一刻的系统时钟」改成了「主窗口时间轴此刻」。要回到旧口径，选「系统时钟」档。
- **天线树里的「轨道根数」星**：旧节点的历元固定为 2026-01-01 00:00Z（v1.4.13 每次以计算时刻为历元），这类星的几何结果会变。
- **升级后第一次打开链路预算四窗**：上次没保存的改动会被写进配置。写之前会先留一档「打开时」历史版本，可以还原。
- **GSO**：关联星此刻解不出星历时，EIRP / G/T 不再拿存盘的旧星位回填。
- **C/I 的 NGSO 起点**：改为开窗时的时间轴时刻。

## 待实测 / 加固（不计入 BUG）
- **跟随视角可能掉帧**：播放时钟时，近场轨道线的材质每一拍都销毁重建，可能每拍重编一次着色器；还没实测是否掉帧。
  - 改法：材质跨拍复用，只换几何。
  - 位置：`src/viz/globe3d/modelLayer.js` 的 `setNear`
- **两条通道没限制路径**：只有页面被注入恶意脚本时才可利用，常规使用碰不到。
  - `models:readFile` 能读任意位置的模型 / 图片类文件。改法：只放行对话框选过的路径及其伴随文件。
  - `video:frame` 没校验帧号，可写到所选目录之外。改法：校验帧号是整数，且写出的文件落在所选目录内。
- **约定违例两处**：
  - `electron/services/models.js:1901` 的失败提示带教学式从句「…请关闭后重试」。
  - 模型工作台万向节 XLSX 导出的「状态」列是文字判定（可跟踪 / 超限 …）。
