## 1. 背景与诊断（已核实）

- 现有「自转」= `scene.js:347` `controls.autoRotate = true; autoRotateSpeed = 0.5`，设置窗「地球自转」开关 + 「自转速度」滑块（`SettingsModal.vue:142–151`）只是调这个匀速转。与 `clock.tMs` 无关：暂停时钟它照转，播放 ×3600 它也不快。
- 场景是**地固（ECEF）**坐标：地球网格静止，卫星 SGP4 → ECI → `eciToEcf(gstime)` 落到地固系（`ConstellationMap3D.vue` `refreshPositions` 约 1988–2030 行），晨昏线同一 GMST（`viz/terminator.js:63`）。**Y 是极轴**（`scene.js:1475` `ORB_AXIS = (0,1,0)`，`focusLanes.js:12`）。
- 已有一个「惯性」先例：聚焦星轨道圈按参考 GMST 建几何、每拍用 `setOrbitRingSpin(ringEpoch.gmst − gmstNow)` 绕 Y 反转（`ConstellationMap3D.vue:1760–1761`、`scene.js:1506–1509`）。**新的惯性视角就是把同一个增量施加到相机上**——轨道圈在屏幕上不动、地面在它下面滑过，这正是验收判据。
- 「太滑溜」两个根因：
  1. `controls.enableDamping = true; dampingFactor = 0.08`（`scene.js:340–341`）。OrbitControls 的 damping 是**逐次 update 的一阶滞后滤波**：拖动中相机以 `delta × 0.08` 逐帧逼近指针命令、松手后剩余量继续滑。时间常数 1/0.08 = 12.5 帧 ≈ 208 ms @60fps、417 ms @30fps（画质低/中档封顶 30 fps）——**拖动中地球落后指针约 200 ms，松手后再滑同样多**，且手感随帧率变。
  2. `controls.rotateSpeed = 0.5` 恒定（`scene.js:344`）：OrbitControls 每像素转 `2π·rotateSpeed/H` 弧度，与相机距离无关。贴地（距离 1.02–1.3 R）时地面在指针下飞过；默认距离 3 R 时满屏拖一次转 180°，地面也比指针快一倍。
- 滚轮现状：3D `zoomTarget *= e^(deltaY·0.0018)`（`scene.js:380–384`）一格（deltaY=100）≈ 距离 ×1.197；2D `scale *= e^(−deltaY·0.0015)`（`flatCoverage.js:3256–3262`）一格 ≈ ×1.162。底部状态栏把缩放显示为**进度百分比** `Math.round(zoom.value×100)%`（`App.vue:578`，`stores/zoom.js`，t ∈ [0, 1.2] 对数映射，± 按钮一次走 0.01）。换算成这条读数：3D 一格 ≈ 4.8 个百分点、2D ≈ 3.6 个百分点。**用户说的「3%」就按这条读数定义：一格 = 缩放读数走 3 个百分点**（与 ± 按钮同一刻度，用户看得见、能对上）。

参照的成熟实现（按项目记忆 `research-before-ui-work.md` 的约定：先查成熟方案再动手）：
- Cesium `ScreenSpaceCameraController`：拖动 1:1（抓住的地面点跟着指针走）、松手后惯性按 `exp(−(1−inertiaSpin)·25·t)` 衰减（`inertiaSpin` 默认 0.9），**按时间不按帧**；Cesium Sandcastle「ICRF」示例：场景仍在地固系画，每帧给相机套 ICRF→Fixed 变换 = 惯性视角。
- STK 3D 窗口：中心体参考系 Fixed / Inertial 两档，切档只改相机所在的系。
- three.js OrbitControls（r184）：`autoRotate` 已按 `deltaTime` 归一，**`enableDamping` 没有**（`update()` 里 `_sphericalDelta *= (1 − dampingFactor)` 逐次衰减，`OrbitControls.js:790–795`）。

## 5. 地球自转：惯性视角 / 相机跟随

### 5.1 语义

| 档 | 相机所在的系 | 画面 | 备注 |
|---|---|---|---|
| **相机跟随**（`frame:'fixed'`，**出厂默认**） | 地固 ECEF | 地面不动，卫星相对地面走 | 逐位等于 v1.4.11 行为；SatSoft / STK / Cesium 出厂同此 |
| **惯性视角**（`frame:'inertial'`） | 惯性（相机在 ECEF 里以 −ω_E 绕极轴退） | 地球随仿真时钟东转 15.04°/h；GEO 星跟着地面走；LEO 轨道面 / 聚焦星轨道圈在屏上不动 | 实时档 1 Hz 每拍 0.0042°；播放 ×600 步长 60 s 每拍 0.25° |

**自转角速度不是参数**（用户 2026-09-21 明确：完全仿真，不再可以改变自转速度）：两拍之间地球转过的角度恒等于 `GMST(t₂) − GMST(t₁)`，由 `sat.gstime` 算出（与星位、晨昏线同一函数、同一相位），即恒星日 86164.0905 s、360.9856°/日、15.041°/h。快慢只随时间轴的步长 / 倍速 / 跳转走；界面上**不留任何速度旋钮**，代码里也不留可调系数。实时档 1 Hz 每拍 0.0042°，默认距离下每秒不足一像素，几分钟才看得出在转——这就是实际。

「相机跟随」= 改造前不勾展示性自转时的静止画面：场景本就是地固系，相机固定在地固系里，等价于相机与地球同步自转；卫星相对地面的运动、GEO 定点、晨昏线移动早已按 GMST 算对。本次只是把这一档正名，并新增惯性档。

出厂默认取「相机跟随」是为了老用户升级后画面不变；用户若要改默认，改 `viewPrefs.js` 一处即可（见 §13）。

### 5.2 实现（Cesium ICRF 同一思路：场景不动，动相机）

1. `viewPrefs.frame: 'fixed' | 'inertial'`。
2. `scene.js` 新增：
   ```js
   let frameMode = 'fixed', lastGmst = null
   function setFrameMode(m) { frameMode = m === 'inertial' ? 'inertial' : 'fixed' }   // 切档不跳：只从下一拍起施加增量
   // 每拍一次（refreshPositions 里调，两条分支都要调）：gmst 为本拍时刻的 gstime（弧度）
   function setEarthSpin(gmst) {
     if (!Number.isFinite(gmst)) return
     if (frameMode === 'inertial' && lastGmst != null) {
       const d = spinDelta(lastGmst, gmst)          // wrapToPi(gmst − lastGmst)，纯函数，见 §10
       if (d) { _q.setFromAxisAngle(ORB_AXIS, -d); camera.position.applyQuaternion(_q); controls.target.applyQuaternion(_q); inertia.cancel() /* 不取消也行，见 5.3 */ }
     }
     lastGmst = gmst
   }
   ```
   - 轴与符号**照抄轨道圈**：圈用 `setFromAxisAngle(ORB_AXIS, ref − now)`，相机每拍累加 `−(now − prev)`，两者同轴同号 → 惯性档下轨道圈相对屏幕静止（这就是 §11 A1 的判据；符号若写反，圈会以两倍速度反跑，一测就露）。
   - `controls.target` 恒为原点（`enablePan=false`），一并旋转只是为了通用。
   - 增量施加在 `holdFrames` 闸内（`refreshPositions` 里），与本拍星位同一帧上屏；`controls.update()` 每帧从 `camera.position` 重算球坐标，用户拖动的 `_sphericalDelta` 自然叠加，无需碰 OrbitControls 私有量。
   - **跳时刻**（拖游标 / 「跳到时刻」/ 「此刻」）：Δ 经 `wrapToPi`，跳 3 天不转三圈；惯性档下地球跳到该时刻朝向、相机不动——这是定义，不做平滑。
   - `lastGmst` 在「相机跟随」档也每拍记录，切到惯性档时不产生跳变。
   - 2D 视图期间 `scene` 已 `pause()`，`setEarthSpin` 照常改 `camera.position`（不出帧、开销可忽略），切回 3D 即正确。
3. `ConstellationMap3D.vue`：
   - `refreshPositions` 在 `applyTerminator()` 之后、`renderEntries.length` 早退之前加 `scene.setEarthSpin(sat.gstime(calcAt()))`（无星也要转；正常分支复用同一个 `gmst`，别算两遍）。
   - `watch(() => viewPrefs.frame, v => scene && scene.setFrameMode(v))`；scene 创建后与 `restoreSettings` 后各套一次。
   - 五处「聚焦 / 定位时关自转」的语句直接删：惯性档下定位一个地点之后地面随时间漂走是物理，不是要压掉的展示效果。
   - 侧栏 `.pchips` 那枚小标改为显示当前档名并点击切换：`{{ viewPrefs.frame === 'inertial' ? '惯性视角' : '相机跟随' }}`，`.on` 当且仅当惯性档。
   - 页面命令 `const.rotate` → **`const.frame`**：`label: '地球自转'`，`icon: 'rotate-cw'`，`check: viewPrefs.frame === 'inertial'`，`run: toggleFrame`；`cmdKeywords.js`：`'const.frame': ['rotate','spin','inertial','fixed','earth rotation','自转','惯性','跟随','地固']`。

## 6. 拖拽阻尼

### 6.1 目标手感（Google Earth / Cesium 口径）

1. **拖动中 1:1**：抓住的地面点跟着指针走，没有滞后。
2. **松手后有一段惯性滑行**，按时间指数衰减，快慢由「拖拽阻尼」决定，**与帧率无关**（30 / 60 / 不限 三档手感一致）。
3. 按下、滚轮、键盘方向键、搜索定位、恢复视图 → 立即终止滑行。

### 6.2 三处改动

**(a) 关掉 OrbitControls 的滞后滤波**：`controls.enableDamping = false`（删 `dampingFactor`）。拖动量在下一次 `update()` 全额生效。

**(b) 距离感知的旋转灵敏度**（治「贴地飞过」）：每帧在 `loop()` 里按当前相机距离 d（地球半径 = 1）更新
```
controls.rotateSpeed = rotateSpeedFor(d, fovDeg) = clamp( (d − 1) · tan(fov/2) / π , 0.005, 0.5 )
```
推导：屏幕中心处地面深度 d−1，每像素世界位移 `2(d−1)tan(fov/2)/H`，除以半径 1 即所需弧度；OrbitControls 每像素转 `2π·rotateSpeed/H`，两者相等得上式。d=3（默认距离）→ 0.244，满屏拖一次转 88°，地面恰好跟指针走；d=1.15 → 0.018；d ≥ 5.1 → 封顶 0.5（拉远后与现在逐位一致）。触控同一条路径。

**(c) 惯性滑行**：纯函数模块 `src/viz/globe3d/dragInertia.js`（§10），scene.js 接线：
- `controls.addEventListener('start', …)`：`inertia.begin()`（清样本、终止上一段滑行）；拖动期间每帧 `inertia.sample(now, controls.getAzimuthalAngle(), controls.getPolarAngle())`（θ 差要 `wrapToPi`）。
- `controls.addEventListener('end', …)`：`inertia.release(now)` → 用最近 ≤ 80 ms 的样本估角速度 (ωθ, ωφ)；样本不足或速度低于阈值则不滑。
- `loop()` 每帧：`const s = inertia.step(dt)`（dt = 本帧 now − 上一**出帧**的 now，钳到 ≤ 100 ms，与 `fpsCap` 跳帧、`frameHold` 停帧兼容）；`s` 非空时用 `rotateBy` 同款球坐标数学施加 `(s.dθ, s.dφ)`（φ 钳 `[1e-4, π−1e-4]`，触边把 ωφ 清零），再 `controls.update()`。
- 衰减：`ω(t+dt) = ω(t)·exp(−λ·dt)`；停止阈值 |ω| < 0.02°/s（0.00035 rad/s）。
- **阻尼百分比 → λ**（Cesium 形状，p 是设置里的 0–100）：
  ```
  p = 100      → 不滑行（λ = ∞）
  0 ≤ p < 100  → λ = max(0.5, 25 · p/100)   [1/s]
  ```
  参考点：p=10 ≈ Cesium 默认（inertiaSpin 0.9，λ=2.5，速度半衰期 0.28 s）；**p=50（出厂）λ=12.5，半衰期 55 ms**，一次 300°/s 的甩动滑约 24°，「有惯性但收得住」；p=0 λ=0.5，半衰期 1.4 s。
- `faceTo` / `rotateBy` / `setView` / `wheel` / `pointerdown` 里各加一行 `inertia.cancel()`。
- 现有 `updateRotate()`（按模式关 `enableRotate`）与标记 / 波束 / 标签 / 多边形拖拽路径不变。

### 6.3 设置

`viewPrefs.dragDamping: 50`；`scene.setDragDamping(p)`；设置窗滑块 0–100 步进 5，读数 `<em>{{ p }}%</em>`；`title`：「松手后滑行的衰减：100% 立即停住，0% 滑得最远」。

### 6.4 改版（2026-09-21 晚）：惯性滑行 → 粘滞跟随（仪器手感）

§6.1–6.3 按 Google Earth 口径落地后，用户实测「阻尼拉满后的效果仍然不够好，希望有专业仪器的感觉」。
根因是口径不对：拉满（p=100）＝无惯性＝生硬直连，而用户说的「阻尼」是阻尼铰链 / 液压云台那种
**粘滞感**——越大越重、停得越柔。已改为：

- 模型：相机球坐标以**一阶粘滞跟随**指针命令，`x' = (x* − x)/τ`。载体就是 OrbitControls 自己的
  damping 递推，但 `dampingFactor` 每帧按真实经过时间取 `1 − e^{−dt/τ}`（精确离散化，30 / 60 / 不限
  三档轨迹逐点相同）。相机只逼近、**永不越过**指针命令，松手后只把欠着的补完，**没有自由滑行**。
- 「拖拽阻尼」p → τ = 120 ms × (p/100)^1.5：p=0 直连；p=50（出厂）42 ms，以 90°/s 拖动时地面落后
  指针 3.8°，停手后 ≈150 ms 停稳，剩余角半衰期 29 ms；p=100 120 ms（最重，半衰期 83 ms）。
- ★ `dampingFactor` 帧间恒为 0，只在 loop 的 `update()` 前设成 f、用完归零：OrbitControls 在每个 pointermove /
  touchmove 里自己也 `update()` 一次，若那次也施加，拖动中的滞后只剩理论值一半、且随鼠标回报率变（验证台 A7
  抓出：实测 5.2° vs 期望 11.1°；归零后 11.07° vs 11.17°）。
- 交互期解除帧率上限：拖动中 / 跟随未停稳 / 缩放缓动中每个 rAF 都出帧，30 fps 省电档只管静止画面。
- 滚轮缩放缓动改按时间：τz = 84 ms（60 fps 下逐帧等于原来的 0.18，30 fps / 144 Hz 手感与之相同）。
- 代码：`viz/globe3d/dragFollow.js`（替代 `dragInertia.js`，含参考递推 `stepFollow`）+
  `packages/core/test/dragFollow.test.mjs`（27 条）；scene.js 的 `setDragDamping` 只改 τ；
  `faceTo / setView` 清掉未施加完的拖动命令（`clearFollow`）。验证台 A7 段整段重写。
- 设置窗 title 改为「拖动的粘滞感：0% 直连，越大越重、停得越柔；地面不会滑过光标」，词典同步。

## 7. 滚轮缩放比例（3D / 2D 各一档）

### 7.1 口径

**一格滚轮 = 底部状态栏缩放读数走 p 个百分点**（t 空间步进，p 出厂 3，范围 1–20，整数）。这条读数两张图各自 `t ∈ [0, 1.2]`，与 ± 按钮的 0.01 同一刻度。方向不变：滚轮向下（deltaY > 0）= 缩小 = t 减小。

滚轮事件归一为「格数」（纯函数 `wheelNotches(e)`，§10）：`deltaMode 0`（像素，Windows 标准鼠标一格 ±100）→ `deltaY/100`；`deltaMode 1`（行）→ `deltaY/3`；`deltaMode 2`（页）→ `deltaY`；平滑滚动 / 精密触控板把一格拆成多个小事件时按比例累加，最终仍是每 100 像素 = p 个百分点。`ctrlKey`（捏合）不在本次范围，照旧当普通滚轮。

### 7.2 接线

- 3D `scene.js` wheel 监听：
  ```js
  const t1 = stepZoomT(distToT(zoomTarget), wheelNotches(e), wheelPct, TMAX)   // clamp [0, TMAX]
  zoomTarget = tToDist(t1); reportZoom(); inertia.cancel()
  ```
  每帧缓动 0.18、`syncNear`、进度条回填全不动。`scene.setWheelStep(p)`。
- 2D `flatCoverage.js` `onWheel`：只把 `scale = clamp(scale·exp(−deltaY·0.0015), …)` 那一行换成 `scale = tToScale(stepZoomT(scaleToT(), wheelNotches(e), wheelPct, TMAX))`（`tToScale = t => exp(lnS0 + t·(lnS1−lnS0))`，与 `setZoomT` 同式），光标锚定的 `wx,wy → tx,ty`、`noteZoom()`、`requestDraw()`、`onZoom(scaleToT())` 逐字保留。`flat.setWheelStep(p)`。
- 页面：`viewPrefs.wheelStep3d: 3`、`wheelStep2d: 3`；scene 创建后、`ensureFlat()` 里、以及 `watch` 两个字段时各推一次。
- 设置窗两行：「3D 滚轮缩放」「2D 滚轮缩放」，滑块 1–20 步进 1，读数 `<em>{{ p }}%</em>`，`title`：「每滚一格，底部状态栏的缩放读数走多少个百分点」。

改造后出厂手感：3D 从每格 4.8 个百分点降到 3（略细），2D 从 3.6 降到 3（几乎不变）。用户觉得慢就在设置里拉大，这正是做成设置项的目的。
