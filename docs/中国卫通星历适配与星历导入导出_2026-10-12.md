# 中国卫通星历（.eph）适配 · 导入「新建 / 对应已有卫星」· 星历导出

2026-10-12。起因：用户给了一份中国卫通自己的高轨星历 `6C-20260930.eph`，要求查清格式并适配（要鲁棒）；
导入星历要能「新建卫星」或「对应某颗已有卫星」；不论星历是内置、自建还是导入的，都要能从星座功能里按
自定义星座 / 内置星座 / 卫星组 / 单星导出正确格式的星历，格式正确性与准确性优先。

---

## 1. 这是什么格式

**不是公开标准**（CCSDS OEM/OPM、STK .e、SP3、ModITC、MEME 都不是；公开资料查不到规范），是卫通测控系统
自用的文本报文。以下口径全部来自实物的逐字节分析：

| 项 | 实物 |
|---|---|
| 编码 / 行尾 | **GBK**（CP936，Windows 简体中文 ANSI）/ **CRLF**，末行后也有 CRLF |
| 第 1 行 | 49 个 `_` + 标题 + `_` 补齐到 104 字节；实物标题是 14 个 `%`（占位，不是星名） |
| 第 2 行 | 40 个空格 |
| 第 3 行 | 49 个 `_` + **地固坐标系瞬根**（GBK 14 字节）+ 41 个 `_` + 生成时刻（本地时 `yyyy/M/d H:mm:ss`） |
| 第 4 行 | 列头 `_______Time(UTC)_______________X___…___dZ___________`（下划线当分隔） |
| 数据行 | `yyyy/M/d H:mm:ss` + 6 列 X Y Z dX dY dZ；每列 = 两个空格 + 符号位（`-` 或空格）+ Delphi `ffExponent(15,4)` 体例（`-2.74261083105968E+0007`），行尾再两个空格 |
| 零点 | 整零点写成 `00:00:00`，且其后**只空一格**（10 处逐行核过；其余时刻 `H:mm:ss` 后空两格） |
| 单位 / 帧 | 位置 m、速度 m/s；**地固系**（瞬根 = 瞬时状态矢量），速度是相对旋转系的速度 |
| 步长 / 时段 | 60 s；2026-09-30 01:17 → 10-20 01:17 UTC（20 天，28794 行） |
| 机动 | 10-10 08:55:18 单独一行（机动开始）→ 600 s 后 09:05:18（机动结束）**该行原样重印一次**（弧段边界）→ 此后网格从 09:05:18 起每 60 s 一行（秒位从 :00 错到 :18）；末行落在整段终止时刻（步长 42 s） |

**数据本身的诊断**（解析不依赖它们）：

- 帧：位置二阶差分得加速度，与地固系动力学 `g − 2ω×v − ω×(ω×r)` 吻合到 1e-6 m/s²，与惯性系假设差四个量级。
- 机动：08:55:18 → 09:05:18 半长轴 42164.94 → 42163.87 km（Δa ≈ −1.07 km，Δv ≈ 0.04 m/s），倾角不变 —— **东西位保**。
- 速度比位置差分系统性偏东 ~5e-4 m/s（换算速度用的地球自转角速度与位置帧差 ~1.1e-11 rad/s）。
- UTC 零点前后位置有米级跳步（日更的 UT1−UTC 不内插所致）。
- 星下点 130.57°E → **中星 6C（ZHONGXING-6C，NORAD 44067，2019-012A）**。与 CelesTrak 根数（历元 10-07）比：历元附近
  差 2–5 km；机动后根数不知道这次机动，10-15 差 68 km、10-19 差 124 km —— 精密星历的价值正在于此。

## 2. 解析（`packages/core/utils/csEph.js`，格式 id `cs-eph`）

鲁棒性清单（每条都有测试，见 §7）：

- **编码**：读文件一律按字节读，`textCodec.decodeText` 认 BOM（UTF-8 / UTF-16LE/BE）→ 严格 UTF-8 → GB18030。
  原来 `fs.readFileSync(fp,'utf8')`：表头帧名读成 U+FFFD，**不报错、静默丢帧**。拖放也改成传字节。
- **表头**：可缺失（无表头时要求第一行起就是数据，免得把别的带日期的文本吞进来）；帧名认 地固 / 地心固连 / ECEF / ITRF /
  WGS-84 / CGCS2000（→ 地固）、J2000 / EME2000 / 历元平赤道 / ICRF / 惯性（→ J2000）、真赤道（→ TOD）、平赤道（→ MOD）、TEME；
  时标认 UTC / 北京时（−8 h）/ GPS / BDT / TAI / TT；列头按名认列（X Y Z dX… / VX… / X_DOT…，可带单位括号）。
- **数据行**：日期 `/ - .` 分隔、`T` 连接、小数秒；数值 Delphi `E+0007` / 常规科学计数 / 定点 / Fortran `D` 指数；
  分隔符空格 / Tab / 逗号 / 分号。坏行跳过并点名首个行号。
- **单位**：位置按 |r| 中位数判 km / m（近地轨道 6.3e3–2e6 km ⇔ 6.3e6–2e9 m，两段不重叠）；速度按**位置差分**标定
  （最小二乘比例吸附到 1e-3 / 1 / 1e3），与表头不符按差分为准并告警；残差以**惯性速度量级**计 > 1e-3 即判速度列不可信、
  退回位置插值（地固系里 GEO 的速度只有几 m/s，拿它当分母会把 SGP4 本身 1.6e-5 的速度—位置不自洽放大成假不一致）。
- **坐标系**：表头为准；表头缺失按动力学判；两者**强烈矛盾**（残差比两个量级以上）才推翻表头并告警。
- **整理**（`ephemNormalize.js`，与 STK / OEM 共用）：时刻乱序 → 稳定排序；同刻多行：状态相同 = 弧段边界（.eph 约定）、
  状态不同 = 脉冲间断，**两个状态都留**（后者顺延 1 ms，spans 拆段，插值不跨缝）；缺口按 Hermite 余项 `h⁴n⁴r/384` 估误差，
  > 1 km（无速度 50 m）才拆段——GEO 10 min 机动窗口估计 0.4 m，照常桥接；6 h 缺口估计 670 km，拆段。
- **变体**：「瞬时根数」列（a e i Ω ω M/ν）按二体换算成状态矢量；「平根」报文拒收（要源软件的平根理论）。
- **插值**：带速度用三次 Hermite（局部两点，天然不跨机动窗口），否则 Lagrange-8。

## 3. 写出

`serializeCsEph` 逐字节复刻上述版式（含零点那一格、机动重印行）；坐标系恒为地固（该报文唯一见过的帧，写别的帧等于发明格式），
GBK 编码由 `textCodec.encodeText(…,'gbk')` 完成（反查表由 `TextDecoder('gbk')` 现推，不引第三方依赖）。
**实测：实物解析后重写，4955489 字节逐字节一致**（复用原表头，或用同样的标题 / 生成时刻新生成表头，两种都一致）。

## 4. 导入：新建卫星 / 对应已有卫星

流程（星座栏「＋ → 导入星历文件…」、「文件」菜单、拖放、文件管理同一套）：主进程按字节读 → 认编码 → 解析 →
**逐星找候选** → 导入对话框里逐颗选「新建卫星」或「对应已有卫星」→ 提交。纯平均根数且干净的文件照旧一步落库。

- **候选**：按几何，不按名字。编目（active + 各命名组，含随包快照）与自定义库的根数用 SGP4 推到**各自的根数历元**
  （钳进星历时段：SGP4 在历元附近最准，统一取「此刻」会拿机动前的老根数硬比机动后的新轨道——中星 6C 实测历元处 2.3 km、
  机动后两天 27 km），与导入星历在 TEME 里比距离；别的导入点序列星在重叠时段中点比。平均运动 ±5% 粗筛省掉九成 SGP4。
  建议项：足够近（max(50 km, 0.2%·r)）且与次近者拉得开（3 倍）或名字也对得上（「6C」↔「ZHONGXING-6C」，中文族名
  中星 / 亚太 / 天链… 映射到编目英文写法）。中星 6C：本星 2.3 km，次近的同轨位邻星 328 km。「其它卫星…」可在全量目录里挑任意一颗。
- **对应 = 叠加星历**：外部星历不另立一颗星，而是挂到目标星（按 NORAD）身上。取位时**新导入的叠加表优先**，逐张查，
  落在谁的时段内用谁，都不在才回落本体（SGP4 / 本体点序列）。时段外不消失、照常走 SGP4。
  - core：`orbitPos.setOverlayResolver`（主进程 customSats 注入「NORAD → 表」），全部引擎（NGSO / 再生 / 端到端 / 可见性 /
    CI 时变 / 日凌 orbitSource）都经 `orbitPos.positionAt`，自动生效；CI 与日凌原先直调 `propagate`，已改走 orbitPos（无叠加时逐位不变）。
  - 渲染端：`satPos.setOverlays`（3D 页与模型工作台各灌一份）；聚焦几何 Worker 没有注册表，发 satrec 前 `stampOverlays` 打戳随克隆过去；
    导入组里被对应的星条目顶目标星的身份，渲染集里换成全量池里那颗本尊（同一颗星在各集里是同一个对象，选中 / 跟随才认得出）。
  - 信息栏「实时状态」多一行「星历」：此刻由叠加星历供位时报来源组；悬停看格式与时段。
  - 改对应：导入组菜单「对应已有卫星…」（同一个对话框，候选同一套）/「取消对应」；文件管理「对应…」。不许对应到自身。
- **存储**：组清单 `custom.json` 的星多一个 `bind:{noradId,name}`；采样仍按 TEME 存，另存**原帧原值**（`src`，TEME 来回会动
  15 位有效数字的末位——实测约三成数值）与 .eph 的原表头（`fmt`）；导入原文另存 `ephem/<组>.src`（≤ 64 MB）。删组一并删。

## 5. 导出

入口：星座栏任一集（内置星座 / 卫星组 / 导入组 / 自定义星座 / 卫星天线树 / 搜索结果）菜单「导出星历…」、展开成员表勾选后「导出」、
右侧信息栏导出钮（聚焦集）、文件管理的导入组 / 自建星座「导出」。引擎在主进程 `electron/services/ephemExport.js`。

| 格式 | 写得出的星 | 要点 |
|---|---|---|
| OMM CSV / JSON / KVN / XML | 平均根数星（编目 / 自定义库 / 自建星座 / 天线树根数星） | 记录按来源找回**带全部官方字段**的原记录（同号同历元才认）：编目星整行等于源 CSV；整个内置组 CSV 且没剔星时吐缓存原文 |
| TLE / 3LE | 同上，编号 ≤ 339999（Alpha-5） | 超限的星跳过并点名（自建星座 900000 段写不进去）；校验位按规范 |
| CCSDS OEM（KVN / XML） | 全部 | 头 / 每星一块 / 尾三段，多星可一个文件（每星若干段）或一星一个文件；KVN 只写 ASCII（ORIGINATOR `SATSIM`，中文星名退到 OBJECT_ID） |
| STK .e | 全部，一星一个文件 | 段界写 `SegmentBoundaryTimes` + 同刻两行（空行隔开，规范惯例）；Hermite 的 `InterpolationSamplesM1` = 点数 − 1（阶 = 2×它+1） |
| 中国卫通 .eph | 全部，一星一个文件 | 恒地固系、GBK、CRLF；同源原值导出复用原表头、子集也是原文的逐行子集 |

- 平均根数星 / 定点星在 [起, 止] 上按步长采样（末点补到终止时刻，与卫通体例一致）；点序列星缺省导**原始采样点**（时段内的原点，
  数值逐位等于导入时），也可等间隔重采样。
- 挂了叠加星历的星，导出点与平台此刻取位逐位同口径；源切换处（进 / 出叠加时段、表内机动断点）补一对边界状态并拆段
  （OEM 分段 / STK SegmentBoundaryTimes / .eph 同刻两行）。实测：中星 6C 的编目星导 OEM，SGP4 / 精密 / 精密 / SGP4 四段，
  段界正好落在星历起止与机动结束时刻。
- **逐字节**：整组导出、同格式、原始采样、时段盖住整组、原帧 → 直接写导入原文（对话框读数显示「原文」）。
- 大批量：逐星算逐星写盘，每 30 ms 让一次事件循环，进度回推、可停止。

## 6. 精度口径（诚实的那一版）

- 地固 ↔ TEME 只用 GMST（平台既有口径，与 `satellite.js eciToEcf` 逐位同式），**地固源来回逐位还原**——卫通 .eph 是地固源，
  平台里的星下点、仰角、斜距就是原文件的地固坐标。
- 惯性 ↔ 地固换算不含 ΔUT1 与极移（`frames.js` 头注的既有口径）：J2000 源导成地固格式（或反之）GEO 上是百米量级；
  要米级须引入 IERS EOP，届时只改 `frames.js`。
- 插值：60 s 采样 + 600 s 机动缺口（合成 GEO）< 1 m；SGP4 自身速度不是位置的精确导数（GEO 0.05 m/s），Hermite 由此引入 < 1 m。

## 7. 顺手修掉的既有问题

1. STK `.e` 的 `SegmentBoundaryTimes` 原先整块被忽略、段界处的第二个状态被当重复点剔掉 → 现在两侧状态都留、按段界拆段。
2. 多段 OEM「下一段 START_TIME = 上一段 STOP_TIME」（机动星历的常见写法）：原先直接拼数组，机动后的状态被当重复时刻剔掉，
   **段缝后面整整一个步长取不到位置** → 现在走同一套整理，两个状态都留。
3. 插值器（core 与渲染端两份同步改）：查询时刻恰好落在下一段首点（与上一段末点只差 1 ms）时，原先落回上一段末点。
4. OEM KVN 的 ORIGINATOR 原写中文「卫星仿真平台」（KVN 只许可打印 ASCII）→ `SATSIM`。
5. 多星点序列组导 STK .e 原先只写第一颗 → 单目标格式一星一个文件。
