## 4. 引擎改造（`sunOutageCalculator.js`）

### 4.1 星历档（`params.orbit`）

- 入参：`params.orbit`（`buildSatrec` 的 spec，见 §3）；给了 `orbit` 就走星历档，否则照旧走 `satLon`。两者都给以 `orbit` 为准。
- 轨道源：引擎**不直接建 satrec**，经 §12 的 `orbitSource(spec)` 拿到 `{ posEcefKm(ms), summary, span, lonAt(ms) }`（本期只有 SGP4 一种实现，内部才用 `require('./ngsoGeometry.js').buildSatrec(spec)`）。区制守卫用 `summary.periodMin`：`|periodMin − 1436.07| > 28.72` → 返回 `{ error: true, message: '非地球同步轨道，日凌预报只支持 GSO' }`（与 `orbitClass.js` 的 GSO 容差同一数）。
- **卫星轨迹表 `SatTrack`**（星历档的核心，也是批量提速的关键）：一个按 `dayJD` 记忆化的对象，两级采样：
  - `coarse(dayJD)`：每 10 min 一点（145 点），`src.posEcefKm(ms)`，km；`ms = (jd − 2440587.5) × 86400e3`（UT）。SGP4 实现里就是 `sat.propagate(rec, new Date(ms))` → `sat.eciToEcf(pos, sat.gstime(date))`。
  - `fine(dayJD)`：每 60 s 一点（1441 点），同法。
  - 任一采样点返回 `null`（超出星历覆盖区间 / 传播失败）→ 该天记为「无星历」跳过，不计入 `coverageDays`（§4.3）；SGP4 实现永不返回 null（区间无限）。
  - 逐秒取值 = 相邻两个 60 s 采样点的线性插值（倾角 15° 的 GSO 在 60 s 内的弦垂 ≈ 9 m，从 38 000 km 外看 ≈ 1.4e-5°，远小于求根容差对应的太阳位移 0.002°）。**不许逐秒 propagate。**
  - 缓存对象经第二参数 `ctx.satTrack`（`Map`，键 = `JSON.stringify(orbit)`）传入，批量里所有站共用同一颗星的轨迹；`ctx.orbitSource`（已建好的轨道源）同理，批量里一颗星只建一次；单次调用没传 `ctx` 就自己建。轨迹与站无关，一颗星一季只算一次。
- 逐日预筛（星历档）：站→星单位向量的赤纬 `asin(u.z)` 在当天 coarse 采样上取 min / max，把现有判据 `|δ_sun − δ_sat| > θ_th + 0.05°` 改成对区间判：`decLo_sun − decHi_sat > θ_th + margin` 或 `decHi_sun − decLo_sat < −(θ_th + margin)` 跳过，`margin = 0.05° + inclDeg × (2π / 1436.07) × 5`（10 min 采样两点之间赤纬最多走的量；`inclDeg = summary.inclDeg`）。
- 事件函数：`fDay(s)` 里 `satU` 改为随秒取值（fine 表插值后归一化），其余（`sunUp`、`findWindows(…, { coarseStep: 15, tol: 0.5 })`、峰值取法）不变。
- 汇总量：`satAz / satEl / satLonEff` 取**分点日正午（UT）**那一拍（`src.lonAt(ms)` 给经度）；`el ≤ 0` 报同一条「卫星在地平线以下」错误。逐日记录可加 `satLon`（峰值时刻星下点经度，3 位小数），可选。
- 定轨档：`satU` 仍是常量，代码路径**一个字节都别动**（金标准逐位对拍的就是它）。用 `if (orbit)` 分岔，而不是把常量路径也改成「插值表」。

### 4.2 纯几何档（`params.criterion`）

- `params.criterion`：`'degradation'`（缺省，现状）| `'geometric'`。
- `outageModel(...)` 加一参 `criterion`：几何档 `thetaTh = thetaB`（恒 > 0，不做 `dTth < dTmax` 那道判断）；其余量（`dTmax / dTth / Tb`）照算，`degradationAt` 照用——`peakCNdeg` 列在两档下都是同一个物理量。
- 返回 `model.criterion`、`model.thresholdAngleSource: 'degradation' | 'beamwidth'`；`thresholdAngle`（分点日门限角）几何档 ≡ `beamWidth`；每日 `thresholdDeg` 亦然。
- `degThreshold` 在几何档下不参与定窗，但仍回显在 `model.degThreshold`（原样透传，别清零）。

### 4.3 分点与批量

## 12. 与「星历导入」设计的接口约定

另一份设计（2026-09-21 对照 STK「Insert Satellite」的差距分析，尚未实施）要新增一种传播类型 **`ephem`**（STK .e / CCSDS OEM / SP3 的时间标签状态矢量，插值而非 SGP4），可能还有年历（YUMA / SEM → 既有 `elements` 类型，日凌零改动）与 SATCAT 筛选接进搜索池。本任务**不实现 `ephem`**，但把缝留好，将来接入时日凌引擎与窗口不再改动，只补 §5 的 `ref` 解析。

1. **轨道源接口**（新建 `packages/core/utils/orbitSource.js`，CJS；引擎只认它，不认 satrec）：

```
orbitSource(spec) → {
  kind: 'sgp4' | 'ephem',
  summary: { periodMin, inclDeg, ecc, epochIso },   // 区制守卫 / 预筛 margin / 历元读数只看这里
  span: null | { startMs, endMs },                   // null = 无限期（SGP4）
  posEcefKm(ms) → [x, y, z] | null,                  // ECEF（WGS84）km；null = 区间外 / 传播失败
  lonAt(ms) → deg | NaN                              // 星下点经度，°E 正
}
```

   本期只实现 `sgp4`：`ngsoGeometry.buildSatrec(spec)` 建 satrec（`buildSatrec` 本身不动），`summary` 取 `2π / rec.no`、`rec.inclo / RAD`、`rec.ecco`、`rec.jdsatepoch`；`posEcefKm` = `propagate → eciToEcf(gstime)`；`lonAt` = `eciToGeodetic`。坐标系转换（TEME / J2000 / ICRF / Fixed → ECEF）是各实现自己的事，引擎只吃 ECEF。
2. **覆盖区间**：引擎按 §4.1 处理 `null` 采样，回 `coverageDays` 与 `model.ephemSpan`（§4.3）；界面读数行按 §6.3 的分支先写好。日凌只看分点前后各 30 天，飞控给的短期星历恰好是这一段——这条缝是给你自己卫星的精密星历留的。
3. **取星单一出口**：`src/ngso/satSearchPool.js` 新增 `orbitSpecOf(rec)`（`omm` → 13 字段纯拷贝；`elements` → 六根数；其它类型抛「未知轨道类型」）与 `slotLonOf(rec)`（记录自带 `summary.lonDeg` 时优先用它；`omm` → `geoLonAtEpoch(omm2satrec)`；`elements` → 按 `buildSatrec` 同一换算造 OMM 记录再 `geoLonAtEpoch`，做到不抛错即可）。将来 `ephem` 池记录只要带 `incl / meanMotion / ecc` 摘要字段（供 `classifyOrbit` 与本窗口的 GEO / IGSO 过滤）和 `summary.lonDeg`，日凌搜索就直接可见、可选——这一条要写进星历导入那份设计的池记录契约。
4. **配置存法**：§6.6 的 4 KB 内嵌 / 引用两档；引用形状 `{ type: 'ephem', ref: { groupId, satId } }`（自定义卫星库的导入组 id + 星 id），解析放主进程 `resolveOrbitSpec`（§5），渲染端不搬星历正文过 IPC。
5. **「刷新星历」**只对 `omm` 显示（按 NORAD 回池重取）；`ephem` 没有「刷新」，只有重新导入。
6. **来源标签三档**：定轨 / 星历（OMM 历元）/ 星历文件（覆盖区间）——Word 参数表、Excel 表题、读数行共用 `sunParams.js` 的 `SAT_SOURCE_LABEL`。
7. **顺序与冲突**：两份工作都会碰 `satSearchPool.js`、`customSats.js`、`ngsoGeometry.js` 一带。本任务先落地并留缝，星历导入随后往缝里插 `ephem`；**不要开两个会话并行改这几处**。
