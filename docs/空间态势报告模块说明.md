# 空间态势报告模块说明

模块 id `ssa`。2026-09-16 立项并实现。本文写给下一次维护的人：数据从哪来、报告里每个数按什么口径算、
哪些事刻意没做。界面上的口径说明只在 `title` 里（仓库 CLAUDE.md 规矩），完整定义在这里和报告的
「口径与判据」一节。

---

## 1. 一句话

从 CelesTrak 取**卫星编目 SATCAT**（全部空间目标的所有者 / 类型 / 状态 / 发射与陨落日期 / 轨道概要）
和平台已有的 **GP 星历**（17 个星座组 + `active` 全部在轨），在软件内生成一份可翻阅的电子报告，
可导出 Word。

报告**只有表、图、口径**，没有「态势评价 / 结论」段 —— 判定留给看报告的人。

### 统计范围 = 报告主体 + 四道筛选

界面上这两层在检查器的**同一个区**里（分区名「范围」），上层定报告长什么样、下面四行定统计谁。
2026-09-17 之前它们是两个区（「范围」与「范围筛选」）、功能区里还有重复的第三处，同一个词三处所指不同。

**报告主体**二选一，决定报告的**结构**（分段控件，两档同时在屏上）：

| 报告主体 | 报告长什么样 |
|---|---|
| 全量编目 | 8 章通用统计（总览 / 区制 / 所有者 / 发射陨落 / 星座部署 / GEO 弧 / 星历时效 / 附录） |
| 卫星组 | 每个组一章（概况 / 成员表 / 轨道分布 / 变化 / GEO 成员），可多选，组来自星座页的「卫星组」 |

**筛选**四道，决定报告**统计哪一批对象**，可叠加（交集），两种主体下都生效。
典型星座 / 所有者取值多，走「按钮 + 浮层多选」；轨道区制 / 对象类型只有四到六档，整行铺成芯片，
每行排头一枚「不限」芯片：没筛时亮的就是它（芯片全灭与全选在屏上分不出），点它＝这一维归零。
分区标题右端的「清空筛选」只在真筛了东西时出现，清的是四道筛选，不动报告主体与卫星组。

| 筛选 | 取值 | 判据 |
|---|---|---|
| 典型星座 | Starlink / OneWeb / Kuiper / 千帆 / 中国星网 / 铱星 / Globalstar / Planet / Spire / O3b / GPS / 北斗 / Galileo / GLONASS | `CONST_PATTERNS` 名称前缀，**近似归类** |
| 所有者 | SATCAT 的 OWNER 代码（136 个） | 字段精确匹配 |
| 轨道区制 | GEO / IGSO / MEO / LEO / HEO / —（判不出） | `classifyOrbit` 的结果 |
| 对象类型 | 载荷 / 火箭体 / 碎片 / 未知 | OBJECT_TYPE 字段 |

同一维多值是**并集**，不同维之间是**交集**：选「轨道区制 = GEO」+「所有者 = PRC」出的是中国的 GEO 资产。

★ 筛选在 `buildSsaModel` 里**一次性切好**，往下所有统计吃的都是切过的那份 —— 别在各章里各筛各的，
那样第 2 章与第 4 章的合计就会对不上（单测里有一条断言专门钉这个：筛过之后「编目总览」的合计
必须等于第 1 章的「本报告统计条数」）。

★ **区制筛选生效时，判不出区制的对象（记「—」）一律落选** —— 它们不是「不属于这些区制」，
而是根数为空判不出来。想单看这批，显式选「—」。这条写进了报告的「口径与判据」。

★ GP 星历只按**星座名前缀**筛（星历里没有所有者与类型这两列）。卫星组报告的成员表用的是
**全量**编目索引，因为得能查到「本次被筛掉的那颗是什么」，否则会误报成「编目查无此号」。

筛选生效时，报告第 1 章多出「筛选条件」一块（逐维列出）与「本报告统计条数 = 筛后 / 总数」一行，
附录的「口径与判据」多出「筛选条件」一类；报告名与文件名带上筛选摘要
（如「中国 载荷 空间态势报告」/ `空间态势报告_中国_载荷_20260916`）。不筛就一条都不出。

### 检查器四区（2026-10-16 重排）

按「要回答的问题」排，**只列当前报告里真起作用的参数**：

| 区 | 行 | 说明 |
|---|---|---|
| 范围 | 报告主体 · 卫星组 · 典型星座 · 所有者 · 轨道区制 · 对象类型 | 见上 |
| 时间 | 基准时刻 [生成时 \| 指定] · 显示时区 · 近期窗口「近 [30] 天」 | 指定档下一行给 datetime-local 时刻框 |
| 章节 | 九个章节开关；「发射与陨落」下挂「逐月统计 近 [24] 个月」，「GEO 带」下挂「重点弧段 [60]°E 至 [150]°E」 | 仅全量编目；章关掉其下参数跟着收起 |
| 表格 | 全量：排名条数「前 [15] 位」；卫星组：成员表行数「最多 [500] 行」 | |

- 参数读成一句话（「近 / 前 / 最多 / 至」在框前，单位在框后），字段口径只在悬停 `title` 里。
- 「报告名称」一行删了：封面上就地可改，同一个值放两处只会让人以为是两样东西。
- 报告「数据与方法 → 报告基准」里的参数行与检查器**同名**（近期窗口 / 逐月统计 / 排名条数 / GEO 重点弧段 / 成员表行数上限），
  同样只列本报告用上的那几项。
- 旧名对照：近期明细 → 近期窗口；所有者榜 → 排名条数（它同时管所有者、碎片母体、GEO 拥挤轨位三张排名表）；
  逐月序列 → 逐月统计；大表行数 → 成员表行数（它只在卫星组报告的成员表上生效，全量报告里改它什么都不变）。

## 2. 数据链路

### 2.1 SATCAT 与 GP 走同一条四级众包链路

```
                      ┌────────────────────────────────────────────┐
  satcat:csv(opts) ──▶│ electron/services/omm.js  fetchCsv(key)    │
  omm:csv(key,opts) ─▶│  key ∈ {17 个 GP 组, 'active', 'satcat'}   │
                      └───────────────────┬────────────────────────┘
                                          │
      ① 当日本地缓存  <userData>/data/omm/csv_<key>.csv  写于今天 → 直接用，不联网
                                          │ 否则
      ② CelesTrak 直连  GP: gp.php?GROUP=… （主端点 3 次 → 补充端点 2 次）
                        SATCAT: pub/satcat.csv（无补充端点）
                        成功 → 落盘 + best-effort 回传云镜像 ommCloud.maybeUpload
                                          │ 失败 / 今天已试过 / 熔断
      ③ 腾讯云 COS 众包镜像  omm/csv_<key>.csv.gz
                        闸门：云端那份不比本地最优的新就不下载
                                          │ 失败
      ④ 本地回落  用户旧缓存 与 随安装包内置快照 resources/omm/csv_<key>.csv.gz
                        两者取【更新的一版】（offlineBest）
```

**众包的含义**：不建服务器、不加定时任务。每天第一个直连成功的用户把新数据回传 COS，
其余用户（含被墙的）从镜像取。`maybeUpload` 自带 6 小时新鲜度闸门，403 后整个会话不再回传。

SATCAT 在 `omm.js` 里是 `DATASETS` 的一条：
```js
const DATASETS = { satcat: { url: 'https://celestrak.org/pub/satcat.csv', label: 'SATCAT 卫星编目', valid: validSatcat } }
```
`known(k)` / `csvUrl(k)` / `validOf(k)` / `GL(k)` 按它分流，**17 个 GP 组的 URL、判据、缓存文件名、
日志措辞、返回形状一律未动** —— 加的是「第二种数据集」，不是改造。

### 2.2 有效性判据 `validSatcat`（`packages/core/utils/satcatValid.js`）

三条同时满足才认这份文本是 SATCAT：
1. 首行含 `NORAD_CAT_ID` / `OBJECT_TYPE` / `OPS_STATUS_CODE` / `LAUNCH_DATE` / `DECAY_DATE`；
2. 数据行 ≥ 50000（2026-09 实测 70,667）；
3. 最后一条非空行恰好拆出 17 列 —— **防截断**：半份 CSV 的前面部分完全合法，只有尾行能揭穿它。

一份实现三处引（omm.js 的 CJS、fetch-omm-snapshot.mjs 的 ESM、测试），别抄第二份。

### 2.3 代码表不走网络

`src/shared/satcatCodes.js` 是**生成物**（`scripts/build-satcat-codes.mjs` 抓 CelesTrak 三张页生成），
提交进仓库、随安装包走。代码表一年动不了几次，而每次生成报告都要把上万行的代码翻成名字 ——
那是查表不是取数。改名 / 补漏收的代码改生成脚本再重跑，别手改生成物。

★ 上游 `sources.php` 2026-09-16 实测漏收 4 个实际在用的所有者代码（JOR / KWT / SVK / UGA），
在生成脚本的 `MANUAL_OWNER` 里补齐；`satcatCodes.test.mjs` 扫内置快照，**未命中必须为 0**。

★ 主权口径与平台一致（`src/viz/globe3d/data/frozen.js` 的台港澳红线）：涉台港澳的代码中文名
一律「中国台湾 / 中国香港 / 中国澳门」，英文 `Taiwan, China` 等。统计仍按 SATCAT 原代码分行，
不合并、不改数。

### 2.4 联网永不阻塞界面

与 3D 页同一口径：先用本机（当日缓存 / 旧缓存 / 内置快照）即时出报告，联网那一版在后台跑完
再刷新读数。**已生成的报告不自动重排**，只把读数变成「数据 10:12 · 报告 09:37」，用户自己决定
要不要重新生成。用户点「刷新」才 `force`。

## 3. 报告章节

### 全量（`scope = all`）

★ 2026-10-15 二期重排（`docs/空间态势报告优化方案_2026-10-15.md` §3）：先结论、再方法、后分项。
章 key `regime` / `epoch` 已删，新增 `summary` / `debris`；老存档里的旧键读到即忽略。

| 章 | 表 | 图 | 来源 |
|---|---|---|---|
| 1 关键指标 | `kpi` 块：编目 / 本年至今与去年同期 / 近 N 天 / GEO 带 / 星历五组读数（已格式化串） | — | SATCAT + GP |
| 2 数据与方法 | 数据时间 · 来源 · 条数；筛选条件；报告基准；星历历元龄与在轨覆盖率表 | — | — |

| 7 大型星座 | 每星座（只数载荷）：累计发射 / 在轨 / 活跃 / 近 N 天 / 近 365 天 / 累计陨落 / 星历颗数 / 主壳层 ×3 | — | SATCAT + GP |
| 8 GEO 带 | 编目 / 有星历 / 定点解算三行对账；10° 经度段 36 行；共位簇（≥ 3 颗）；重点弧段清单 | 经度占用条带 | GP + SATCAT |
| 附录（不编号） | 口径与判据（四列，占表号）；本报告出现过的代码表 | — | — |

**筛选感知**（`ssaReport.skipSec`）：只筛一家所有者 → 无所有者章；类型筛里没有碎片 → 无碎片章；
类型筛里没有载荷 → 无星座章；区制筛里没有 GEO → 无 GEO 章。整章不出的不占章号，它登记过的图一并撤掉。

**改设置即重出**（`SsaApp.generate({ live: true })`）：决定内容的设置签名一变，350 ms 防抖后重出，
旧文档留在屏上直到新的一份排好，按当前章锚住阅读位置；生成中再改就排队。功能区「生成」按钮已删。
数据到达仍不自动换数，状态栏「报告 · 数据」读数可点。

**「口径与判据」是四列表**（类别 / 项 / 判据 / 数据来源），不是一张平表：原先把「SATCAT 的字段规则」
「由根数算出来的量」「按名称猜的归类」「随设置变的窗口」混在一起，读者没法判断哪条是编目自带的事实、
哪条是本平台算的、哪条只是近似 —— 而这恰恰是拿这份报告对外说话时最先被问到的。类别按
「对象状态 → 对象属性 → 轨道 → 时间 → 归类方法 →（筛选条件）」排，来源分
`SATCAT 字段 / GP 星历 / GP 优先缺则 SATCAT / 由根数算出 / 名称近似 / 报告设置 / 卫星组存档` 七档。

★ 2026-09-17 这张表做了两件事：**判据格逐条精简**（只留「怎么算的」——字段名、阈值、集合、公式、
单位、边界一个不少，讲动机的从句全删；原先「区制判定」尾部的 e / a 求法拆成自己一行），以及
**从 `note` 块升格成正式 `table`**，跟第 7 章 GEO 那几张同一副骨架、占表号「表 N」。
`note` 这个块型随之删除（它本来只有这一个使用者），屏上与 Word 两端的分支一并清掉；
附录里紧随其后的代码表号顺延 +1，第 1–8 章的表号一个不动。
屏上这张表按 `tableId` 认（`/\.criteria$/`）：判据列要折行（`.ssa-wrap`，其余三线表逐格 `nowrap`），
且无论多少行都不许翻进 ExcelGrid（那条路不认 `widths` 且逐格 `nowrap`）。

### 卫星组（`scope = groups`，每组一章）

| 节 | 内容 |
|---|---|

| G.2 成员表 | 名称 · NORAD · 国际编号 · 所有者 · 发射日期 · 在轨天数 · 状态 · 类型 · 区制 · 近 / 远地点 · 倾角 · 周期 · RAAN · 历元 · 历元龄 · RCS · GEO 定点 · 来源 |

## 4. 判据

| 项 | 判据 |
|---|---|
| 在轨 | `DECAY_DATE` 为空 且 `ORBIT_TYPE ∈ {ORB, DOC}` 且轨道中心为地球（`EA` 或数字 = 停靠母体） |
| 已陨落 | `DECAY_DATE` 非空 或 `ORBIT_TYPE = IMP`，且轨道中心为地球 |
| 深空 / 着陆 | `ORBIT_CENTER ≠ EA` 且非数字，或 `ORBIT_TYPE ∈ {LAN, R/T}`：**单独计数，不进区制与所有者表** |
| 活跃载荷 | `OBJECT_TYPE = PAY` 且 `OPS_STATUS_CODE ∈ {+, P, B, S, X}` |
| 区制 | `src/shared/orbitClass.js` 的 `classifyOrbit`。SATCAT 行：e =(APOGEE − PERIGEE)/(APOGEE + PERIGEE + 2Re)、a 由 PERIOD 反推；根数为空 → `—` |
| 近 N 天 | `LAUNCH_DATE / DECAY_DATE ≥ asOf − N 天`（按 UTC 日历日） |
| 在轨龄 | asOf − LAUNCH_DATE（天） |
| 历元龄 | asOf − GP EPOCH（天） |
| GEO 定点 | 历元处 SGP4 一拍的星下点经度（`src/shared/geoSlot.js`），°E 正 °W 负 |
| 共位 | GEO 定点经度按升序相邻差 ≤ 0.2° 的连通分量，≥ 2 颗 |
| 轨道面估计 | 折叠倾角 1° 分壳；壳内 RAAN 环形排序，相邻差 > 4° 处切分 |
| 星座名称模式 | `ssaStats.js` 顶部的 `CONST_PATTERNS`，**以名称前缀近似，与 CelesTrak GROUP 不完全等价** |
| 成员四类 | 在最新星历中 / 不在星历但 SATCAT 未陨落（`missAt`）/ SATCAT 已陨落 / 编目查无此号 |

三条口径上的话要说在前头：

- **在轨 ≠ 活跃**。编目里在轨的三万多个对象里，碎片与火箭体占一大半；「活跃载荷」才是那个
  通常被叫作「在轨卫星数」的数。两个数报告里都给，别混用。
- **所有者 ≠ 注册国**。SATCAT 的 OWNER 是 CelesTrak 按运营主体给的代码，与 ITU 申报国、
  《外空物体登记公约》的登记国都不是一回事。
- **轨道量优先取 GP**。成员表的近 / 远地点、倾角、周期优先按历元处根数换算（a 由平均运动、
  近远地点 = a(1∓e) − Re），无 GP 才退 SATCAT 的整数千米值；来源列注明 `GP` / `SATCAT`。

| 测试 | `packages/core/test/satcatCodes.test.mjs` · `ssaStats.test.mjs` · `ssaChart.test.mjs` · `ssaDocx.test.mjs` · `ommCacheFirst.test.mjs`（加了 satcat 断言） |

## 5b. 几处容易改错的口径

- **配置的出厂名 = 报告名 + 存盘时刻**（「中国 载荷 空间态势报告 09-16 23:40」），不走
  `lbAutoName.newCfgName()` 的序号名。这里一份配置就是「一份报告的出法」，范围与筛选一变报告
  就换了个东西，序号名（配置 1 / 配置 2…）在列表里全长一个样，隔天自己都认不出来。
- **GEO 弧段两头不对调**。经度是个环：`[150, −150]` 说的是跨 180° 接缝那段 60° 宽的太平洋弧，
  对调成 `[−150, 150]` 就成了它 300° 宽的补集。`ssaStats.inArc` 与 `ssaChartSvg` 的 `drawStrip`
  都按 `from > to = 跨接缝` 解释，界面只做夹取不做对调 —— 三处必须同口径。
  输入框右侧的 `°E` / `°W` 角标按当前值现算，0 与 180 都归东经（与报告里 `fmtLonEdge` 同口径）。
- **报告抬头五项随配置存，屏上就地改**（2026-10-15）：标题＝`state.name`（检查器里的「报告名称」一行 2026-10-16 删了），
  编号 / 密级 / 编制单位 / 日期＝`state.head`。屏上抬头每一项就是一个输入框（`SsaDoc` 的 `head` prop，
  Enter / 失焦提交、Esc 撤回），导出对话框的五个框是同一份的另一处编辑口（`head` prop + `head` 事件），
  两处改的是一个值。抬头**不进 `curSig`**：改了直接上屏、不亮「输入已变」、不必重出；`docHead` 的 watch
  把它就地写进 `model.doc`，导出深拷的就是那份。标题 / 日期清空＝自动（标题按生成那一刻的范围拼、
  日期取生成时刻在显示时区下的那天）。旧窗口级键 `ssa/report/doc` 改作「上次填的密级 / 单位」给新建配置预填、
  并给没有 `head` 的老配置补齐；`ssa/report/title` 迁进当时打开的那份配置后删除。
  之前的毛病：抬头只在导出对话框里改得了、改完要重新「生成」才上屏，日期还被对话框打开那天钉死落盘。
- **版式按 `docs/空间态势报告样式规范_2026-10-15.md`**（2026-10-16 落地）。改版式前先读那份规范的实施记录。要点：
  · 屏上纸面（`SsaDoc.vue` 的 `.ssa-sheet`）恒浅色，纸根把 `--bg / --text / --border …` 就地改成浅色档，纸内嵌套件跟着浅；
    纸宽 794 px × s，s = 数据区字号 / 11 且不超过中栏能放下（ResizeObserver + 盯 `<html>` 的 style）；不用 CSS zoom。
  · 图：模型 `figures[id].mm` 给成图物理尺寸（std 160×80 / tall 160×110 / flat 160×50 mm），屏上与导出都走
    `chartSvg(spec, { theme: 'paper', widthMm, heightMm, scale })`，导出 scale 1 再 ×6.25 栅格化（600 dpi），Word 里按 mm 原尺寸放。
    对象类型色跟 `series.key`（类型码）走：PAY #15619B / R/B #D8960E / DEB #B8333D / UNK #B7B7B7，混合量石板墨 #4A5560。
  · 表号 / 图号【按章编】：正文「表 3-2」、附录「表 A1」、组章「表 G1-2」、英文「Table 3.2」；关键指标页不编号不占章号。
    两端各数各的：屏上 `SsaDoc.vue` 的 `chapterNo(s, ++tno)` 与 Word 的 `chapterNo(sec, ++ctr.t)`，`ssaDocx.test` 的 `screenNumbers()` 是裁判。
  · 表格读数格式化只在渲染端：`src/shared/ssaFormat.js`（屏上）与 `reportSsaStyle.formatColumns`（Word）是【手写双份】，测试对拍。
    整张表有 ≥ 10000 的数时 ≥ 1000 的一并细空（U+2009）分组；负号 U+2212；`blankCols` 的空串印空白。
  · Word：`reportSsaStyle.planTable` 按内容量列宽，文字列可折行（每列 ≥ 18 mm），放不下降 8 pt 密排，还放不下切横向节；
    ★ 横向节不用 kit 的 `sectPage`（它先对调宽高、docx 9 又对调一次，落盘仍是纵向尺寸），用 `reportSsaDocx` 自己的。
  · 附录拆 A 口径与判据 / B 代码表 / C 参考文献（`appendix: true`，章 key `appendix` / `appendix-b` / `appendix-c`，检查器里仍是一个开关）。
  · 块型五种：kv / table / figure / kpi / refs。表块可带 `headGroups` / `rowRoles` / `blankCols`。
- **台标只进 Word 页眉，屏上封面不画**（2026-10-16 撤）：屏上没有页眉，画在封面上像凭空冒出来的。
- **台标（logo）是全局键 `lb/report/logo`**，与链路预算三窗共用一枚 —— 它是一家单位的东西，
  不该按窗口各存一份。对话框里的「平台标志」一键用的是本软件自己的标志（`src/assets/logo.png`，
  同「关于」窗口那一枚），换成本单位的台标仍走「选择图片」。两个入口写的是同一个键。
- **`curLang()` 不是响应式的**（它直读 localStorage）。凡是「生成出来的选项文本」——
  所有者下拉、星座/区制/类型的勾选项、自动报告名与文件名 —— 都得挂在 `langNow` 这个
  ref 上（由 `runtime.js` 的 `onLangChange` 推），否则切了语言这些 computed 一个都不会重算，
  界面上就是半边中文半边英文。DOM 呈现层只管模板里的静态串，管不到这些。
- **`serializeState` 的指纹与 `watch` 的触发源必须同进同出**。四道筛选进了指纹却没进 watch 源，
  症状是「改了筛选、保存按钮不亮脏点、`ssa/last` 也不落盘」—— 离改动点很远，极难回溯。
- **表号 / 图号两端各数各的，规则必须逐字同一条**：占表号的只有**非空的 `table` 块**
  （`kv` 不占、空表不占）。屏上在 `SsaDoc.vue` 的 `view` computed 里数，
  Word 在 `reportSsaDocx.js` 里数 —— `packages/core/test/ssaDocx.test.mjs` 的 `screenNumbers()`
  是这条规则的裁判，还有一条源码级 tripwire 盯着 `SsaDoc.vue` 只许有一处在数。
- **「成员表行数」（`opts.rowCap`，出厂 500）屏上与 Word 同一个值**。两端各一套上限会让题注里
  「（共 N 条）」这句读数在两边说的不是同一件事。只有卫星组报告的成员表吃它。
- **基准时刻可指定**（2026-10-16）：`state.refTime = { mode: 'now' | 'fixed', iso }`，存档只在非缺省时写这个键
  （老配置序列化逐字不变）。生成时刻（`genAt`，印在附录「生成时刻」与状态栏「报告 hh:mm」、日期留空时作报告日期）
  与基准时刻（`dataMeta.asOf`，统计截至）分开；「生成时」档两者相同。指定档进 `curSig`（改了即重出），生成时档不进。
  时刻框按显示时区读写（`geoT0.js` 的 `t0InputValue / parseT0Input`，与 NGSO「起点 = 指定」同一对），
  提交时夹进 [1957-10-04, 此刻]。编目侧由 `ssaStats.backdateRows` 按发射 / 陨落日期倒推；
  星历侧取不到历史、用最新那份，**历元龄按星历数据时间（`gpAt`）计**——拿过去的基准去减最新历元会得出负龄。
- **显示时区在检查器里可改**（`TzPicker`，存本机键 `ssa/tz`，不随配置）：只改时刻的印法，统计按 UTC 日历日不变。
- **成员表恒走 ExcelGrid**，不按行数分流：它有 19 列，正文栏宽撑不下必然横滚，而静态三线表
  没有冻结列 —— 滚到右半边最左的「名称」已经出去了，认不出这一行是哪颗星。
- **「近 N 天」按 UTC 日历日**：基准时刻先归到它所在的 UTC 零点再往前数。直接
  `asOf − N×24h` 会落在当天某个钟点上，同一天上午与下午生成的两份报告能差出好几条，
  而两份都印着同一个窗口起点。
- **越界值不许并进末桶**：`histBins` 缺省把 `> hi` 的值并进末桶（倾角 180° 那种要的就是这个），
  但「近地点高度 0–2000 km」这类有物理上界的图必须传 `dropOver: true` —— 否则那根柱子画的是
  「≥1950 km 的全部对象」（真实数据上是 3364 vs 真值 11，全图第二高的假柱子）。
- **交付文档里不许出现 ★**。★ 是本仓库源码注释的记号，报告里既没有脚注也没有图例，
  读者只会当成排版残留；判据列只写判据，对数据的评述与读图教学一概不写。

## 6. 已知局限

1. **星座名称按前缀近似**。`CONST_PATTERNS` 靠 `OBJECT_NAME` 前缀分类，与 CelesTrak 的 GROUP
   不完全等价：改过名的、代号不规则的、一箭多星里搭载的别家卫星都会算错几颗。要精确就得按
   NORAD 号维护名单，那是另一件事。
2. **SATCAT 的轨道概要是整数千米 + 两位小数的周期**，用它反推的区制在边界上（近 2000 km 的
   LEO/MEO 界、同步周期 ±2% 的边缘）会与用 GP 根数算的结果差个别颗。成员表因此优先取 GP。
3. **GEO 定点取历元处一拍**，不是长期平均。漂移星（未受控的退役 GEO）的「定点」只是它历元
   那一刻在哪，隔几天就不同 —— 共位簇里混进漂移星是正常的。
4. **`missAt` 只记首次缺席观察时刻**，不是陨落时刻。星历某天没出现可能只是那组没更新。
5. **没有历史**。所有的数都是「此刻这份编目怎么说」，`inOrbitCumulative` 那条逐月曲线是拿
   发射 +1 / 陨落 −1 的前缀和倒推的，不是历史快照 —— 编目里被删掉的条目它看不见。
6. **不含未编目碎片**。SSN 只编目约 10 cm 以上的目标，毫米—厘米级碎片（ESA 估计上亿个）
   整个不在编目里，任何按编目算的「碎片数」都是下界。
7. **停靠对象（`DOC`）算在轨**，其中一部分（如挂在空间站上的实验载荷）在别处的口径里可能
   不算独立在轨物体。

## 7. 二期候选（本期不实现）

**逐日态势摘要**：每天第一个联网用户把 `ssaStats` 的总览数字（约 5 KB JSON）回传
`omm/ssa-digest/YYYY-MM-DD.json`，客户端按日期 HEAD 拉近 90 天，报告多出「近 90 天在轨 /
活跃 / 发射 / 陨落走势」。读改写无原子性，丢一天可接受 —— 这是唯一一条能在不建服务器的前提下
拿到历史的路子，正好补上 §6.5 那条局限。

明确**不做**：SOCRATES 交会与碰撞概率；机动 / 轨道维持检测（需逐日历史）；自定义卫星；
服务器端定时抓取；PDF；小程序同步；任何文字判定。
