## 1. 现象与根因（已实测，执行前不必重测）

现象：这张 GRD 选「分带填充」后 2D 巨卡，不选不卡；3D 不卡（3D 今天已做完 L0：填充缓冲 84→36 B/三角）；**电平几个都一样卡**。

根因（Node 里跑主线 `bandGeometry`，4 个 set、hull 关、stride 1）：

| 电平数 | bandGeometry | 多边形(子路径) | 顶点 | 等值线段 | 顶点/多边形 |
|---|---|---|---|---|---|
| 1 | 51 ms | 757 k | 2.28 M | 1.5 k | 3.01 |
| 3 | 66 ms | 764 k | 2.30 M | 8.1 k | 3.02 |
| 12 | 75 ms | 802 k | 2.46 M | 46.6 k | 3.06 |
| 24 | 85 ms | 851 k | 2.65 M | 95.8 k | 3.12 |

- 多边形数的地板是 **757 k ＝ 4 set × 每 set 约 19 万个「可见且高于最低档」的网格三角形**。电平从 1 加到 24，多边形只多 12%。每个格子的两个三角形不论落在哪一档都各自成一个子路径（顶点/多边形 ≈ 3 说明它们几乎全是原封不动的三角形），电平表只决定「三角形被分到哪条 path」，不决定总量。**所以减电平不见效，不是「多画了看不见的电平」**——电平表没有显隐位（`src/components/GrdSetSections.vue` 240–251 行的每档只有填充色/线色/值/名），也没有哪一档被偷偷画了。
- 真正的边界信息量只有等值线的 1.5 k–96 k 段。填充用 2.46 M 个顶点去表达 47 k 段就能围出来的区域，差两个数量级。
- 2D 的 Path2D 是 `setField` 时烘一次的（`buildFillPaths` 1323 行），但**光栅化是每帧的**：`drawField`（1431 行）每帧 `ctx.fill(path)` × 层数 × 档数 × ≤3 份 ±360 副本，而 `onMove`（2219 行 `dragging` 分支）、`onWheel`（2007 行）每次都 `invalidateStatic(); requestDraw()`。今天 `.fillharness/index.html` 实测（CPU 光栅沙箱，只看比值）：逐三角填充随渲染倍率近似线性涨（100%→136 ms、200%→257、375%→532），合并成环几乎不动（7–20 ms）——成本在「图元数 × 边长」，不在像素数。
- hull（地平弧凸包点数）之所以成了「平滑度妥协」，是因为跨地平三角形逐个按 `clipToHull`（SH 裁剪）裁到这个凸包，环越密每个碎多边形顶点越多。它只是同一个病的症状。

## 2. 为什么选 GPU 网格着色，不选别的

| 候选 | 结论 |
|---|---|
| **A. WebGL2 网格着色（本任务）** | 成本随**屏幕像素**走，与 GRD 大小、电平数、hull 无关；平移/缩放/改档/改透明度/指向拖拽全部变便宜；地平按每像素精确判、无凸包；填充与等值线用**同一三角网 + 同一线性插值**，等值线与填充边界严格重合（这正是 v1.0.4-2 当年把 GPU 填充换回 CPU `bandGeometry` 的唯一理由，本方案满足它）。7-14 与 09-06 两次性能分析都得出「让成本随屏幕像素走」这同一个方向。 |
| B. 下位集闭环（等值线环围成多边形，Canvas2D） | 今天做过原型并接入 2D，逐像素闸差 2.7% 全在地平一圈，用户手测后要求整份撤回（代码在 `.fillharness/rings/`，主线一行没有）。仍是 CPU 几何、指向拖拽仍慢、地平仍要一条裁剪环。**本任务不做，不要重拾**。 |
| C. 同档相邻格并成行程条带 | 约 3×，对 400% 下 500 ms/帧的基数不够。不做。 |
| D. 位图缓存 | 平移能省，缩放每一步仍要整轮光栅化（500 ms 一跳），指向拖拽/时钟播放场变时缓存作废。不做。 |
| E. 按视区裁剪 CPU 几何（L1） | 今天做完当天撤：裁剪一旦生效视区一动就要整轮重建（280+ ms）。**任何按视区省算力的做法都不能在 CPU 侧切几何**，GPU 方案天然满足这一条（视区变化只改 uniform）。 |
| F. 只画「要显示的」电平 | 前提不成立（没有隐藏电平，且总量不随电平变，见 §1）。 |
| 顺带说明 | 2D 的实际渲染倍率是 `effDpr()`（107–124 行）：吸附到 DPR 整数倍且 `SS_MULT_MAX = 2` 封顶——Windows 100% 缩放下 400% 与 200% 都渲成 2×，125% 下 400% 是 2.5×。「降倍率」在 2D 上省不了多少，别拿它当修法。 |

## 4. 设计

### 4.1 数据流：2D 在等距圆柱下不再生成 fillBands，改送网格

`buildLayer` 增加第三个产物 `fieldMesh`，**只在**「本次喂的是 2D（`isFlat()`）且 2D 渲染器回答 `fieldBackend() === 'gl'`」时生成；此时 `bandGeometry` 以 `wantFills = false` 只出等值线（省掉 95 ms 的逐档裁剪与全部 `buildFillPaths`），`fillBands` 置 null。其余情形（3D、导出、非 identity 投影、无 WebGL2）一切照旧。

```
fieldMesh = {
  NX, NY, box, stride,          // 与同一层 segGroups 用的 bandGeometry 完全同一套 box / stride（autoStride 的返回值）
  lonU: Float32Array(N),        // 经度按【该星星下点经度】就近解缠（连续、不跨 ±180 断）；N = NX·NY，box 外的值不读
  lat:  Float32Array(N),
  db:   Float32Array(N),        // field.db（含 NaN）
  vis:  Float32Array(N),        // proj.vis（< 0 越地平）
  satN: [x, y, z],              // 卫星 ECEF 逐分量除以 (A, A, B) 的归一坐标（见 4.3）
  levels: Float32Array(nb),     // 升序绝对电平 asc[i].abs
  colors: Float32Array(nb * 3), // 0..1
}
```

`projectGrid` 的 `lon / lat / vis` 本就是 Float32Array，直接引用（不要拷贝、不要经过 Vue 响应式）。`lonU` 是唯一新算的量：一遍循环，相对 `c.meta.satLon`（或实时星位）解缠。

渲染器 API 新增 `fieldBackend()`：返回 `'gl'` 当且仅当 WebGL2 上下文可用且未丢失、`PJ.identity`、非导出、电平数 ≤ 64；否则 `'paths'`。**`buildLayer` 每次都问它**，不缓存。

导出时序要核实：`exportFlat` 置位 → `feedFlat()` → `recompute()` → `exportRender`。`exportRender` 期间 `compat = true`，但 recompute 发生在它之前——所以 `fieldBackend()` 还要看一个由导出流程显式置位的 `exporting` 标志：导出那条路上 `flat.setExporting(true)` → feedFlat → 导出 → `setExporting(false)` → 再 recompute 一次恢复屏上 GL 路。验收项之一就是「导出 PNG 与改造前逐字节相同」。

### 4.2 渲染端：`src/viz/flatmap/glField.js`（新）+ `drawField` 分叉

- 一个不进 DOM 的 `<canvas>` 拿 `webgl2`（`{ alpha: true, premultipliedAlpha: true, antialias: false, preserveDrawingBuffer: false, depth: false, stencil: false }`），尺寸与主 canvas 的设备像素严格一致，`resizeNow` 时一并改。`webglcontextlost` → `preventDefault` 并把后端切成 `'paths'`、通知页面重算一次（`onBackendChange` 回调 → `grd.recompute()`）；`webglcontextrestored` 再切回。
- 每个子层一组缓冲：`lonU / lat / db / vis` 四个 `ARRAY_BUFFER`（或交错成一个）、一个 `Uint32` `ELEMENT_ARRAY_BUFFER`。索引按 `bandGeometry` 742–751 行**一字不差**的循环生成（同 box、同 stride、末格夹边界、a–c 对角线），并镜像 `loadTri` 的前两条跳过：任一角 `db` 为 NaN；三个角 `vis` 全 < 0（**这一条必须做**：全越地平的三角形在经纬平面上可能横跨可见区，不剔会把地平外的方向图值糊进地球）。`max dB < L0` 这一条**不**进索引（留给片元 discard），这样索引只随场/指向变、不随电平变。
- `drawField` 上半段：若该层有 `fieldMesh` 且后端为 `'gl'`，对 `wraps()` 里每个未被 `bounds` 剔掉的 `off`：设置 uniform（`dpr, kk, tx, ty, LON0, off, W, H`）、`drawElements`；一层画完 → `ctx.setTransform(1,0,0,1,0,0); ctx.globalAlpha = fieldAlpha; ctx.drawImage(glCanvas, 0, 0)` → `gl.clear`。**逐层各 drawImage 一次**：现状是各层各自带 `fieldAlpha` 逐次 `fill`，层与层之间是半透明叠加；一张 GL 画布里把多层画在一起再合成一次会改变多层重叠处的颜色，验收会抓到。同一 JS 任务里 render → drawImage → clear 多次是安全的，不需要 `preserveDrawingBuffer`。
- 下半段等值线不动。`covGridLayers`（STK）、`drawSatFills`、导出 `compat` 分支不动。
- 每帧只改 uniform；**平移/缩放不许触发任何缓冲上传或 CPU 几何**（L1 的教训）。缓冲上传只在 `setField / patchField`。

### 4.3 着色器合同

顶点：

```
in float lonU, lat, db, vis;
uniform float uLon0, uOff, uK, uTx, uTy, uDpr, uW, uH;
out float vDb, vLon, vLat;
x_css = (lonU - uLon0 + uOff) * uK + uTx;   y_css = (90.0 - lat) * uK + uTy;
gl_Position = vec4((x_css * uDpr) / uW * 2.0 - 1.0, 1.0 - (y_css * uDpr) / uH * 2.0, 0.0, 1.0);
vDb = db; vLon = lonU; vLat = lat;
```

等距圆柱下 CSS 坐标是世界度的仿射变换，GPU 对 `vDb` 的线性插值 ≡ `bandGeometry` 沿三角形边的线性插值 → 等值线（CPU）与填充边界（GPU）重合到亚像素。

片元：

```
uniform vec3 uSatN;                              // 卫星 ECEF ./ (A, A, B)
uniform int uN; uniform float uLevels[64]; uniform vec3 uColors[64];
// ① 精确地平：大地纬度 φ、经度 λ 的地表点在归一坐标下恰在单位球上
//    Nn = 1 / sqrt(1 - e²·sin²φ)
//    P' = ( Nn·cosφ·cosλ,  Nn·cosφ·sinλ,  Nn·(1-e²)·sinφ / sqrt(1-e²) )      // |P'| ≡ 1
//    可见 ⇔ dot(P', uSatN) >= 1       （与 coverage.js limbPoint 的推导同源：线性映射保持相切）
// ② 电平：k = #{ i : uLevels[i] <= vDb } - 1；k < 0 或 vDb 为 NaN → discard（NaN 的比较恒假，自然落到 discard）
// ③ 颜色 uColors[k]，alpha 1
```

要点：

- 归一坐标下 `|uSatN| ≈ 6.6`（GEO），float32 的相对精度对「≥ 1」判据够用（地面误差米级）；**不要**在 ECEF 千米量纲下做这个点积。`e² = E2`、`A / B` 与 CPU 用同一份常量。
- 经度解缠围绕星下点，可见半球宽 < 180°；`lonU − uLon0` 再加 `uOff ∈ {−360, 0, 360}` 三份副本，与现有 `wraps()` / `bounds` 完全同一套剔除逻辑（`bounds` 用 `lonU` 的 min/max）。
- 三角形跨地平：`projectGrid(limbOutside = true)` 的越地平顶点落在地平外，片元用①精确切掉，**不再需要 hull**。CPU 里 `m = 0` 线是弦、真地平是弧，弦弧之间那一片以前靠凸包补、现在由①天然填满。副作用：外缘直边（相邻两个地平外顶点的连线）与真地平之间理论上有 ≤ 1 km 量级的欠填，肉眼不可见，验收里量一下写进报告即可。
- 档边不做 AA：`effDpr ≥ 2` 时合成器降采样已给 2–3× 的边缘平滑，且等值线本就描在边界上。`fwidth` 混色留作后续可选项，不在本任务。
- GLSL ES 3.00 允许非常量循环上限，仍写成 `for (int i = 0; i < 64; i++) { if (i >= uN) break; … }`。电平数 > 64 → `fieldBackend()` 回 `'paths'`。

### 4.4 缓冲复用与 patchField

`recompute` 注释里说 3D「图层按 id 复用 GPU 缓冲」——去看 `scene.updateCoverageField / patchCoverageLayers` 是怎么给层定身份的，GL 侧照同一口径复用缓冲（尺寸不变走 `bufferSubData`）。做不到就整份重建：4 set 合计约 6 MB/次，可接受，别为此拖工期。`patchField`（拖拽热路径）只重传被替换的那一层。

### 4.5 不变式（改完自检）

1. 关掉分带填充、切 3D、导出、换成 Mercator / Robinson / Albers / 方位等距、STK 覆盖、对星壳层：**行为与像素与改造前一致**（这些路都不该碰到新代码）。
2. `s.alpha`（填充透明度）/ `s.lineAlpha` / `s.lineWidth` 的 watch 仍只改 alpha 或只重算线，不引起 GL 缓冲重传。
3. 「拖着转」（`rotLive`）期间 `drawField` 直接 return 的口径不变；松手后 `rebuildPlane` 重烘 `segPaths`，GL 层只需重设 `uLon0`（`LON0` 变了），不需要重传。
4. 一帧一个时刻：不许把 GL 上传或绘制延后到下一帧（`recompute` 后那段注释里的时钟铁律）。
5. 每帧要问的量必须 O(1) 且不碰 DOM（今天 viewMetrics 探针版把 2D 卡死过一次）。

## 7. 坑清单（都踩过，别再踩）

1. **L1 教训**：按视区省算力只能走「不需要重建」的路。GL 路上，视区变化 = 改 uniform，仅此而已。
2. **每帧量必须 O(1) 不碰 DOM**：探针式 `getBoundingClientRect` 逆投影 26 点曾把 2D 当场卡死。
3. **全越地平的三角形必须从索引剔掉**（4.2），否则地平外的方向图值会横跨到地球上。
4. **不要把 `fieldMesh` 交给 3D 或导出**：`updateFill` 只吃凸多边形 fillBands；`exportRender` 的 `compat` 分支只认 fillBands（PNG 与 PDF 逐字节一致是硬约束）。
5. **Vue 响应式代理**：`Float32Array` 直接引用即可，但层对象别从 `reactive` 里取；喂 GL 的一律纯数据。
6. **Canvas 逐像素验证台三陷阱**：`willReadFrequently` 抢在渲染器 `getContext` 之前；预览窗藏起来 rAF 全停；`document.hidden` 时上屏 canvas 读回全 0——读离屏。
7. **Electron 窗口驱动不了**（launch.json 的 dev 拉起真桌面窗；renderer 单开无 IPC，数据加载不出）：UI 像素级效果只能验证台 + 用户手测，别在报告里说「已在 Electron 里实测」除非用户测过。
8. **并发会话**：同一工作树还有别人未提交的改动（`flatCoverage.js / projection.js / scene.js` 等今天都有 diff），只 `git add` 你的文件，不 `stash`、不 `checkout --`、不整份 `cp` 还原；回退只能外科式反向 patch。
9. **hull 与 stride 别动**：`satHull` 100 与 `autoStride` 继续服务 CPU 路（3D / 导出 / 非 identity）和等值线；GL 路不用 hull，但等值线用的 stride 必须与索引生成的 stride 相同（4.1）。
10. **不写界面说明文字**（CLAUDE.md）：本任务不该新增任何 UI 文案；若加后端切换开关，放画质档「自定义」里一行拨杆即可，无解释段。
11. **多层半透明叠加**逐层 `drawImage`，不许一张 GL 画布合并多层后只合成一次（4.2）。
12. **`LON0` 会变**（拖着转、换切口）：位置里 `LON0` 必须是 uniform，不能烘进顶点缓冲。
