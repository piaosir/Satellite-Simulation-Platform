# 日凌预报（GSO）模块说明

独立窗口「日凌预报 · GSO」：给定一颗 GSO 卫星与一批地球站，算出春分 / 秋分前后各 30 天内每天的
日凌窗口（起止 / 峰值时刻、时长、峰值 C/N 恶化、最小夹角），并出 Excel / Word / ICS 三种交付物。

- 渲染端 `src/suntool/`（`SunOutageApp.vue` 界面、`sunParams.js` 纯逻辑），入口 `src/suntool.html` + `src/suntool.js`
- 引擎 `packages/core/utils/sunOutageCalculator.js`（v5.3），轨道源 `packages/core/utils/orbitSource.js`
- 主进程 `electron/ipc/register.js` 的 `sunoutage:*` / `suntool:*`，导出版式 `electron/services/report.js`
- 太阳射电流量 F10.7：`electron/services/solarFlux.js`（取数）+ `packages/core/utils/solarFluxPick.js`（规则）
- 配置库 `configs.sun.json`（命名空间 `sun`，`orbitType: 'SUN'`）
- 测试 `packages/core/test/`：`sunOutage`（金标准）/ `sunOutageModes` / `sunOutageXlsx` / `sunParams` /
  `sunOutageIpc` / `solarFlux`

## 1. 取星：定轨 / 星历两档

| | 定轨 | 星历 |
|---|---|---|
| 入参 | `params.satLon`（定点经度 °E） | `params.orbit`（轨道 spec） |
| 卫星位置 | 理想地球静止轨道的常量点 `satXYZ(satLon)` | 逐时刻由轨道源给出的 ECEF |
| 含什么 | 只含轨位 | 倾角、偏心率、东西与南北漂移 |
| 不含什么 | 倾角、漂移 | **轨道保持机动** |
| 适用 | 受控 GEO 的常规预报；与改造前逐位一致 | 倾斜 GSO、退役漂移星、短期精密星历 |

两者都给以 `orbit` 为准。轨位可以从搜索结果自动带入（历元处的星下点经度），也可以手填。

### 局限（写进界面的只有读数与颜色，口径在这里）

- **SGP4 不含轨道保持机动**。受控 GEO 每隔一两周做一次位置保持，SGP4 只按根数外推，
  历元离分点越远越偏。实测 `ZHONGXING-6C`（历元 2026-09-16，平均运动比恒星日慢 0.0152°/天）：
  距历元 7 天的秋分算得星下点 130.19°E（与轨位 130.46°E 只差 0.27°），
  而往回推 179 天的春分算得 102.14°E —— 偏了 28°，那一季的结果只是模型外推，不能当预报用。
  界面上「距分点」绝对值 > 60 天时着警示色，就是这条口径唯一的提醒。
- **非同步轨道拒算**：`|周期 − 1436.07 min| > 28.72`（恒星日 ±2%，与 `src/shared/orbitClass.js` 同一组数）
  直接返回 `{ error: true, message: '非地球同步轨道，日凌预报只支持 GSO' }`。
- **太阳亮温是模型算出来的，不是量出来的**（v5.3，见 §8）。1–17 GHz 是野边山逐日流量对 F10.7 的
  回归谱，残差 2%~2.5%；17 GHz 以上是锚定外推，Ka 频段约 ±10%、Q 频段约 ±15%。F10.7 由主进程
  按该季分点日从 NOAA SWPC 取（观测日值 / 45 天预报 / 观测月均 / 太阳周预测四档，见 §8.4），
  取不到才落回缺省 120。合成到峰值恶化约 ±0.2 dB；起止时刻对噪温只呈对数敏感，差值在数十秒量级。

### 不逐秒 propagate

星历档的卫星位置按**两级采样 + 日内线性插值**取，不逐秒调 SGP4 ——
与 `daySun` 的「一天内能不能插值」同一条原则：

- **粗表** 10 min（145 点/天）：只管两件事 —— 当天有没有星历、逐日赤纬预筛的区间上下界；
- **细表** 60 s（1441 点/天）：供事件求根逐秒取值，过了预筛才铺。

实测倾角 5° 的 GSO，60 s 插值的位置误差 8.7 m，从 42 000 km 外看是 1.19e-5°，
比求根容差 0.5 s 对应的太阳位移（≈0.002°）小两个量级（`sunOutageModes.test.mjs` 钉着这条）。

逐日预筛的余量 `margin = 0.05°（插值余量）+ inclDeg·(2π/1436.07)·5`：
星下点赤纬 δ = i·sin u、du/dt = 2π/P，10 min 粗采样两点之间赤纬最多走这么多。不留这一项，
倾斜星的事件日会被漏筛。

轨迹表按 (轨道, 日) 记忆化，经 `ctx.satTrack` 在一批站之间共用 —— 轨迹与站无关，一颗星一季只采样一次。
实测北京首站 50 ms → 乌鲁木齐次站 9 ms；主进程另有一个容量 2 的 LRU 让分块 IPC 之间也复用。

## 2. 判据：恶化门限 / 纯几何两档

| | 恶化门限（缺省） | 纯几何 |
|---|---|---|
| `params.criterion` | `'degradation'` | `'geometric'` |
| 门限角 θ_th | 由 D(θ) = D_th 二分反解 | ≡ θ_3dB = 70λ/D |
| 窗口 | { t : D(θ(t)) ≥ D_th } | { t : θ(t) ≤ θ_3dB } |
| 与噪温的关系 | 有（T_sys 越低、门限角越大） | 无 |

其中

- θ_B = 70λ/D（真实 3 dB 波束宽，**全宽**，不加太阳视半径）
- ΔT(θ) = T_sun · K(θ)，K 为「太阳均匀盘 × 高斯主瓣」的精确卷积（Simpson + 指数缩放 I₀）
- D(θ) = 10·lg(1 + ΔT(θ)/T_sys)

纯几何档下 `degThreshold` 不参与定窗，但仍原样回显在 `model.degThreshold`。
**峰值恶化 dB 两档都按上面的物理模型算出** —— 它是物理量，与定窗判据无关。

θ_3dB 通常比恶化门限档的门限角窄（Ku 2.4 m：0.700° vs 0.976°），故纯几何档的事件日是恶化门限档的
子集、逐日时长也更短；反之（大口径高频）则相反。两档的日期集合恒是子集 / 超集关系。

- 计算全程 UTC（引擎逐日给 `date` + `startTimeUTC / peakTimeUTC / endTimeUTC`）。

## 4. Excel：运行版《日凌时间表》

版式照用户给的运行原件《CH12_C_全球_1.8m.xls》（中星12号 87.5°E · C 频段全球波束 · 1.8 m ·
2026 秋季，68 站 1094 天）逐格量出来复刻。**★ 这一张不是三线表** —— 它是发给值班与客户的时间表，
一季一张 sheet（sheet 名与页首标题都写「{年}年{春季|秋季}」）。

| 行 | 内容 | 字体 | 行高 |
|---|---|---|---|
| 1 | `A1:I1` 合并　`{卫星}  {年}年{春季\|秋季}日凌时间表`（两个空格） | 华文楷体 24 磅粗 · 居中 | 34.5 |
| 2 | `A2:I2` 合并　`卫星名称:{卫星}    东经{轨位}度`（半角冒号 + 四个空格） | 华文楷体 16 磅粗 · 居中 | 22.5 |
| 3 | 表头 | 华文楷体 12 磅粗 · 居中 | 16.5 |
| 4+ | 数据，**站信息列 A–E 按站纵向合并**（一站一块） | 等线 11 磅 · 居中 | 14 |

列：`序号 | 地点 | 经度 | 纬度 | 天线尺寸（米） | 日期 | 开始时间 | 结束时间 | 持续时间（分）`
（括号是全角）。列宽 8.45 / 8.45 / 8.45 / 8.45 / 10 / 12 / 9 / 9 / 10 —— 只有「地点」列在站名比
原件那批四字名更长时只增不减地放宽，截断是丢信息。

全表每格四边细实线、无底纹、不冻结、不筛选、网格线保持显示。该季无事件的站不出块，序号在表内连号。

值的口径：

- 日期写**真日期值**（`yyyy-mm-dd`）；
- 开始 / 结束写**带秒的** Excel 时间序列值，由 `hh:mm` 只显示到分 —— 与原件一致（原件存的也是秒）；
- 持续时间 = `round(真实秒 / 60)` 的整数分。★ 原件里 `14:10~14:17` 那天写的是 **8** 而不是 7，
  正因为它取的是真实时长（460 s = 7.67 min），不是两个显示值相减。这条在测试里有专门一条钉着。
- 日期与时刻都已在渲染端按显示时区平移好，主进程只写不算。

### 两个坑

1. **`views` 必须显式给**。exceljs 不写 `<sheetViews>` 元素时，Excel 打开会把**整表行高按 2/3 缩掉**
   （34.5 → 23、22.5 → 15、14 → 9.4；用 Excel 重存一遍，`ht` 真就被改写成 23）。
   exceljs 自己读回来看不出任何差别，只有真用 Excel 打开才发现。本仓库别的 Excel 出口都顺手带了
   `views`（多是 `showGridLines: false`），所以从没撞上这一条。原件网格线是开着的，
   故这里给 `{ showGridLines: true }` —— 要的只是让那个元素存在。
2. **不调 `applyBookFont` / `autofitBook`**。前者把中西文归位成 宋体 + Times New Roman，会把原件的
   华文楷体 / 等线 冲掉；后者会把量出来的定值列宽行高改走样。

### 与运行原件的对拍

把频率按 C 频段下行 **3.8 GHz** 填、判据选**纯几何**，我们的引擎就是这份运行表的判据 ——
68 站 1094 个事件日逐日对拍：

| 频率 | θ_3dB | 时长偏差均值 | 起始时刻偏差均值 | 天数 |
|---|---|---|---|---|
| **3.8 GHz** | 3.068° | **+0.05 min**（\|偏差\| 均值 0.09，最大 2） | **0.04 min**（最大 1） | 1094 天里只差 2 天 |
| 3.95 GHz（频段默认） | 2.952° | −1.25 min | 0.67 min | 少 45 天 |

反推最佳拟合门限角是 3.065°，与 3.8 GHz 下的 70λ/D = 3.068° 重合。也就是说：
**差别只在填哪个下行频率，判据本身一致**。频段默认值 3.95 GHz 是 C 频段下行的中心频率，
要复现运行表就把「频率」那一列填 3.8。

## 5. 配置 state

`configs.sun.json`，命名空间 `sun`，与五个工作台共用 `ConfigTree` 三件套。

```js
{
  orbitType: 'SUN', name: '',
  sat: {
    name, noradId,
    source: 'slot' | 'ephemeris',
    slotLon: '130.5',
    orbit: null | { type: 'omm', … } | { type, ref: { groupId, satId } },
    epoch: '', inclDeg: null, groupLabel: ''
  },
  year: '2026',
  seasons: ['vernal', 'autumnal'],
  criterion: { mode: 'degradation' | 'geometric', degDb: '1' },
  stations: [{ stationName, longitude, latitude, band, frequency, diameter, sysTemp }]
}
```

- 数值一律存字符串（草稿串口径：`-`、`1.` 这类中间态不能被改成 0）。
- **结果不入库**（重算是秒级的）。载入配置即清掉屏上的结果。
- 星历正文 ≤ 4 KB 内嵌配置（OMM / elements 都远小于此）—— 离线打开旧配置也能按当时的根数重算，
  点「刷新星历」才换成最新的；超过 4 KB 的只存引用 `{ type, ref }`，正文不搬进配置、不过 IPC。
- 显示时区不进配置（窗口偏好，`sun/tz`）。
- 工作状态存 `localStorage` 键 `sun/last`（state + activeId），挂载时恢复；关窗序：守卫 → 冲刷 → 放行。
- 规范化走 `sunParams.normState`，幂等：`serialize → apply → serialize` 的指纹必然相等。
- v5.3 之前的配置里有 `criterion.solarTemp`（手填太阳亮温）。太阳亮温已不是入参，`normState`
  读到直接丢 —— 留着只会让指纹带上一个再也不参与计算的键。老配置照常载入，只是那一项没了。

## 6. 卫星检索与别名

候选 = 星历池（`src/ngso/satSearchPool.js` 的共享单例）里 `classifyOrbit ∈ {GEO, IGSO}` 的记录
∪ `src/linkbudget/satPresets.js` 的预设表，按规范化名去重、**池记录优先**（预设名留作检索别名）。

规范化名 = 大写、去括注、`ZHONGXING-` → `CHINASAT `、折叠分隔符。于是：

- CelesTrak 把中星编目成 `ZHONGXING-6C`，预设表里是 `CHINASAT 6C` —— 合并成一条，显示编目名；
- 搜「中星 6C」「中星6C」「CHINASAT 6C」「chinasat6c」「ZHONGXING-6C」「44067」都命中同一条；

## 7. 已知局限清单

1. SGP4 不含轨道保持机动（见 §1）。
2. 太阳亮温的射电盘径不随频率变化（低频日冕外延不建模）——与耦合计算共用同一盘径，小口径极限下
   流量守恒，盘径选取误差自相抵消；17 GHz 以上是锚定外推（Ka ±10%、Q ±15%），详见 §8.6。
3. 一份配置一颗卫星（多颗同算不做）。
4. 只支持 GSO：非同步轨道直接拒算。
5. 扫描窗口固定为分点前后各 30 天（61 天）。倾角大的 GSO 事件可能落在窗口边缘而被截断。
6. `dailyResults[].satLon` 只在星历档有（峰值时刻的星下点经度，3 位小数）。
7. 算不出的站在站表里只出 `✕` 与红色，具体原因在右侧结果栏（`StationGrid` 没有逐格 `title` 钩子，
   本模块「只用不改」它）。

## 8. 太阳亮温模型 v5.3

日凌的深度全由一个量决定：太阳在该频率上的亮温 T_sun。窗口判据
`D(θ) = 10·lg(1 + T_sun·K(θ)/T_sys) ≥ D_th` 里，K(θ) 是纯几何（太阳均匀盘 × 高斯主瓣卷积），
T_sys 是用户站的属性，只有 T_sun 是模型给的 —— 它错多少，门限角与窗口时长就跟着错多少。

### 8.1 v5.1 的两处不准（为什么要改）

v5.1：`T_b(2.8) = F10.7·λ²/(2k·Ω_d)`，再按 `T_b(f) = 6000 + (T_b(2.8) − 6000)·(2.8/f)^1.8` 外推，
F10.7 恒取 120。

- **单一谱指数 1.8 对 3–40 GHz 太陡**。与野边山逐日实测比（F10.7 = 120）：3.75 GHz 偏高 9%、
  Ku 12.5 GHz 偏低 19%、Ka 19.45 GHz 偏低 23%、Q 40 GHz 偏低 27%。
- **F10.7 恒 120 与真实太阳活动无关**。2019–2020 谷底约 70，2024 峰年常在 200 以上，
  2026 秋分附近实际约 105–130 —— 同一副天线在谷底与峰年的峰值恶化差 2 dB 量级。

### 8.2 数据与拟合

- **野边山射电偏振计（NoRP）逐日总流量**（国立天文台野边山太阳射电观测所，1 / 2 / 3.75 / 9.4 / 17 GHz，
  单位 sfu = 1e-22 W·m⁻²·Hz⁻¹），2004-10 → 2026-07；
- **DRAO Penticton F10.7 逐日观测值**（加拿大自然资源部空间天气，`fluxobsflux` 列，取 20 UT 那次）。

按日期配对 7 325 天，逐频作稳健线性回归 `S_f = a_f + b_f·F10.7`（3σ 剔野点，迭代 5 轮）。
数据、脚本与系数文件在 `docs/research/solar-flux-fit/`（`fit.mjs` / `check.mjs` / `coef.json`）。

| f (GHz) | a_f | b_f | R² | 残差 σ (sfu) | N（剔野点后） |
|---|---|---|---|---|---|
| 1.0 | −1.979 | 0.70334 | 0.950 | 5.5 | 6 574 |
| 2.0 | −10.643 | 0.94073 | 0.983 | 4.4 | 6 182 |
| 2.8 | 0 | 1 | 恒等 | — | — |
| 3.75 | 17.318 | 0.88345 | 0.988 | 3.5 | 6 818 |
| 9.4 | 210.379 | 0.68094 | 0.927 | 6.9 | 6 699 |
| 17.0 | 592.284 | 0.45292 | 0.611 | 13.6 | 6 885 |

17 GHz 的 R² 低不是拟合差，是量程小：该频点的动态范围只有 ±5%，残差 σ ≈ 2%。
月均回归（242 个月）给出同一组斜率，线性够用（二次项系数 ≈ −1e-3，F = 200 处与线性只差 2–4 sfu）。
高活动端（F > 150）残差均值：3.75 GHz −2.1 sfu、9.4 GHz +0.3、17 GHz −4.0，峰年线性略高估 1–2%。

### 8.3 模型公式

```
S(f, F) = 锚点 S_f = a_f + b_f·F 之间按 log S – log f 线性插值        （f ≤ 17 GHz；f < 1 取 1 GHz 锚点值）
        = S_q(f) + b₁₇·(F − 67)                                    （f > 17 GHz）
S_q(f)  = 35 / 80 GHz 两个标定锚之间 log-log 插值                    （17 < f ≤ 80）
        = 由 T_q(f) = 6000 + 731·(80/f) 反算的流量（1 AU 光学盘）    （f > 80）
T_sun(f) = S(f, F)·1e-22·λ²/(2k·Ω_d)，Ω_d = π/4·(当日太阳视直径)²
```

- **17 GHz 以上没有逐日数据**，静日谱改用 NoRP 自己的绝对标定常量锚定：手册 man_v04e §2 把
  35 / 80 GHz 的流量刻度固定为 2400 / 9000 sfu 这两个静日值，换算成光学盘亮温 9 378 K / 6 731 K，
  与文献静太阳 8 mm ≈ 8 500–9 500 K、3.7 mm ≈ 6 500–7 500 K 相符；80 GHz 以上向光球层 floor 6 000 K 收敛。
- **活动增量在 17 GHz 以上按流量恒定外推** `ΔS = b₁₇·(F − 67)`：活动区的自由-自由辐射是平谱，
  回旋共振分量 20 GHz 以上已消失。换成亮温即 ∝ f⁻²，35 GHz 处峰年也只有 +2.6%。
- **Ω_d 取当日光学盘**，S 是「地球处观测流量」，两者随日地距离同比变化 —— 口径自洽，不做 1 AU 归算
  （只有 > 80 GHz 那一段由 T_q 反算流量时用 1 AU 盘，与 T_q 的定义域一致）。

亮温换算（1 AU，视直径 0.53312°）与 v5.1 对比：

| f (GHz) | T_b @ F=67 | T_b @ F=120 | T_b @ F=200 | v5.1 @ F=120 | v5.1 相对新模型 |

### 8.4 F10.7 从哪来

引擎不联网、不碰文件系统：F10.7 由主进程 `electron/services/solarFlux.js` 按【该季分点日】查好，
经 `params.f107` / `params.f107Meta` 传进来。分点日走引擎导出的 `equinoxDateOf`（不在 IPC 层抄第二份公式）。

四个 NOAA SWPC 产品：

| 产品 | 内容 | 用途 |
|---|---|---|
| `products/10cm-flux-30-day.json` | 最近 30 天 20 UT 观测值 | 过去 30 天内的目标日 |
| `text/45-day-forecast.txt` | `45-DAY F10.7 CM FLUX FORECAST` 块，每行 5 对 `21Sep26 105` | 未来 45 天内的目标日 |
| `json/solar-cycle/observed-solar-cycle-indices.json` | 观测月均（实测只从 2004-10 起有 F10.7，共 263 条；更早的行是 -1） | 过去任意月 |
| `json/solar-cycle/predicted-solar-cycle.json` | 太阳周预测月均 + 25/75 分位带，到 2030-12 | 未来任意月 |

取值优先级（`solarFluxPick.f107For`，窗口 = 分点日 ±20 天）：

1. **逐日**：30 天观测与 45 天预报合成一条日序列（同一天两者都有取观测），窗口内 ≥ 10 天有值 → 取均值。
   全是观测标 `daily`，含预报标 `forecast45`；
2. **观测月均**：目标月在月表里 → 该值，标 `monthly`；
3. **预测月均**：目标日落在预测覆盖内 → 相邻两月中点之间按日期线性插值，标 `predicted`，带 low / high；
4. **预测末值**：目标日在最后一个预测月之后 5 年内 → 末月值，标 `predicted-tail`；
5. **缺省** 120，标 `default`（本机连内置快照都没有，或目标日早于全部产品）。

取数链路与星历（`omm.js`）同一口径，**计算永不等网络**：当日缓存闸 → 直连四个产品（各 20 s、各 2 次）
→ 落盘 + 众包回传云镜像 → 云镜像（COS，键 `solarflux`）→ 用户缓存 / 内置快照
`resources/space-weather/solar-flux.json`（随安装包分发，无网设备靠它）。计算只读本机已有的那一份
（`snapshot()`，同步返回），联网刷新在算完之后不 await 地捅一下。发版前 `npm run omm:snapshot`
会把星历与 F10.7 两份快照一起刷新。

### 8.5 界面与报告怎么显示

- 界面**没有太阳亮温的输入框**（v5.3 起删掉）。引擎侧 `params.solarTemp` 覆盖仍在，
  留给需要对齐第三方工具口径的调用方，界面不给入口。
- 结果卡「太阳亮温 13 115 K」，卡内第二行小字 `F10.7 129.6 · 预测 2026-09`（算的时候用的那个值）。
- 顶栏一行 `F10.7 数据 2026-09-21 · 内置快照`，点一下重新联网取；刷新完只更新这一行，不自动重算。
- Word 参数表「太阳亮温」行写亮温 + F10.7 与出处；方法段写明回归谱与 F10.7 的来源。
  ICS 事件描述行追加 `· 太阳亮温 13115 K（F10.7 129.6）`。
- Excel《日凌时间表》是运行原件的版式，没有噪温 / 亮温列，不加。

### 8.6 精度与已知局限

- 拟合残差：3.75 GHz σ ≈ 3 sfu（≈ 2.5%）、9.4 GHz ≈ 7 sfu（2.4%）、17 GHz ≈ 13 sfu（2%）；
- F10.7 来源误差：观测日值 ±0；45 天预报 ±5–10 sfu；月预测 ±7–15 sfu（SWPC 给的 25/75 分位带，
  回显在 `model.f107Low / f107High`，不上屏）；
- 合成到峰值恶化：Ku 2.4 m 站约 ±0.2 dB（v5.1 恒 120 那套在谷底 / 峰年可错 ±1 dB 以上）；
- **17 GHz 以上是锚定外推**：Ka 频段约 ±10%、Q 频段约 ±15%；
- **射电盘径随频率变化（低频日冕外延）不建模**：与耦合计算共用同一盘径，小口径极限下流量守恒，
  盘径选取误差自相抵消；
- **太阳耀斑 / 射电暴的瞬时增强不建模**（分钟量级的事件，不是日凌预报的口径）。

### 8.7 legacy 档

`params.solarModel: 'legacy'` 走 v5.1 整套（`solarTempLegacy`，一个数字都没改）。
金标准 `sunOutage.test.mjs` 的夹具是 2026-09-07 用 v5.1 亮温抓的，它钉的是**采样 / 插值路径**逐位不变、

## 9. 与「外部星历导入」的接口

另一份设计要新增传播类型 `ephem`（STK .e / CCSDS OEM / SP3 的时间标签状态矢量，插值而非 SGP4）。
本模块**不实现 `ephem`**，但缝已经留好，接入时日凌引擎与窗口都不必再改：

1. **轨道源**（`packages/core/utils/orbitSource.js`）：引擎只认
   `{ kind, summary: { periodMin, inclDeg, ecc, epochIso }, span, posEcefKm(ms), lonAt(ms) }`
   五个成员，不认 satrec、不做坐标系转换。新增一种 `kind: 'ephem'` 的实现即可。
2. **覆盖区间**：`span` 非 null 时，区间外的采样点返回 `null`，引擎把那天记为「无星历」跳过、
   不计入 `coverageDays`，并回显 `model.ephemSpan`；汇总量（方位 / 仰角 / 星下点）取不到分点日正午时
   向两边找最近的有星历的一天。界面的「星历覆盖 … · 缺 n 天」读数行分支已写好。
3. **池记录契约**：`ephem` 型池记录只要带 `incl / meanMotion / ecc` 摘要（供 `classifyOrbit` 与本窗口的
   GEO / IGSO 过滤）和 `summary.lonDeg`，日凌搜索就直接可见、可选。
4. **配置存法**：4 KB 内嵌 / 超过只存引用两档（见 §5）；引用的解析放主进程 `register.js` 的
   `resolveOrbitSpec`，渲染端不搬星历正文过 IPC。
5. **「刷新星历」**只对 `omm` 显示（按 NORAD 回池重取）；`ephem` 没有「刷新」，只有重新导入。
6. **来源标签三档**：定轨 / 星历 / 星历文件，词在 `sunParams.SAT_SOURCE_LABEL`。
