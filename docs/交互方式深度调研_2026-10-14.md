## 0 结论

**单点机制已经比较丰富。** 例如：
- 链路表有 Excel 手感（键入即编辑、填充柄、冻结列、与 Excel 互贴）；
- 标题栏有命令搜索，能定位到参数行；
- 建链可以全程用键盘（Enter / Esc / Backspace，检索框上下选、进出卫星集）；
- 链路预算配置会自动保存，并保留 30 档历史版本；
- 有聚焦、跟随，以及模型工作台的拖放装配。

**短板不在功能缺失，而在缺少几块公共底座，导致各模块各写一套、彼此不一致。** 归纳成四条主线：

1. **安全网缺失。** 主窗口没有场景级撤销；删除操作的保护有五种不同口径；文件删除直接 `unlink`，不进回收站；多处失败只写 `console.warn`。这几处最可能真丢数据。
2. **地图工具态没有统一状态机。** 共有 10 种绘制、放置、拖拽态，各自清场，互斥有漏洞；只有建链一种响应 Esc、Enter、Backspace。两种态同时开着时，用户加的点会悄悄写到错误的对象上。
3. **独立窗口群还不是「一个工程」。**
   - 没有场景（工程）文件；
   - 计算窗算出的时刻和对象回不到主窗；
   - 菜单「退出」实际只关主窗：计算窗开着时程序不退出，主窗也找不回来。
4. **结果和输入快照脱节。** 过境 Excel、SSA 报告、波束合成都会出现「当前输入的标签贴在旧结果上」，交付物会张冠李戴。

## 2 重大问题与提升点

每条按「现状 → 影响 → 成熟做法 → 修法」写。工作量：S 不超过半天，M 约 1–3 天，L 超过 3 天。

### A 安全网：删除、撤销、失败

**A1【P0】天线树的 ×：不确认，直接删盘上 GRD。**（I1 同族，范围更大）
- **现状**：
  - 卫星行 × 的调用链：`removeSat`（CM:8503）→ `grd.removeSatellite`（useGrdCoverage.js:920）→ `coverageGrd.remove` → electron/services/coverage.js `remove()` 里的 `fs.unlinkSync`。整颗星的全部导入 GRD 被一次删掉。
  - 天线行 ×（CM:13290）和对星覆盖面板（SatCovPanel.vue:204）直接调用 `removeAntenna`。
  - 同样的删除在文件管理里会先 `ask()` 确认（FileManager.vue:319-320）。
- **影响**：× 紧挨着 ✎ 和 ＋。误点一次，天线设置和 GRD 副本全没了；链路预算里引用它的卫星条目变成「未导入」，频率计划成了孤儿。
- **修法**：
  - 调用处加确认，复用星座栏的两步确认。提示里写出运行时数据：「被 n 个链路预算卫星条目、m 份频率计划引用」。
  - 文件删除改用 `shell.trashItem`，或移进 `userData/trash/grd`，7 天后清理。

**A2【P1】主窗口没有场景级撤销；侧栏 × 一点即删；图上拖拽的改动也不进撤销栈。**
- **现状**：
  - 删 Polygon（`removePoly` CM:7652）、删链路或节点、删点 / 站 / 航迹、删波束组都是一点即删。
  - `bsRemoveGroup` 删组时会连同该组的撤销栈一起删掉（useBeamSynth.js:541 `_stacks.delete`），注释说明不弹确认是因为「confirm 会抢焦点」。
  - 图上拖动都不压撤销栈：`onMarkerDragged`、Polygon 顶点 / 整体拖动、`grd.beamDrag`、`bs.dragBeam`。其中 `beamDrag` 会把原来的指向模式改成 azel 再改成 geo，改了就回不去。
  - `useMarkerTable` 的快照撤销栈现在只能从表格浮窗里触发。
- **成熟做法**：Figma、VS Code 用全局撤销栈；Gmail、Drive 是「已删除 · 撤销」回执条；QGIS 有编辑缓冲；Blender 拖动中按 Esc 还原。
- **修法（M）**：
  - 新建 `stores/sceneUndo.js`，记录「标签 + 域快照 + 还原函数」，上限 50 步，只存内存。场景状态都在 localStorage 的几个键里（`globe3d/markers`、`globe3d/polygons`、`globe3d/beamSynth`、`constellation3d/*`、`globe3d/settings.grd`），其他窗口通过 storage 事件读这些键，所以还原后会自然同步。
  - App.vue 的 `onKey` 接 Ctrl+Z / Ctrl+Y，生效条件：焦点不在可编辑元素上、事件没被 `defaultPrevented`、没有遮罩。
  - 删除后状态栏停留约 8 秒「已删除 Polygon「X」 · 撤销」。这一行只陈述状态并给一个操作链接，符合 CLAUDE.md。
  - 拖动开始时先压栈；拖动中按 Esc 还原到起点。

**A3【P1】链路表（StationGrid）单格键入不进撤销栈。**
- **现状**：
  - `pushUndo` 只在批量操作里调用。`endEdit`（SG:868）和下拉提交都不压栈。所以键入一格后按 Ctrl+Z，会连同上一次批量操作一起回滚；如果之前没有批量操作，就什么也撤不了。
  - `onKey`（SG:1142）的 `if (!props.stations.length) return` 写在快捷键分支前面，「清空」之后 Ctrl+Z 和 Ctrl+V 都被吞掉。
- **对照**：同仓的 `useGridSelect`（ExcelGrid 用）是先 `pushUndo` 再 `onEdit`；Excel 也是每次提交单元格算一步。
- **修法（S）**：`startEdit` / `beginCapEdit` 时记下快照，`endEdit` 时值有变化就压栈；空表守卫移到 Z/Y/V 分支之后。linkbudget 和 ngso 两份副本一起改。

**A4【P1】频率计划：删除不确认、不能撤销、没有版本，600 ms 后落盘。**
- **现状**：
  - 频率分配表里按 Delete 或 Backspace 就执行 `removeIds`（FpAlloc.vue:177/330），而同一窗口删转发器是要确认的（FreqPlanApp.vue:1028）。
  - 删 LO 或波束会级联清空所有转发器对它的引用（`removeLo` / `removeBeam`）。
  - 拖拽改载波也不能撤销。
- **修法（M）**：照 `useMarkerTable` 的快照栈给计划加 Ctrl+Z / Y（`carriers` 每次都是整份换新，适合做快照）；计划接入 `useConfigVersions`，获得历史版本。

**A5【P1】失败静默：数据或交付物悄悄缺失。**
- **现状**：
  - **GRD 持久化失败**：`importGrd`（useGrdCoverage.js:1753）、`importSynthGrd`（:1808）、解析天线（:1863）都只 `console.warn('…仅本会话内有效')`，重启后天线就没了。
  - **启动重载失败**（:1019）：天线照样列在树上，勾选后不出图，也没有任何标记。
  - **交付物缺内容却报成功**：
    - `collectGxt`（CM:7285）里 `catch → console.warn('GRD 导出等值线失败')`，GXT/KML 中 GRD 那一部分被丢掉，而主窗导出本身不给任何回执；
    - `harvestFigures` 的 `catch → out[i] = []`，报告缺图但没有告警；
    - `generateAll` 中单组失败只写 `console.error`。
  - **主窗场景写盘**：`saveSettings`（CM:11634）和 `persistMarkers`（CM:11071）都是 `catch { /* ignore */ }`，localStorage 配额满了也是静默的。
  - **带上下文开窗**：六个计算窗的 `onToolContext` 都是 `.catch(() => {})`，从地图「导入链路预算」失败时没有任何反馈。
- **成熟做法**：VS Code 把错误送进通知中心并常驻；STK 有 Message Viewer。
- **修法（M）**：
  - 新建 `shared/reportError(where, e)`：写 `logMsg(…, 'error')`（全仓目前还没有用到 `'error'` 级），同时在当前窗口给出可见提示。
  - 部分成功统一报成「n 成功 / m 失败：原因」。
  - 写盘失败的提示可以先单独做（S）。

**A6【P1】没有全局异常和崩溃兜底。**
- **现状**：
  - src 里没有 `app.config.errorHandler`，也没有 `unhandledrejection` 处理；electron 侧没有 `render-process-gone` / `unresponsive` 处理。
  - 很多 `await api.*` 没有 try，例如 `useConfigTree` 的新建、改名、删除、移动。
  - 历史上出过的 GRD 白屏，现在仍会停在白屏，没有任何提示。
- **修法（S–M）**：每个窗口入口挂全局 handler，接到 `reportError`；主进程监听 `render-process-gone`，弹出「窗口已崩溃」并提供「重新载入 / 关闭」两个选项。

**A7【P2】同名星历导入会静默整组替换。** `customSats.js` 按 `g.name` 替换整组（ephem 类型还会调用 `ephemStore.remove`）。干净文件导入不弹对话框，结果只在收起的日志里留一句「替换 1」。
- **修法（S）**：改为另建新组（名字加后缀）；或在导入预览里标明「将替换」。

**A8【P2】删除保护口径有五种。**
- 现有的五种：两步确认（星座栏）、模态确认（配置树、文件管理）、不确认（多数侧栏 ×）、右键立即执行（标记行的模型块和色块）、按 Delete 即删（频率计划载波）。
- **修法**：定一个统一判据 `useDestructive`：
  - 能撤销的操作：直接删，同时给撤销条；
  - 不能撤销、或有跨模块引用的操作：先确认，并给出引用数。

### B 地图工具态

**B1【P1】没有统一的工具状态机：互斥有漏洞，横幅会叠，快捷键不一。**
- **现状**：每个入口自己写清场代码，清的范围各不相同。
  - `polyStartDraw`（CM:7633）会清建链、调整位置、调整、拖动、波束放置、航迹；
  - `editTraj`（CM:11124）只调用 `endLinkDraw()`。
- **复现**：Polygon 绘制中，到标记栏点航迹「编辑」，两种态并存。`onMapRightClick`（CM:9466）先判断 `curPoly()`，本想加给航迹的点全进了 Polygon。
- **其他表现**：
  - 拖拽波束开着时右键「绘制 Polygon」：左拖改的是视轴，右键才加顶点。
  - 横幅都在同一位置（top: 64px），两种态并存时叠成一条。
  - Enter、Esc、Backspace 只有建链响应（`onLinkKey`），其余 9 种态按 Esc 都没反应，其中 5 种还没有横幅。
  - 离开视图时：建链自动完成、拖拽波束关闭，其余态都挂着不动。
  - 波束放置却跟着 `shellUi.side` 走，一收起侧栏就退出，与已定的「收起侧栏 ≠ 离开视图」口径相反。
- **成熟做法**：QGIS 同一时刻只有一个 Map Tool，数字化时 Esc 放弃、Backspace 删上一点；Figma 按 Esc 一律回到 Move 工具。
- **修法（M）**：
  - 新建 `useMapTool`：所有入口统一走 `setTool(kind, opts)`，只渲染一个横幅组件。
  - 快捷键统一：Esc 退出（没成形的直接丢弃）、Enter 完成、Backspace 撤销上一点。
  - 快捷键让位沿用 `LNK_KEY_BLOCKERS`；是否算离开视图一律按 `sideCtx()` 判断。

**B2【P1】绘制、拖波束、拖标签时不能用鼠标导航，误拖一下就落一串点。**
- **现状**：
  - 绘制态左键一按就起笔，每移动 14 px 加一个点（`POLY_DRAW_MIN2`），旋转被锁住，右键也是加点。
  - 拖波束、拖标签会吞掉所有左键；`labelDrag` 起拖没有距离阈值，会抓起全图离光标最近的标签。
  - 中键在 3D 和 2D 都没有动作。
  - 2D 双击会落下两个重复顶点，同时 `fit()` 跳回全图。
- **成熟做法**：SATSOFT 手册 §5.2（PDF p58）是左键逐点、按住拖为徒手画、右键完成；QGIS 数字化时按住中键或空格可以平移。本平台自己的「地图放置」也已经是「点击落点、拖动照常导航」。
- **修法（S–M）**：
  - 绘制态改成放置态的语义：单击加点、拖动导航；徒手画改为 Shift + 左拖。
  - 所有模态下中键都能导航。
  - 拖波束限定在视轴或 −3 dB 圈附近才起拖；拖标签加约 20 px 阈值。
  - 绘制态双击不触发回全图，相邻重复点去重。

**B3【P1】除卫星以外，地图对象都不能左键选中，也没有悬停反馈。**
- **现状**：
  - `onMapPick`（CM:9052）只处理卫星条目（`if (!en) return`），站、点、航迹、Polygon、链路单击都没反应。
  - 光标压在卫星上不变形、不出名字；14 px 的拾取半径在密集星座里基本是盲点。
  - 可复用的现成件：`entHitAt`、`linkNodeAt` 的命中顺序、`lnkAreaAt`、模型拖放用的 `setDropHighlight` 高亮环。
- **成熟做法**：Cesium Viewer 单击选中实体；SATSOFT 编辑时光标靠近边线，边线会高亮（PDF p61）；QGIS 有 Map Tips。
- **修法（M）**：
  - 单击 = 选中，加高亮环，并用 `revealSection` 定位到侧栏对应的行。
  - 悬停做 rAF 节流的命中测试，给出 pointer 光标、高亮环和名字签。名字签是运行时数据，按 CLAUDE.md 可以留。

**B4【P1】右键菜单的对象分支不全。**
- **现状**：
  - 压在卫星上：没有「聚焦 / 加入聚焦 / 移出聚焦」；「取消聚焦」清的是整个聚焦集，不是压着的这一颗。

- **修法（S–M）**：

  - 全局段按有没有数据用 `v-if` 裁掉。

**B5【P2】自动切到 2D 的编辑既不定位到对象，也不收尾。**
- **现状**：
  - 调整顶点、整体拖动、调整中心、删除波束、站点栅框选会自动切到 2D，但不把画面移到对象上。
  - 手动切回 3D 后，这些 2D 专属态不退出：3D 上还画着手柄，却拖不动。
  - GXT 卡片的「定位」（`focusCovSat`）在 2D 下无效。
- **修法（S）**：自动切 2D 的入口补一次 `flat.centerOn(对象)`；切回 3D 时退出 2D 专属态；「定位」在 2D 下改走 `centerOn`。
- **注意**：子代理还建议在 3D↔2D 切换时交接视图中心。这属于 09-15 已回退的「2D↔3D 视图接力」，**本文不列入建议**，要做须先问用户。

**B6【P2】缩放锚点和修饰键口径不一。**
- 缩放：3D 滚轮朝屏幕中心缩放，2D 和模型工作台以光标为锚。
- 修饰键：图上点星时 Ctrl 和 Shift 都是增减；SatList 里 Shift 是连选；站点栅是 Ctrl 并入、Alt 减去。

### C 窗口群与跨模块联动

**C1【P1】「退出」只关主窗，计算窗开着时程序不退出，主窗也回不来。**（含 I5）
- **现状**：
  - App.vue:215「退出」的实现是 `run: () => window.close()`，悬停提示写的是「关闭主窗口」。
  - electron/main.js:109 主窗 `closed` 时只连带关掉性能表；`window-all-closed`（:880）要等全部窗口关完才退出。
  - `second-instance`（:31）在主窗不在时只聚焦 `getAllWindows()[0]`，不重建主窗；拿到的甚至可能是导出 PDF 用的隐藏打印窗。
- **影响**：
  - 用户「退出」后只剩一堆计算窗，入口全没了；
  - 自动更新的「退出时安装」一直等着。
- **成熟做法**：STK、MATLAB 关掉主框架就是关掉整个工程。
- **修法（M）**：
  - 主窗 `close` 时先 `preventDefault`，逐个关闭带守卫的计算窗，等它们各自确认后再关主窗。
  - `second-instance` 在 `!_mainWin` 时调用 `createWindow()`。

**C2【P1】带守卫的计算窗，在渲染崩溃或监听还没挂上时关不掉。**
- **现状**：
  - main.js 中 7 处写法都是 `e.preventDefault(); send('*:closeRequested')`，没有超时兜底；只有模型工作台有 3 秒兜底（main.js:574）。
  - LB 的 `onCloseRequested` 在 `onMounted` 末尾才注册，前面的 `await loadConfigs()` 没有包 try。
- **影响**：白屏后点 X 没反应，只能去任务管理器结束进程；C1 的退出路径也会被它卡住。
- **修法（M）**：把 9 份复制的 `create*Window` 抽成工厂 `createToolWindow({ key, page, guard })`：
  - 守卫统一加 3 秒兜底；
  - `render-process-gone` 时直接放行关闭；
  - `unresponsive` 时弹原生框，让用户选「等待」或「强制关闭」；
  - 顺带统一窗口位置记忆（现在只有性能表有，main.js:636-669）。

**C3【P1】计算窗回不到主窗（串联清单 C2 仍是「部分完成」）。**
- **现状**：
  - NGSO 的典型时刻 t*、日凌逐日表、星间距离极值、C/I 最差时刻，都要手抄时刻再到主窗时间轴里键入。NGSO 代码注释（:1174）里自己写着要「把时间轴设到 t*」。
  - 现成的范式：性能表的 `perfwin:act` 已经能 `seekClock` / `focus`（perfWinHost.js:349-350）。
  - `sceneClock.js` 的 `onSceneClock` 有定义，但没有任何地方调用。
- **成熟做法**：STK 对象浏览器加动画到指定时刻；MATLAB linked plots。
- **修法（M）**：
  - 主进程加 `scene:cmd` 中继，照 `perfWinAct` 的写法，命令白名单为 `seekClock` / `focusSat` / `flyToSite`（瞬时正对，不做飞行）/ `highlightLink`。
  - 首批接入点：NGSO / 再生 / 端到端「卫星几何」里的 t*；日凌逐日表的行；链路表行右键「在主窗口定位」。

**C4【P1】频率计划改了，链路预算静默沿用旧频率。**
- **现状**：
  - SatellitePanel.vue:110/112 只在挂载时或 `fpId` 变化时调用 `getPlan`；`refreshLatest` 不会重新套用。
  - `freqPlan:save` 不广播（register.js:882）。
- **影响**：改了 LO 或转发器后，链路预算的上下行频率、极化、带宽不变，「输入已变」也不亮。
- **修法（S–M）**：
  - `freqPlan:save/remove/rename/importJson` 之后向所有窗口广播 `freqPlan:changed`。
  - `lbFreqPlanRef` 加 `resyncAll(satConfigs)`，收到广播、窗口获焦、点「刷新」时都调用一次；用户已解锁覆盖的字段不动。

**C5【P1】主窗改了天线指向，GSO 的地理场图跟着变了，表格回填却没跟。**
- **现状**：`reloadSatTree`（LB:911）只替换 `satTree` 和 `grdCfgs`；回填 watch（LB:950-955）的依赖里没有天线配置，而 `geoLink` 的依赖里有。
- **影响**：图和表用的是两个版本的方向图；之后随便改动一行，整列 G/T、EIRP 会突然被重写。
- **修法（S）**：`reloadSatTree` 末尾调用 `scheduleGrdFill()`（非 force，指纹本身已经保护手改值）。NGSO、再生式没有核实，需要同口径检查。

**C6【P2】其余联动缺口。**
- 建链导入后与图上链路断开关联，重复导入会产生重复行（串联清单 C5，未做）。
- 天线改名后，链路预算显示「未导入」（串联清单 C7，未做；`antKeyOf = folder + '|' + name`）。
- C/I 的卫星库只在开窗时读一次，开窗时库为空则「从卫星库导入」永远不出现（CiApp.vue:59/229）。
- 计算窗标题固定，不带当前配置名。
- 计算窗 `backgroundColor: '#ffffff'`，暗色主题下开窗会闪白。

**C7【结构性 · ★待拍板】主窗口没有「场景 / 工程文件」。**
- **现状**：
  - 主窗场景分散在 localStorage 的十余个键里，外加 userData 下的 GRD、星历、频率计划文件。
  - `globe3d/settings` 的 `snapshot()` 把场景数据（天线树、性能表、壳层）和显示偏好（字号、边界样式）混存在同一个键里。
  - 全仓没有「打开 / 保存 / 另存场景」的入口。
  - 链路预算的分享包会剥掉方向图。
- **影响**：
  - 不能同时保存或切换多个项目；
  - 不能把一个完整场景交给同事复核；
  - 配额满或清理 userData 后，整个场景丢失且不报错。
- **成熟做法**：
  - STK 用 .sc 场景文件，另存为 .vdf 时把外部文件一起打包；
  - SATSOFT 用 .ssp / .ssw 工程文件（手册 p8、p25、p28）；
  - QGIS 用 .qgz（zip 包，路径相对）。
- **修法方向**：
  - 第一期（M）：「文件 › 导出场景包 / 导入场景包」。zip 里放 manifest、场景 JSON、被引用的 GRD / 星历 / 频率计划、链路预算配置，依赖闭包复用 lbShare v3。
  - 第二期（L）：场景改存 userData 下的原子文件，带历史版本；标题栏显示场景名和未保存状态。
  - 需要拍板的原因：它与 08-31 回退的「配置管理与分享」相邻。那次是线上分享加设置可视化，这次是本地场景文件，方向需要用户定。

### D 结果与输入的一致性

**D1【P1】过境 Excel 用当前输入给旧结果做表头。**（两个子代理独立发现）
- **现状**：
  - 改目标或门限时，`watch([minElev, targetKind, targetId])` 只重算瞬时结果（useVisibility.js:351）；`accessResults` 不清空，也不亮「输入已变」。
  - `exportAccessExcel`（CM:781）里的目标名、`minElevDeg`、`satSet` 都读当前值。
  - 覆盖参数变化时也只是存档（:357）。
- **影响**：可能出现「站 B 的文件名里装着站 A 的过境窗口」，门限标注也与数据不符。
- **成熟做法**：STK 的对象一变，Access 结果即失效。
- **修法（S）**：
  - 抽一个 `useStaleResult({ deps, compute })`。
  - `computeAccess` 时把目标、门限、卫星集钉成快照（时窗已经这样钉了 `accessHorizonMin`），导出只读快照。
  - 输入指纹变化就亮「输入已变」，导出前补算（照 I2 的口径）。

**D2【P1】SSA 改了设置不提示，导出 Word 也不补算。**
- **现状**：`dataNewer`（SsaApp.vue:303）只比较数据时间；改范围、章节、参数只存档（:466）；`openReportDialog`（:348）直接导出旧模型，文件名却按当前范围生成（:352）。
- **修法（S）**：用 JSON(scope, groups, sections, opts, lang, tz) 做签名，签名不一致就亮「输入已变」，导出前自动执行 `generate()`。

**D3【P1】电磁波束仿真：多馈源、赋形、相控阵组生成后再改参数，没有任何过期标识。**
- **现状**：按钮恒为「生成 / 更新此组」（CM:13809）；高斯组有 150 ms 自动同步，其余三种组没有。
- **修法（S）**：所有组都记录 `_genSig`（复用 stkSig 的思路），签名不一致就亮「输入已变」。

**D4【P2】NGSO「起点 = 时间轴」档的结果不随主时间轴失效。** stale watch（ngso:646）不包含场景时刻，t0 只在计算那一刻读一次。
- **修法（S）**：在 scene 档下用 `onSceneClock` 比较，差超过 1 秒就亮「输入已变」。再生式、端到端同口径核对。

**D5【P1】多格式报告的兄弟文件、PFD 目录输出会静默覆盖。**
- **现状**：保存框只对第一种格式询问是否覆盖；随后 `stem.docx`、`stem.pdf` 直接 `writeFileSync`（register.js `report` 段）。PFD 的 `file:saveMany` 选目录后，同名文件也直接覆盖。
- **对照**：视频的 PNG 序列有 `askReplace` 确认。
- **修法（S）**：写盘前汇总已存在的文件，回到渲染端用同一款确认卡。

**D6【P1】数值输入没有校验和范围，引擎按前缀解析，静默算出错数。**
- **现状**：
  - 引擎 `pickNum` 用的是 `parseFloat`（packages/core/utils/linkCalculator.js:256）：从 Excel 贴来的「36 MHz」读成 36，「12,5」读成 12。
  - 上行频率列的单位是 GHz（params.js:68），填 14250 不报错；全仓没有频率范围检查。
  - 3GPP 物理层字段用 `Number($event.target.value)`（BasebandPanel.vue:485-535）：清空得 0，乱填得 NaN；同文件已有 `numAttr` 却没用上。
- **成熟做法**：STK 和 Excel 的数据验证都在输入时拒收，并给出范围。
- **修法（M）**：
  - 字段 schema 加 `min/max`；输入格不合法时标 `st-bad`，悬停 title 写出范围。
  - 计算前做预校验，坏行跳过，并逐行报告是哪一行、哪一列、什么值。
  - 引擎改用 `shared/num.js` 的严格解析。**改动涉及引擎数值，必须用快照哈希逐位对拍。**

**D7【P2】提交语义四套混用，「清空」有五种含义。**
- **提交语义**：
  - 对地覆盖设置区（GSS）一个分区里同时有回车提交、逐键生效、失焦提交三种；
  - 环境场「档数」（NumBox）与紧挨着的「上下限」（逐键）也不一样。
  - 添加卫星对话框（sat-dlg）改一格落一格、不能取消，只填名称就会在 0°E 建出一颗星（CM:8411）；旁边的仰角线弹窗却要点「保存」。
- **非法值处理**：NumBox 越界时静默钳制、非法输入静默回退（NumBox.vue:42-48），例如实时气象频率输 80 会直接变成 60。
- **「清空」的五种含义**：
  - NumBox：回退到原值；
  - 表格：取缺省值；
  - 3GPP 字段：变成 0；
  - 可见性门限：变成 0°；
  - 覆盖圈：变成「自动」。
- **修法（M）**：
  - 定一条规则：数值框统一用 NumBox 语义（回车或失焦提交，Esc 放弃）；滑杆、拨杆、颜色即时生效；对话框统一用「确定 / 取消」或统一用「实时 + 关闭」。
  - NumBox 拒收时闪 1.5 秒红框，复用星座生成器的 `constFieldBad` 样式。
  - 「清空 = 恢复缺省（灰字就是缺省值）」统一全平台。

**D8【P2】保存模型有三套，日凌 / SSA / 雨衰的「不保存」名不副实。**
- **现状**：
  - 这三窗的工作态每 600 ms 整份写入 `<ns>/last`。开窗时执行 `applyState(c.state); setBaseline(); applyState(st)`（SunOutageApp.vue:621-627），所以关窗时选了「不保存」，下次打开改动又回来了。
  - 这三窗删配置不确认：`useConfigTree.js` 只在开了自动保存时才确认；雨衰（:480）直接删。
  - C/I、PFD 只有一个存储槽，两份研究不能共存。
- **成熟做法**：二选一。要么学 VS Code 的 Hot Exit（不问，直接恢复），要么问了就按答案办。
- **修法（M）**：日凌、SSA、雨衰改接 `useConfigTree({ autosave: true })` 加 `useConfigVersions`；雨衰顺带换成共用实现。

**D9【P2】时刻输入有 7 套解析器、6 种时区口径，其中两处缺年份守卫。**
- **两处缺守卫**：
  - 自定义星座的场景历元：`@change` 后直接 `new Date(v)`（SatLayersPanel:314 → CM:2323）。Chromium 每改一段就触发一次 change，年份打到一半就会写进 `0202-…`。
  - ShellPerfWin:134 用 `v-model`，同样没有守卫。
- **时区口径**：仅主窗口内部就有四种——时间轴、过境、气象（写死 UTC）、场景历元（写死本机）。NGSO 系列把 UTC 标作「UTCG」。
- **修法**：
  - 两处守卫先补（S）。
  - 统一部分抽 `TimeInput.vue`（M）：接受 ISO、空格分隔写法、`+2h` / `-30min`、「游标」，以及粘贴；按时区档解释；回车或失焦提交；年份小于 1000 一律拒收；后缀加时区角标。

### E 时间轴与产出

**E1【P1】时间轴没有事件层，分析结果没法在主时间轴上定位。**

**E2【P1】静态出图不带时刻、图例和标题，也没有取景预览。**

**E3【P1】导出完成后的反馈有六种口径。**

  - `expScope` 出厂是 `'world'`（App.vue:136），所以在 3D 下点工具栏，得到的是 2D 世界平面图。
  - 「矢量 PDF」在 3D 下实际是位图。hint 已经补过，但菜单标签和工具栏提示都没改。
- **修法（S）**：工具栏 title 按当前范围动态写出实际产物；或者工具栏恒按「截图」出图。

**E5【P2】默认文件名没有规则，也没有批量导出。**
- **文件名**：「覆盖图_全球图.pdf」「当前绘制.gxt」「雨衰计算结果.xlsx」都不带对象名和时刻，连续导出会互相覆盖。视频文件名带了仿真时刻和尺寸，可以作为范例。
  - 修法（S）：加 `shared/exportName.js`，统一为「对象_产物_仿真时刻」。
- **批量导出**：多个天线的覆盖图、多份配置的报告目前都只能逐个出。
  - 修法（M–L）：报告对话框加「当前配置 / 勾选多份」两档；覆盖图按 `grd.selected` 循环导出到一个目录。

**E6【P2】长任务没有统一通道。**
- **现状**：
  - 赋形 / 相控阵合成在主线程同步执行（synth.js:1132 `buildShapedGrd`），会卡住界面。
  - 报告生成、GSO / NGSO 批量计算都不能取消。
  - 窗口在后台时任务完成没有任何通知：全仓没有 `setProgressBar`、`flashFrame`、`Notification`。
  - 主窗 PNG/PDF 导出期间没有忙碌态，重复点击被静默吞掉。
  - 过境进度 i/n 已经算出来了，却被固定文案「扫描过境窗口…」遮住（CM:13954，S 级就能修）。
- **成熟做法**：VS Code 的 `withProgress`（状态栏 + 通知 + 取消）；Windows 任务栏进度。
- **修法（L）**：
  - 新建 `stores/tasks.js`：register / progress / cancel / done；状态栏放一个任务格。
  - 窗口失焦时用 `win.setProgressBar` 显示进度，完成后 `flashFrame`。
  - 赋形合成移进 Worker。

### F 键盘、对话框与可发现性

**F1【P1】12 扇窗仍挂着 Electron 缺省菜单。**（I6，现状未变）
- **现状**：
  - 只有模型窗调用了 `removeMenu()`（main.js:556）；全仓没有 `setApplicationMenu`。
  - 缺省菜单带来的误触键：Ctrl+R 重载，会绕过关窗守卫、丢掉撤销栈；Ctrl+W 关窗；Ctrl+0、Ctrl+=、Ctrl+- 整页缩放；Ctrl+M 最小化。
  - StationGrid 对 Ctrl+- 没有 `preventDefault`，按键落到缺省菜单，变成整页缩小；而在 ExcelGrid 里 Ctrl+- 是删行。
- **修法（S）**：`Menu.setApplicationMenu(null)`，再照模型窗的做法，在 `before-input-event` 里吞掉 Ctrl+R 和缩放键。

**F2【P2】对话框的键盘约定不统一，对话框开着时背后的快捷键照样触发。**
- **现状**：
  - 主窗的内联对话框都没有 Esc、Enter，也不设初始焦点，按钮是 `<span class="save">`，Tab 走不到。涉及 appAlert（全局提示都走它）、添加卫星、仰角线、站属性、卫星组管理。
  - 关闭对话框后，焦点不还给打开它的元素。
  - 对话框开着时：Ctrl+Enter 会在后台触发计算（LB:689）；主窗的 Esc 会退出背后的跟随。
  - 做全了的范例：文件管理的 `ask()`（FileManager:56/1043）。
- **修法（M）**：新建 `shared/useModal.js`：
  - 打开时记住原焦点，并聚焦主按钮；
  - 在捕获阶段处理 Esc（检查 `isComposing`），Enter 确认，Tab 圈在框内；
  - 关闭时还原焦点；
  - 对外提供 `isModalOpen()`，所有全局快捷键先判断它。

**F3【P2】快捷键几乎发现不了。**
- **现状**：
  - 菜单栏的 `.mtitle` 是 span，没有 Alt 助记符、F10、方向键导航。
  - 菜单项和命令搜索结果都没有键位列。
  - 计算窗没有命令搜索。
- **成熟做法**：VS Code 命令面板每行都带键位；Office 按 Alt 会显示键提示。
- **修法（M）**：新建 `shared/shortcuts.js` 注册表 `{ id, keys, win }`，作为唯一来源，驱动菜单右列、搜索行尾和按钮 title；菜单栏补上 `role=menubar` 和键盘导航。
- ★ 是否加「帮助 › 键盘快捷方式」参考面板，见 §4-3。

**F4【P2】同一动作在不同窗口键位不一。**
- **现状**：
  - Ctrl+Enter 只有 4 扇链路预算窗有；日凌、雨衰、C/I、PFD、SSA 都没有。
  - 全仓没有 Ctrl+S，虽然日凌、SSA、雨衰都有「保存」按钮。
  - 同键多义：Ctrl+D（表格里是向下填充，模型窗里是复制件）；Backspace（清空 / 清格进编辑 / 撤销节点 / 删除，四种）；Ctrl+W（模型窗关签，别处关整扇窗）；Q（空闲时切坐标系，放置中是滚转）。
- **修法（S–M）**：新建 `shared/useWindowHotkeys.js`，各窗口统一挂 Ctrl+Enter 和 Ctrl+S，并带上对话框守卫和 `isComposing` 检查。

**F5【P2】鼠标点过的按钮会保留焦点，空格就变成「再按一次」。**（未实测）
- **现状**：`spaceIsPlayKey`（CM:6377）排除了 BUTTON。工具栏 `.tbtn`、活动栏 `.actbtn` 被点过后保留焦点，这时按空格会重复「导出 PNG」或收起侧栏，而不是播放。
- **修法（S）**：这些按钮加 `@mousedown.prevent`，键盘 Tab 照常能聚焦。

**F6【P2】剪贴板有四套语义，不能跨窗口传递对象。**
- **现状**：
  - 星座栏「复制卫星」存在内存变量 `satClip` 里，只能从菜单触发，不支持 Ctrl+C；
  - 配置树和频率计划的剪贴板只在本窗口有效；
  - 资源库复制的是条目名文本，粘贴时按名字反查。
- **成熟做法**：Google Earth 把地标作为 KML 放进剪贴板；QGIS 复制要素为 WKT / GeoJSON。
- **修法（M）**：新建 `shared/clip.js`，用 `ClipboardItem` 同时写入 `text/plain`（TSV，供 Excel）和自定义格式 `web application/x-satsim+json`（卫星、站、点）。消费方：StationGrid 的站址列、日凌站表、SSA 卫星组、NGSO 选星。

### G 集合、拖放与文件

**G1【P1】拖入的文件一律当星历处理，别处一律不收。**
- **现状**：
  - 全平台只有三处收文件，都走 `onImpDrop`（CM:12044）。
  - `.grd`、`.kml`、`.xlsx` 拖到地图上，会弹出星历解析失败；拖动途中，`impDragOverH` 对任何文件都点亮描边。
  - 配置树的 `onDragOver` 在 `dragId == null` 时直接 return，所以 `.lbcfg` 拖进来没有反应。
  - 文件管理和各计算窗都没有 `@drop`。
- **用户的高频预期**：
  - GRD 拖到天线树卫星行；
  - `.lbcfg` 拖进链路预算窗；
  - xlsx 拖到链路表或标记表；
  - KML 拖到 Polygon；
  - JSON 拖进频率计划。
- **修法（M）**：
  - 新建 `shared/dropRouter.js`，drop 时按扩展名分流（dragover 阶段拿不到文件名），不认识的类型在状态栏留一句。
  - GRD 走文件路径（`webUtils.getPathForFile`，preload 的 `models.droppedPaths` 已有先例），不读字节，因为 GRD 可能超过 64 MB。

**G2【P1】链路表、站表、算例表不能导入导出 Excel 文件。**
- **现状**：
  - 通用的 `grid:importXlsx` / `grid:exportXlsx`（register.js:1093-1126）和 `shared/gridXlsx.js` 早就有了，但 StationGrid 没有接，只能复制粘贴。
  - 两份 StationGrid 副本的键位与 ExcelGrid 不一致：StationGrid 缺 Ctrl+D、Ctrl+Shift++、Ctrl+- 和带表头复制，Backspace 的语义也不同。
- **修法（M）**：
  - `.sg-bar` 加「导入 Excel / 导出 Excel」，把 `pasteRange` 抽出一个 `pasteText(text, atRow)` 来复用。
  - 键位对齐 Excel。
  - 两份副本实际只差一个 frozen 前缀，合并成一份。

**G3【P1】双击和改名的手势分裂。**
- **现状**：
  - 星座栏：工作树刚改成「双击 = 聚焦、F2 = 改名」。
  - 相邻的天线树：星名双击 = 聚焦，天线名双击 = 改名，没有 F2，改名框按 Esc 也不取消。
  - 航迹表：双击 = 改名。
  - 文件管理：单击名字就进入改名（FileManager.vue:1097/1116/1192/1233）。
- **成熟做法**：Windows 资源管理器、VS Code 都是双击 = 打开或激活、F2 = 改名。
- **修法（S–M）**：
  - 地图对象类列表统一为「双击 = 定位 / 聚焦，F2 或 ✎ = 改名」。
  - 文件管理改用 ✎ 进入改名。
  - 配置树、装配结构树这类纯文档树，保留 Figma 式的双击改名。

**G4【P1】同一资源多处管理，还会留下看不见的孤儿。**
- **现状**：
  - GRD 有两个库：天线树一个，链路预算另存一个 `lb/grdSats`（lbGrdImport.js）。后者在文件管理里看不到，也画不了覆盖。
  - `removeLibEntry`（LB:245）删卫星条目时不清理 `lb:<id>` 下的方向图，盘上的 GRD 成了孤儿。
  - 资源库按 GEO / NGSO / 再生 / 端到端分成四套，互不相通，同一个地球站要建四遍；而 C/I 却能跨三套库读取。
- **修法（M）**：
  - 文件管理「天线方向图」页列出 `lb:` 节点，标明来源，并允许删除。
  - 删除卫星条目时，询问是否连同方向图一起删。
  - 资源库行菜单加「复制到 NGSO / 再生 / 端到端库」。

**G5【P2】显隐控件有三套，复选框还有两种含义。**
- **现状**：
  - 天线行的复选框是「显示」，违反「图层开关一律用 .layersw，复选框只用于参数」的基线；
  - 链路行和 SatList 的复选框却是「选择」。
- **修法（S）**：天线显隐改用拨杆或眼睛，复选框只保留「选择」这一种含义。

**G6【P2】没有文件关联。** `.lbcfg`、`.grd` 在资源管理器里双击打不开；`second-instance` 不处理 argv。
- **修法（S–M）**：在 electron-builder 里登记 `fileAssociations`，并在 `second-instance` 中按 argv 路由到对应窗口。

## 6 次要细节（一行一条）

**画布**
- 3D 没有键盘缩放（+/−），也没有复位视图的键或按钮。
- 航迹横幅只有「撤销上点 / 结束」，没有「取消」；Polygon 横幅是「完成 / 取消」。
- 调整顶点时不能在图上增删顶点（SATSOFT §5.6 支持 Delete 删点、拖边线出新点），也没有吸附和拖动中的数值显示。
- 「拖动调整」投影中心在离开「地图综合设置」后不退出，2D 左拖从平移悄悄变成改投影中心。
- 跟随中右键不拾取星和站，菜单只剩通用项。
- 建链态悬停站或星时，图上没有预览；站压着 GEO 星下点时点不到星，没有消歧。
- 光标处没有 GRD 增益或 GXT 值读数（`sampleBeamAtParam` 可以复用）。
- 拖顶点、拖波束中心时，起手会跳到光标位置，没有保留抓取偏移。

**键盘**
- SatList 的 Esc 没有 `preventDefault`，同一下 Esc 会被 `onNavKeyDown` 再退一层。
- 命令搜索按 Esc 后，焦点落到 body。
- 星座栏的 F2 改的是指针下的那一行，纯键盘用不了。
- 地图右键菜单不支持 ↑↓ 和 Enter。
- 雨衰的配置树没有任何键盘操作。
- 端到端的 Ctrl+Enter、LbSlaDialog 的 Esc 都不检查 `isComposing`。
- 模型窗的菜单开着时，W、E、Delete 仍然生效。

**输入与保存**
- 可见性的图标大小框每敲一键就钳制；门限框清空时按 0° 算。

- 主窗口关闭时如果正在播放，时钟镜像停在 play 状态，各计算窗会一直外推时刻。

- MODCOD 表改了门限后，已有载波沿用旧值，下拉回显变成「请选择」。
- 同类计算窗不能多开来对比两份配置。

**集合**
- 标记行的模型块、色块右键是立即卸下或清除，而平台别处右键都是弹菜单。
- 左栏切换后，Ctrl+C 的含义不同：配置列表里复制的是对象，资源库里复制的是名称文本。
- 信息栏接收拖放，但点亮描边的是地图和星座栏。
- 星座栏用把手拖动排序时，按 Esc 不能取消。
- 配置树、资源库、天线树、Polygon、标记、链路这几个列表都没有筛选框；配置树只能单选。
- 频率计划没有 Excel 导入，转发器表不收粘贴。

**时间与产出**
- 视频的起止框没有「取游标」按钮。
- 过境的起点只能取游标，时窗上限 168 h。
- 星历导出对话框不记住格式、坐标系、步长。

- 日凌 Word 没有封面、字体、LOGO 设置，与链路预算和 SSA 的报告不一致。

**反馈**
- 「天线设置」整节由 `v-if="grd.antMeta()"` 控制，没有聚焦天线时，连一句空态都没有。
- 主窗绑定小程序成功的消息只写进收起的日志。
- 链路预算的 `refreshLatest` 吞掉部分失败，仍提示「已刷新最新设置」。
- 日凌的 F10.7 刷新失败是静默的。
